## 使用约定

- 当前主线：阶段 0 → 阶段 1 的统一入口 / 首批运行时 / 原生子代理展示 → 阶段 2 手动交接；完成 P2.4 即完成当前主线。
- 阶段 3、4、5 均为后置可选，不能因主线完成自动开始；保留旧任务 ID 供追踪。其他运行时与 Paperclip 可以独立选择，不要求先自建自动团队。
- 按依赖顺序推进，每项交付后记录实际改动、证据和剩余边界；未执行的验证不能勾为通过。
- 运行时接入顺序为 Codex → Kimi → Claude；某运行时缺少安装 / 授权时记录延期，可在通用工作台可用后推进其他已具备条件的适配器。P1E 可先基于 OpenCode 开始。
- 文件范围是候选清单，新增目录和接口在相应规格冻结后确定；优先每次改 2–5 个文件。跨 shared / preload / IPC 的完整契约允许更多文件，但不能留下半套可调用接口。
- 本次任务开始时记录的既有未提交修改不属于本计划增量。不得为便于提交而修改、暂存或回退它们。
- 每个实施增量先判断仓库验证门槛：本次任务有效代码 >500 行且文件 >10 个才允许编译测试；否则只做静态审查，交用户手动验证。不能用历史工作凑数。
- “新增用例”与“执行用例”分开记录；合成服务用例、UI 脚本和运行时 smoke 都不能绕过门槛。手机验证暂停，桌面改动不触发手机同步或验证。
- 根 lint / test 配置仍含手机目录；门槛允许验证时，桌面任务采用 `npm run lint -- --ignore-pattern "mobile/**"`、`npm run test -- --exclude "mobile/**"`，不为冻结手机用例阻塞 PC，也不删除测试或伪造结果。
- 依赖、schema、IPC、worktree、真实调用按执行计划中的前提处理；已有明确授权直接沿用。用户已授权连续实施时，在授权范围内推进，不逐项重复申请。
- 本清单不授权安装、调用付费模型、提交、推送、删除或修改业务代码；后续实施以用户明确的实施范围为准。
- 会话约束贯穿每项：一次发送绑定所选运行时和原生会话；连接 / 切换不新建或恢复，不广播；历史失败不补建，创建结果未知不自动重试。Desktop 可见性与实时同步分别验证，不一概承诺。
