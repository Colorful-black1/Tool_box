## 1. 目标与默认决策

在 Tool_box 内选择不同编程 Agent，沿用现有对话、Prompt 模板、工具结果交接和三套主题。复杂任务优先交给所选 Agent 及其原生子代理完成；Tool_box 首先提供统一入口、原生执行状态展示和用户控制的跨 Agent 交接。

当前执行主线收缩为“统一入口 → 原生子代理展示 → 手动跨 Agent 交接”。自动团队调度、团队任务数据库、并行 worktree 和 Paperclip 仅保留为后续选项，不随主线自动实施。原阶段和任务 ID 保留，后置条目明确标为可选，避免改变已有引用。

本计划中的后续类型、路径、通道和表名均是设计候选；在对应阶段冻结规格后才实施。计划评审不等于授权安装依赖、调用付费模型、修改 schema、创建 Git 分支或提交代码。已有明确授权可直接沿用，无需重复申请。

### 默认方案

1. 首先支持 Windows 原生运行时和本机项目目录；其他系统、WSL 和远程执行另列适配范围。
2. 保留当前 OpenCode 体验。单 Agent 扩展顺序：Codex → Kimi Code → Claude。
3. 默认只允许全局一个由 Tool_box 发起的顶层运行；可以浏览其他会话。该运行内部的子代理由原生 Agent 调度，不因统一入口而额外创建一队 Tool_box 成员。
4. 第一阶段补充原生子代理的可观测性，第二阶段提供手动交接和可选角色预设。完成第二阶段即完成当前主线。
5. 第三阶段自动串行团队、第四阶段并行工作区、第五阶段其他运行时及 Paperclip 均为后置选项；有明确需求并选定范围后再启动。并行依赖自动串行稳定，其他适配器和 Paperclip 可独立选择。
6. 所有 AI 回复保留真实增量输出要求；没有原生增量的接口不能通过前端逐字动画伪装为流式。
7. 一次对话绑定一个运行时及其原生会话。连接、切换和草稿填入均不新建、不恢复、不发送；用户手动新建或选择历史，不向其他 Agent 广播消息。
8. 手动交接只准备所选目标会话的草稿；新建目标会话和发送各自显式操作。当前主线没有“启动团队任务”或自动推进下一角色的行为。
9. 可选角色预设记录职责、模型与 Prompt，品牌与职责分开；预设不自动创建 Tool_box 成员运行、原生子代理或会话。原生子代理是否启用由运行时及项目权限决定。
10. 当前主线不引入独立后端、不改 SQLite 表结构、不改变 AI 助手的内部工具权限。手机端已暂停维护，既不扩展界面，也不承担共享逻辑 / schema / 主题的同步与验收任务。

### 备选方案

| 方案 | 优点 | 代价与采用条件 |
| --- | --- | --- |
| 统一入口 + 原生子代理 + 手动交接，当前主线 | 延续现有桌面交互，复用运行时的任务分解和执行能力 | 维护适配、消息路由和交接；原生可观测性按接口降级 |
| Tool_box 自动团队，后置可选 | 固定跨运行时步骤、审批和恢复 | 自行维护任务持久化、调度、用量与工作区；需独立需求和验收 |
| 独立 Paperclip 后端，后置可选 | 复用其任务、成员、预算与长期调度 | 部署并维护本机或自有服务器实例，再调用该实例的官方 API；由 Paperclip 唯一调度同一任务 |

### 原生子代理与跨工具协作的边界

原生主 Agent 负责一次复杂任务的分解、子代理委派与结果汇总。OpenCode 内的子代理可配置不同模型、提示词和权限；不同模型仍使用 OpenCode 的运行机制。是否实际调用子代理取决于模型、运行时能力和项目规则，不能承诺复杂任务一定自动并行。

Tool_box 的手动交接用于“OpenCode 完成实现后，用户选择另一运行时审查同一 diff”等场景。交接包含必要上下文和明确来源，不复制所有聊天，也不因为有多个 Agent 就增加调用。

原生委派层和 Tool_box 自动团队层同时启用会增加上下文、取消、用量统计和并发写入的复杂度。因此当前主线只观察原生执行，并由用户控制跨工具交接；未来选用自动团队时再定义两层调度的边界。

## 5. 统一契约的设计边界

### 5.1 身份与对象

拟定义以下概念，名称在阶段 1 的契约评审时冻结：

| 对象 | 主要内容 |
| --- | --- |
| `CodingAgentRuntimeView` | runtimeId、类型、程序路径、版本、连接 / 授权状态、执行位置、能力 |
| `CodingAgentCapabilities` | 真实文本增量、历史列表 / 读取 / 恢复、模型 / 模式、审批、取消、可验证只读、原生子代理观测、Desktop 可见性、用量等独立能力 |
| `CodingAgentSessionView` | Tool_box 会话引用、原生 sessionId、runtimeId、项目目录、原生标题、状态和有界消息 |
| `CodingAgentRunView` | runId、会话引用、连接代次、开始 / 结束、结果状态、所选配置快照、用量 |
| `CodingAgentEvent` | 运行身份、单调序号及文本 / 工具 / 审批 / 配置 / 用量 / 终态事件 |
| 原生子代理视图（名称待冻结） | 父会话 / 父运行、原生子会话引用、已提供的名称 / 状态 / 产物；缺失项标为未知 |
| `AgentMemberProfile`（角色预设候选名） | 预设引用、名称、职责、runtimeId、模型、模板版本、权限要求；主线不据此自动创建成员会话 |
| `TeamTask` / `TeamStep`（后置） | 选用自动团队后才定义需求、验收标准、成员、依赖、步骤状态及产物引用 |

编程 Agent 使用 `CodingAgent*` 前缀，与本项目 AI 助手现有的 `AgentPermission` / 工具审批类型分开。角色、连接、原生会话、任务和运行均有独立 ID，不能互相替代。

### 5.2 能力、权限与模型

- 能力至少区分：未核实、支持、不支持；控制按钮只按本次连接已核实能力启用。
- 只读模式需要运行时权限或实际沙箱保证；角色文字、“规划”标签和单纯 cwd 都不构成隔离。
- 没有可验证只读 / 审批路径的运行时，不进入自动规划 / 审查角色；允许的手动使用范围需明确显示。
- 会话列表、历史读取、原生恢复分别建能力，不能仅靠一个 `canLoadSession` 推断全部支持。
- 模型列表优先来自运行时官方接口；原生收藏不可用时仅提供 Tool_box 自己的常用模型设置，不宣称与 Desktop 同步。
- OpenCode 现有模型过滤保留在其适配器内；不为其他 Agent 复制读取私有数据库或凭据的做法。
- 运行时自行管理其原生登录；Tool_box 不复制其登录文件，不把工具箱 AI 配置的密钥隐式注入其他运行时。
- 子进程环境按运行时需要和已授权配置筛选，兼顾 PATH / 系统必需项与现有原生认证；不把其他成员的服务凭据全量继承。
- 原生子代理的创建、模型、工具权限和内部并发由原生运行时负责；Tool_box 不复制调度器，不用角色预设绕过权限，也不静默修改原生 Agent 配置。

### 5.3 事件、取消与审批

- 事件至少关联 runtimeId、connectionId / generation、sessionRef、runId 和序号；不依赖原生 sessionId 全局唯一。
- 用户改选成员 / 会话只改变视图；迟到分片不能写入当前草稿、其他会话或后续运行。
- 同一运行只结算一次；完成、主动停止、失败、断连结果未知分开处理。失败不能伪装完成，结果未知不得自动重发。
- 原生没有可重放游标时，不假设能够断点续流。断连后展示最后确认状态，先核实运行是否仍存在。
- “停止”先请求运行时取消，等待有界确认；强制退出只针对 Tool_box 自有子进程树，不结束用户独立打开的 Desktop。
- “取消运行”“断开连接”“关闭会话”分别定义；不能为断开一个成员误停其他成员。
- 停止顶层运行后核对原生子任务的停止状态；协议只确认父运行时，子任务显示未知 / 待核对，不能推断全部停止。内部子代理用量也不能遗漏或被父子汇总重复计数。
- 审批绑定原运行、原连接和原生请求 ID，默认仅提供已支持的单次允许 / 拒绝；未知选项、超时或关闭按保守方式收敛。
- 不用旧、新两套 IPC 事件同时更新同一份 OpenCode 消息；最终原生消息用于结算 / 校验，不能与已显示增量重复追加。
- stdout / stderr 均按不可信外部数据处理：严格校验、限长、脱敏；不向界面输出原始异常栈或原始认证响应。

### 5.4 IPC 演进草案

拟新增 `window.toolbox.codingAgents`，覆盖运行时检查 / 连接、会话列表 / 创建 / 读取 / 恢复、发送、停止、配置、审批和事件订阅。通道候选使用 `coding-agent:runtime:inspect`、`coding-agent:session:open`、`coding-agent:run:send` 等集中定义的语义名；不暴露任意 RPC 转发、命令执行、文件读写入口。

新增输入全部经 `ipc/validation.ts` 校验，保留窗口所有权与主 frame 检查，事件只送达有权使用该连接的窗口。所有跨 IPC 返回值均为可序列化普通视图对象。

旧 `window.toolbox.opencode` 在迁移期间保留并复用同一个 `OpenCodeService` 实例。新适配器先包装旧服务；待调用方全部迁移且完成回归后，再单列旧接口退场任务，不在首批删除旧实现。

### 5.5 会话归属与避免重复创建

一次顶层对话固定绑定运行时、执行位置 / 原生 profile、项目和原生 sessionId。Tool_box 的 sessionRef 只是该原生会话的引用与展示入口，不另建一份独立执行会话；不同运行时恰好返回相同 ID 时也不能合并。连接代次用于隔离迟到事件，不能在重连时据此创建新原生会话。

| 用户操作 | 原生会话与消息行为 |
| --- | --- |
| 连接或仅切换 Agent 入口 | 只改变连接 / 视图，不创建或自动恢复会话，不发送消息 |
| 手动新建 OpenCode 会话 | 仅调用 OpenCode 的新建能力；其他 Agent 不收到消息 |
| 选择 OpenCode 历史 | 恢复该原生会话；失败提示原因，不改为自动新建 |
| 在所选会话继续发送 | 路由到该会话原生 ID，不逐条新建，不向其他运行时广播 |
| 手动交给 Codex 审查 | 用户选择 Codex 的历史会话或手动新建，预览后填草稿，显式发送才执行 |
| OpenCode 内部启动子代理 | 由 OpenCode 创建和管理子会话；Tool_box 按能力展示，不在 Codex / Claude 等工具建立镜像 |

当前 OpenCode 的 `session/new`、`session/load` 和 `session/prompt` 使用原生会话 ID；用户已确认 Desktop 能看到对应会话。其他 Agent 的 CLI / SDK / Desktop 是否共用存储、账号、项目范围及 profile，要分别验证，标为“已验证可见 / 未验证 / 不支持”；不保证每个 Desktop 都显示，也不承诺两个入口实时双向同步。

同一个工作项先在 OpenCode 实现、再在 Codex 审查，会形成两段有不同职责的原生会话。主线只在内存中关联来源、目标及交接快照，不为此新增任务数据库、全量复制历史或对所有 Agent 扇出。持久化关联如有需要，另行说明存储与敏感字段影响。

会话创建请求超时或响应丢失时先核对原生结果；无法确认则提示用户，不自动重试新建。用户若同时在 Desktop 操作相同会话，需要刷新核对原生状态，不能用旧缓存覆盖外部更新或自动重发。

## 8. 阶段 2：手动跨 Agent 交接与可选角色预设

依赖：至少两个运行时通过阶段 1 的基本对话验收；原生子代理界面按能力提供。交付目标：用户能将当前结果交给另一 Agent，所有跨工具步骤由人控制。此阶段完成即交付当前主线。

1. 提供“交给其他 Agent”：显式选择目标运行时、项目和原生会话；选择历史或单独手动新建。目标未选定时只允许编辑预览，不因为交接自动创建会话。
2. 交接包包含目标、约束、验收标准、已知事实、用户选择的文件 / diff 引用、未完成项、来源运行与 base revision。上下文显式选择，超长提示删减，不复制所有成员历史。
3. 提交预览后仅填入目标草稿；已有草稿先确认替换，用户仍需点击发送。发送失败保留草稿，不自动换 Agent、补建会话、全量广播或重试可能已执行的操作。
4. 发送前核对目标目录、执行位置、权限和适用项目规则。引用文件 / diff 不等于已同步代码；目标在远端或无文件访问时提示缺口，不暗示另一 Agent 已具备相同上下文。
5. 可附规划、实现、审查等角色预设，直接复用现有 Prompt 模板；不强制先建三人团队。预设用于填充职责和配置，不自动改写运行时的原生 Agent / 子代理设置，也不凭角色文字宣称只读。
6. 预设资料仅保存有界非敏感配置，复用现有 kv 的独立版本化字段，限制数量、模板长度和总量；新增字段加入主进程校验。草稿、变量值、私有上下文和流式正文不放入偏好配置。
7. 每次交接 / 运行固定模板正文、版本及已填变量快照，先留内存；运行中改模板只影响未来操作。AI 摘要手动触发并流式展示，不静默额外调用模型。
8. 一个工作项可在内存中关联 OpenCode 实现会话与 Codex 审查会话，清楚显示来源和职责；不为这个分组新增持久化任务表。原生会话各自保留，关联不保证重启恢复；预设配置可恢复。
9. 多个预设可以使用同一运行时；是否使用独立会话由用户选择，不能仅因为切换预设自动新建。原生登录 / 全局配置可能共享，不能宣称完全隔离。

拟涉及：`agent-role-handoff` 模块的交接类型、主进程配置校验、预设 store / UI、`output-actions.tsx` 和 Prompt 交接、现有 kv 接口。类型文件按实际边界命名，当前主线不提前创建团队 service、调度状态机或 schema。

验收：OpenCode 实现 → 用户预览交接 → 选定 Codex 会话 → 填草稿 → 用户发送审查的闭环可用；只有参与的原生会话收到各自消息。草稿 / 模板 / 变量不漂移，不擅自落盘；预设可重启恢复，内存关联不冒充持久化；权限缺失和目录差异可见。

回退：关闭交接 / 预设入口，仍可直接使用多 Agent 对话；保留独立 kv 字段，不删除原模板、原生历史或用户配置。

## 9. 后置可选阶段 3：团队任务持久化与自动串行

启动条件：主线已交付，用户实际需要固定跨 Agent 流程、长期任务或恢复审计，并明确选择该选项；完成阶段 2 不自动进入本阶段。依赖：数据库 / 业务流程方案获得明确授权。交付目标：一个任务按已确认步骤推进，失败和重启后可解释、可接管。

先与复用原生子代理、手动交接及 Paperclip 方案比较收益和维护成本。若选择自建团队，每个步骤明确绑定原生会话，内部子代理仍由运行时负责；自动跨工具执行必须在用户确认的流程范围内，不能把普通直接对话变成全 Agent 广播。

### 3A. 数据设计与迁移门槛

拟在现有 `ToolboxStore` 增加以下领域记录，不新建另一个业务数据库或分散 Repository：

| 候选记录 | 目的 |
| --- | --- |
| `coding_team_tasks` | 需求、验收标准、任务状态、项目与用户确认信息 |
| `coding_team_steps` | 步骤、成员快照、依赖、前后产物、尝试次数 |
| `coding_agent_runs` | runId、原生会话引用、执行配置快照、时间、终态、用量及未知结果 |
| `coding_agent_artifacts` | 计划 / diff / 审查 / 验证证据的元信息、内容或受管引用、来源 revision |
| `coding_agent_events` | 有界的状态、审批决定与运行审计；不逐 token 无限落库 |

实施前产出具体 DDL、索引、外键、归档 / 保留策略、敏感字段清单、事务边界和旧数据兼容说明。含敏感内容的任务说明、上下文快照、摘要或产物不得直接写入明文 kv / 日志；需要持久化的敏感字段走现有 `SafeStorageSecretBox`，受管文件也不能绕过该要求。第三方登录令牌不复制进任务表。

### 3B. 状态机与调度

任务候选状态：`draft → ready → running → awaiting-review → completed`；独立表示 `paused`、`blocked`、`failed`、`cancelled`、`needs-reconciliation`。步骤和运行分别建状态，不把“工具退出”“回答结束”“验收通过”合为一个成功。

1. 任务启动前展示成员、步骤顺序、目标目录、权限、限制和验收要求；用户确认后才运行。
2. 默认流程为规划 → 实现 → 审查 → 验证 → 人工验收；可省略不需要的角色，但不能自动跳过必要的授权和验证条件。
3. 每个步骤有明确输入、输出与准入条件；前一步完成并通过交付物检查后，下一个成员才接收任务。
4. 使用任务 / 步骤版本与执行租约保证一次只分配一个有效运行。重复点击、重复事件和原生重连不能重复发送。
5. 审批等待、权限不足、缺少上下文和原生配额耗尽进入可读等待 / 阻塞状态；用户可修改方案、暂停或取消。
6. 崩溃或重启后，所有未确认终态先进入核对。查询到原生任务仍运行就重新附着；无法确认就人工处理，不能自动重发可能已经改文件的步骤。
7. 用户停止团队时，停止调度新步骤并取消所有本次任务仍活动的自有运行；区分“已请求停止”和“已确认停止”。
8. 已执行写入后不自动换 Agent 重做；改派需检查工作区实际结果，并形成新的尝试和交接记录。

### 3C. 交付、权限与用量限制

- 规划交付：范围、影响、实施步骤、验收标准、未知项；实现交付：实际 diff、文件清单和未完成项；审查交付：问题位置、触发条件、风险与建议。
- 验证记录必须包含真实命令、工作目录、对应 revision、退出码、时间和有界脱敏输出；未执行就写“未执行”，不以模型声称通过代替证据。
- `AGENTS.md` 等自然语言规则不能假设全部自动解析。执行器需要经过审核的命令白名单和项目策略；不能验证策略时等待人工处理。
- 对本仓库，只有本次任务有效代码 >500 行且修改文件 >10 个才允许运行编译测试。未达门槛进入 `waiting-manual-verification`，由用户手动验证；不能因为成员名叫“验证者”就绕过限制。
- 初始建议值：每个写工作区 1 个活动运行；最多 8 步、每步 10 分钟、整个任务 40 分钟、审查返工最多 1 轮。使用前展示并允许用户调整，超时和超轮次暂停而非无限续跑。
- 原生模型 / CLI 自有循环与子代理消耗也属于成本；没有可观测用量时标为未知，不能伪造零成本或精确美元上限。
- 用量区分原生实报与估算；金额限额仅在可靠计费口径下使用，并提示在途请求可能继续产生费用。时间 / 轮次上限始终独立存在。
- 提交、推送、合并、部署和对外发送消息分别遵守用户授权。队长或其他成员不能代替用户批准这些操作。

拟涉及：`chat-store.ts` 与桌面迁移测试、任务纯状态逻辑、主进程 team service / IPC、renderer 团队面板与审计展示、合成恢复验收。手机端 schema / fixture 不在实施范围。

验收：串行闭环完成；审批拒绝、取消、崩溃、重启、重复点击、结果未知、限额和旧数据升级均有可重复场景；验收关联实际 revision，用户仍保留最终确认。

回退：停用新任务启动，保留已有任务只读查看与核对能力。业务入口回退不等于数据库降级；数据库回滚另按已确认方案执行。

## 10. 后置可选阶段 4：并行成员与独立工作区

启动条件：用户确有跨运行时并行写入需求并选定范围。依赖：自动串行流程稳定；创建本地目录、分支与 worktree 的授权明确。本阶段不是使用原生子代理或手动交接的前提。

1. 先确认所选项目是 Git 仓库、工作区状态和基准提交；非 Git 项目继续串行，不自动初始化仓库。
2. 用户有未提交内容时，禁止自动 stash / reset。先选择“使用已提交基线”或用户认可的包含未提交内容方案；不能静默遗漏用户修改。
3. 并行可写任务默认使用独立 worktree。分支候选 `codex/team-<taskId>-<memberId>`，创建前展示路径、基线和用途。
4. 一个 worktree 同时只有一个写入租约；依赖图必须无环，后置任务只接受已确认交付版本。
5. 共享 `.git` 元数据、凭据、依赖缓存、端口和本机数据库仍可能冲突。worktree 只解决代码位置问题，不等于操作系统沙箱；并行运行本地服务还需独立端口 / 数据目录。
6. 首批只支持用户确认后将产物集成到选定目标分支。发生冲突列出文件并停止，不自动覆盖主工作区；集成操作保持可审查。
7. 审查和验证始终针对明确的 diff / revision；集成后工作区变化会使旧结果失效，需要按仓库规则重新决定验证方式。
8. 默认最多 2 个并行活动步骤，额度和预算按整队统计。某分支失败只停止依赖它的后续步骤，用户可选择取消整队。
9. 工作区完成后默认标记待归档并保留产物。物理移除必须遵守仓库授权要求，先校验绝对路径、未提交内容和唯一归属，不自动删除用户目录。

拟涉及：新 workspace service、租约 / 冲突策略、team 调度与运行记录、Git 只读诊断 / 显式操作、团队 UI、带脏工作区的合成验收。

验收：两个成员在独立目录并行完成互不相关修改；没有重复写入、错分支和错误结果复用；冲突、停止、工作区丢失和归档都可人工接管。

回退：关闭并行准入并回到串行；保留现有工作区、分支和记录，不自动清理。

## 11. 后置可选阶段 5：其他运行时与 Paperclip

以下适配器独立选取，不要求先完成自建自动团队或并行工作区。原有直接对话、原生子代理和手动交接均不依赖本阶段。

### DeepSeek Harness

固定实际版本，分别验证 ACP 的会话恢复语义、模型配置、权限和取消。原生 `resume` 不重放历史时，明确区分恢复执行和展示历史。由于当前 ACP 不转发原始 token 增量，先验证官方其他流接口；不存在满足条件的方案时保持“未达到正式接入条件”，不降级用户既定要求。

### WorkBuddy

分别设计本地助理与云端任务适配器。先完成开放平台应用和 scope 前提，确认客户端适用授权流程；按当前文档，`client_secret` 不得发布到 Electron 客户端，需要独立受信服务或官方支持的公共客户端方案。新增服务属于独立范围。

本地消息轮询不能冒充 token 流；云端 SSE 也不等于能直接操作 E 盘项目。需验证目录 / 代码交付、审批、停止、产物与恢复，并分别标记执行位置，不能将两个目标合并为一个无差别开关。

### CodeBuddy Code

作为独立 ACP 适配器复用通用契约。先使用原生 ACP 审批能力，不为省事添加跳过权限参数；SDK 若确有必要，另列依赖审批与预览版本兼容边界。

### Paperclip 可选后端

此选项是部署现成 Paperclip 服务：可在本机或自己的服务器运行，Tool_box 调用该实例的官方 API，例如本地 `http://localhost:3100/api`。当前主线无需部署它，也不预设能直接取得官方托管 API；截至本轮调研，官网云服务入口仍为候补名单。正式选用时重新确认服务可用性和授权。

单独评审服务运行方式、Windows 支持、认证、数据库维护、升级和备份；本地可使用其嵌入式 PostgreSQL，不与 Tool_box SQLite 合库。远端部署另行解决代码位置和执行节点，不能默认访问本机 E 盘项目。

Tool_box 映射成员 / 任务 / 产物，Paperclip 负责执行与调度；该路径可替代自建团队调度，不要求先实现本计划的团队数据库。两边不能争用同一原生会话或工作区。接口应经过认证、限制地址 / 来源、校验外部事件并脱敏。

沿用真实增量、取消、审批、项目边界和结果核对的验收门槛。断开后端时不默默回退本地重新执行同一任务。该选项不修改或替换 Tool_box 原有数据库和 AI 助手。

## 12. 验证策略与命令

### 仓库门槛优先

所有编译、lint、测试、打包、启动服务和验收脚本执行均先检查本次任务实际改动：有效代码 >500 行且文件 >10 个，两项必须同时满足。不能借用前一轮工具修改，不能为触发门槛合并无关工作，也不能把多次编辑同一行重复计数。

未满足：阅读、静态契约检查、diff 审查，提供人工验收步骤，并写明“本次修改影响范围有限，未执行编译验证。” 文档、注释或纯样式本身不触发命令执行。

满足且需要执行时，依次：

```sh
npm run typecheck
npm run lint -- --ignore-pattern "mobile/**"
npm run test -- --exclude "mobile/**"
```

根据实际范围再选择下列已有命令，不因“写进计划”就全部执行：

```sh
npm run build
node verify/desktop-ui/run.cjs --opencode-only --screenshots
node verify/desktop-ui/run.cjs --tools-only
node verify/opencode-smoke.cjs --connect-only
```

UI 验收需要新构建产物，旧产物只能作为历史基线，不可证明新代码通过；即使 `--connect-only` 不调用模型，现有 smoke 内部仍有编译步骤，同样受门槛限制。

根 lint / test 配置仍含手机目录，以上参数只限定桌面验证范围，本轮不修改其配置。改 `src/shared/**`、桌面数据层或主题不再触发手机 typecheck / bundle / 数据验证；旧手机用例失配不作为 PC 交付阻塞项，也不删除或伪造手机测试结果。恢复手机维护时另行确定验证，且仍受仓库门槛限制。

主线拟新增各运行时的合成 transport / service 契约测试、统一工作台消息路由、会话归属、原生子代理降级和手动交接验收。选用后置团队 / 工作区时才新增状态机、崩溃恢复和租约测试。未来脚本写完并审查后才列出最终可执行命令；当前不虚构不存在的验收脚本已可运行。

真实运行时验证使用临时合成项目和用户明确允许的调用范围。创建会话、执行命令、模型请求及可能产生费用分别记录；不以“环境探针”为名调用模型。停止、拒绝和崩溃场景不能操作真实项目验证。

每批结果写明命令、版本、通过 / 失败、警告、真实调用次数及未验证边界。自动化结果、用户手工结果和文档推断分开记录。
