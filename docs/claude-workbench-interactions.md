# Claude 工作台刷新、输入与操作模式

日期：2026-10-26。用户已确认此前历史不一致来自两个同名 `learn` 文件夹：工具箱使用代码盘目录，Desktop 使用桌面目录。本轮按用户要求改善会话更新、输入快捷键及四种模式，不改历史来源范围。

## 行为与原因

- Claude Code／Desktop 已打开的历史在刷新列表、空闲时重新点选后重新读取正文；已连接且历史列表展开时，窗口重新获得焦点也会读取。任务运行或准备期间不自动重读，不自动连接未打开的入口，不轮询。
- 原因一是 renderer 直接激活缓存，原因二是服务层把已结束会话后的全部新正文都当成迟到事件丢弃。现在只有明确的历史重读可以更新正文，原有事件流仍受终态保护。保留同一会话引用、未发送草稿、模型、思考强度与模式；失败保留旧正文，不补建、不重发。
- 编程输入框：Enter 发送，Shift+Enter 换行。中文输入法正在组词、229 确认键及长按重复事件不触发发送；空输入、运行和准备等原有按钮限制同样约束快捷键。草稿恢复不自动发送。
- Claude Code 和 Desktop 提供 Auto（`auto`）、Manual（`default`）、Accept edits（`acceptEdits`）、Plan（`plan`），默认仍为 Plan。只映射到 SDK 原生 `permissionMode`，不在工具箱伪造自动审批，不添加 Bypass 或跳过权限标志。仍需用户处理的原生请求沿用单次审批。
- 监听原生初始化／状态消息中的实际模式；例如 Auto 未生效而变为 Manual 时，同步选择器并提示。未支持的模式会中止任务，不自动扩大权限。Auto 的可用性取决于程序、供应商和模型，不能由工具箱选项保证，见 [官方权限文档](https://code.claude.com/docs/en/agent-sdk/permissions) 与 [模式说明](https://code.claude.com/docs/en/permission-modes)。

## 影响范围

沿用 renderer → 既有 preload／IPC → CodingAgentService → ClaudeAdapter → SDK 的调用链，未改 shared 契约、IPC 通道／参数、数据库、依赖、加密或外部配置。列表读取后按需调用既有 resume 读取接口；读取不是模型任务。服务层增加内部标识，区分明确重读和异步事件，不把渲染层任意数据当作历史快照。

主要文件：`opencode-sessions.tsx`、`opencode-workbench.tsx`、`coding-agent-store.ts`、`coding-agent-service.ts`、`claude-adapter.ts` 及对应回归用例、合成 UI fixture／场景。快捷键适用于全部编程 Agent；正文更新和模式扩展主要影响 Claude 两入口，其他 Agent 缓存激活行为保持原有逻辑。

## 手动步骤与边界

1. 使用更新后的运行版本，在两个应用选择完全相同的项目目录。工具箱 Claude 入口打开原生历史并查看正文。
2. 在 Desktop Code 结束一轮对话，再返回工具箱。保持历史列表展开时应更新正文；也可点击刷新，或重新点选原会话。确认无需断开重连，输入草稿和已选模型／模式仍在。
3. 任务运行期间切回工具箱，不应覆盖正在运行的正文或自动恢复另一个任务。原生历史不可读时应保留当前正文与输入。
4. 在编程输入框测试 Enter 发送、Shift+Enter 换行、中文输入法候选确认不发送。长按 Enter、任务执行中按 Enter 均不应重复提交。
5. 在 Claude 两入口的模式菜单确认四个选项。新会话首次发送后默认 Plan；需要其他模式时停止当前任务，再选择模式并显式发送。确认 Auto 不可用时界面跟随原生状态提示；不能把普通供应商 API 可用等同于 Auto 分类器可用。

只更新已结束、可读取的本机 Code 历史，已有列表／正文显示上限仍有效。两边不能同时执行同一个会话；续接原 Desktop 会话前的外部 Claude 退出检查保持不变。工具箱新建的 SDK 会话仍不会自动注册到 Desktop 列表，不承诺双向实时同步。若原生版本不返回实际模式状态，只能依其原生错误处理，不能保证从状态消息识别降级。
