# Agent 项目记忆与跨项目转用

日期：2026-10-28。用户明确要求实施，并已同意目录选择器、项目选择保存及检测结果的兼容 IPC 扩展。上轮 Token 趋势提示的 4 个未提交文件保留，本轮不纳入代码增量。

## 目标与语义

- 同项目消息转用不新增确认或提示；原有新对话草稿覆盖确认保留。
- 目标已有不同项目时，转用前确认离开原项目、发送时才替换连接、草稿保留及原生历史可重读。若目标来源项目的新对话草稿将被覆盖，合并在同一确认中说明。取消不修改目标状态。
- 确认后仅准备目标新对话草稿，不连接、断开、恢复或发送。提示显示来源 Agent / 来源项目 / 目标原项目；连接文案依据真实连接状态，不能提前声称已断开。
- 返回只恢复原项目的新对话草稿和项目选择，不恢复原生会话。原历史会话未发送草稿仍保留原目录 / 原生会话键，用户明确打开历史后恢复；转用文字不得进入原项目历史草稿。
- 返回时也保留来源项目尚未发送的转用草稿。目标运行 / 准备 / 忙碌时禁止返回或再次转用。确认期间身份、连接或草稿变化时拒绝旧确认。
- 目标尚未拥有项目时按现有首次继承处理，不制造不存在的“原项目”或额外确认。
- 目标本次启动尚未打开时，先只读检测其记忆目录，以局部快照比较及确认；取消不创建目标工作台，也不把记忆恢复写入目标选择。

## 记忆与接口

- 每个 CodingAgentId 独立保存项目，复用现有 kv 的运行时配置；使用规范配置键，Claude Desktop 同时兼容旧 `claude-desktop` 别名与现有 `claudeDesktop`，保留其他偏好字段。
- 用户确认目录选择器即由主进程 realpath、目录与可访问性检查后保存，不要求连接成功。连接成功再以原生规范目录覆盖。
- 记忆目录与当前实际连接目录分开表达。检测增加可选 `projectDirectory` / `projectError`，旧 `directory` 继续代表当前连接或原生偏好，不能把选择更新伪装成连接切换。
- `chooseDirectory(runtimeId?)`：旧无参调用继续仅选择 / 授权目录；有参时校验并保存该 Agent 的项目。
- 新增 `coding-agent:project:select`，输入 `{ runtimeId, directory }`，只保存选择并返回规范路径，用于返回原项目；不启动模型、不修改连接。
- 页面初次检测优先记忆目录，只有从未选择过才继承。草稿文档仍为 v1，只恢复草稿与最后查看入口；其单一 selection 不得覆盖已加载的各 Agent 项目记忆。恢复期间不主动读取原生历史或建会话。
- 目录无效时保留可理解的项目选择及错误提示，允许重新选择；不创建目录，不删除记忆，不崩溃。
- 配置补丁允许按字段更新运行时偏好，保留程序路径和扩展设置；不把 Desktop 两种键当成两个 Agent。

## 实施与验收

顺序：项目偏好读写 / 校验 → 兼容契约与桥接 → renderer 记忆恢复 → 跨项目确认 / 提示 / 返回 → 回归与文档。

- 相同项目、跨项目确认与取消；不提前连接；返回恢复正确目录草稿；历史草稿隔离。
- 确认期间改输入、换目录、重连、开始运行，旧确认不得覆盖新状态。
- 每个 CodingAgentId 独立记忆（包括预留 Kimi），未连接即保存，重启读取及规范目录回写；Claude Desktop 别名及其他偏好保留。
- 记忆路径缺失 / 文件替代目录 / 无访问权限时显示可读提示，选择其他项目可恢复。
- 草稿迟到恢复不覆盖项目记忆，不触发 connect / resume / create / send。
- 只统计本轮新增改动，满足 AGENTS.md 双门槛才运行 typecheck → 桌面 lint → 桌面 tests，再按范围做隔离界面验收。不调用真实模型，不自动提交。

不新增依赖、数据库表 / schema 或加密格式，不扩展手机端。
