## 改动内容与原因

用户要求先提交既有改动，再实施本机 Desktop Code 历史读取和已结束会话续接，并报告完整退出 Tool_box 时主进程弹出 `Object has been destroyed`。

此前工作按范围提交为：`05629b1`（安装包精简）、`7838cd4`（对话五项能力）、`4312e57`（Claude 两入口与供应商隔离）。以下新增改动保留在工作区，未提交、未推送。

- `coding-agents-ipc.ts` 在发送事件前检查窗口和 WebContents 存活；退出先取消 IPC 事件订阅，再释放服务。
- `coding-agent-service.ts` 在窗口销毁时先移除所有者，服务退出先移除监听，再断开适配器。修复了断开过程同步发布终态、向已经销毁的 WebContents 发送事件的顺序错误；任务停止、审批清理和 SDK 关闭仍照常执行。
- `claude-desktop-history.ts` 只读当前 `Claude-3p/claude-code-sessions` 元数据，以 `cliSessionId` 而非桌面列表 ID 关联 SDK；验证项目、结束标记、归档和等待状态。有界遍历，跳过符号链接和损坏记录，日志不包含路径或内容。
- `claude-adapter.ts` 合并本入口 SDK 来源与有效 Desktop Code 来源，Code 列表排除这些来源。只显示同时存在 SDK 记录的可续接会话，正文通过既有 SDK 接口读取；每次发送重新校验来源和外部进程，仍使用同一个 CLI ID 的 `resume`，不创建副本或自动重发。
- 工作台沿用既有历史列表与提示样式，说明仅含 Code 历史以及续接前退出外部 Claude 的要求；未新增操作表单。

## 影响范围

调用链仍为工作台 → 既有 bridge／preload → 既有 IPC 校验 → CodingAgentService → ClaudeAdapter → 只读元数据／SDK。不新增 IPC 通道或字段、数据库 schema、依赖、加密能力，不修改 Desktop／CC Switch 配置，不复制官方登录凭据，不恢复手机端维护。

退出顺序修复适用于统一编程服务中的所有运行时；新历史能力主要影响 Desktop 列表、正文与续接，以及 Code 历史的来源排除。配置读取复用同一 Desktop 数据根，路径含义调整已同步到供应商读取方。

## 操作与手动验收

1. 使用本轮构建或重新打包的版本，保持 CC Switch 网关运行。
2. 进入「编程 Agent」，选择「Claude Desktop」及原会话所在的项目目录。
3. 点击「历史会话」并点选目标，确认标题与正文。查看历史不需要退出 Desktop，不会自动发送或创建新会话。
4. 若要继续原会话，先结束原任务、处理原审批，并从托盘完整退出 Claude Desktop，同时退出其他 Claude CLI 任务。只关闭窗口可能仍驻留后台。
5. 回到工具箱检查模型和操作权限，输入消息后发送。若进程检查未通过，草稿应保留；处理提示后由用户明确重试。续接默认计划模式，采用当前 Desktop 网关。
6. 任务结束后再打开 Desktop 检查原会话是否显示新增消息；这一步尚未实机验证，不能据自动化结果认定双向同步。
7. 分别在未连接、已连接空闲、有运行任务时，从工具箱退出菜单完整退出，确认不再弹出主进程错误，重启后草稿仍可恢复。真实程序退出结果待用户反馈。

## 风险与回退

- 只支持本机、已结束且状态可确认的 Desktop Code 历史；不包含普通 Chat、Cowork、云端／SSH／WSL、归档或正在等待处理的会话。macOS／Linux 原会话续接暂未开放。
- 进程检查是发送前的快照，不能阻止之后重开外部应用；请顺序切换使用。它会保守阻挡任何以 Claude 命名的相关进程，其他 Claude CLI 仍在运行时也可能需要先退出。查询失败、超限或格式无法识别时不发送。
- Desktop 私有元数据格式变化、当前项目目录的路径别名、日志缺失或超过读取上限，可能导致历史不出现；不会因此补建会话。列表上限沿用当前项目最近 2000 项中筛选 200 条，正文仍受 200 条／200,000 字符上限约束。
- 不改写 Desktop 的列表、状态与游标；真实第三方供应商续接及返回 Desktop 后的回显仍待手动验证，不承诺实时双向同步。
- 无 schema 迁移；回退业务代码即可恢复旧入口行为，保留既有配置和加密草稿。无需删除或重置用户数据库，不应为回退清空用户记录。
