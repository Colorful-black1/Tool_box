# Claude 接入

Tool_box 把 Claude 分成两个独立入口：**Claude Code**（`claude`）和 **Claude Desktop**（`claude-desktop`）。两者共用官方 Agent SDK 执行，但供应商来源、程序／项目偏好、加密草稿和历史范围全部独立。这里只描述当前实现与仍然有效的边界；通用工作台规则见 [编程 Agent](coding-agent.md)。

## 两个入口的分工

| 项 | Claude Code | Claude Desktop |
| --- | --- | --- |
| 供应商来源 | `~/.claude/settings.json`（或绝对 `CLAUDE_CONFIG_DIR`） | CC Switch 的 `Claude-3p` 当前 profile |
| 需要 CC Switch 运行 | 通常不需要（本地代理模式需要） | 是（网关模式） |
| 历史来源 | 本机 Code 会话 | 本入口自建 SDK 会话 + 当前项目的 Desktop Code 会话 |
| Desktop 原有聊天 | — | 不导入 |

- 新增 `claude-desktop` 标识，既有 `claude` 标识与 Code 配置保持兼容；共享的四层调用（类型 → 通道 → preload → renderer）只是多了一个合法值。
- Desktop 入口复用 SDK 执行编程任务，只沿用 Desktop 的第三方网关配置，不接管 Desktop 窗口、原有聊天或官方订阅认证。不需要先打开 Desktop 窗口。
- 没有可用的第三方 profile 时明确报错，不回退到 Code 或官方供应商。
- 两入口的运行状态、程序／项目偏好、加密草稿互不影响；Desktop 入口创建的 SDK 会话只出现在该入口的历史里。

## Desktop 供应商配置契约

- 只读 `Claude-3p/configLibrary/_meta.json` 的 `appliedId`，再读该 ID 对应的 profile；不扫描、不猜测其他 profile。Windows 在 `%LOCALAPPDATA%`，macOS 在 `~/Library/Application Support`，Linux 在 `~/.config`，交付平台仍是 Windows。
- 只接受 `inferenceProvider=gateway`、受支持的认证方式、有效 HTTP(S) 地址与有界模型列表。HTTP 只允许回环地址；拒绝 URL 内嵌凭据和跳转。
- 只提取网关地址、认证与模型；不导入权限、MCP、hooks、shell、插件或任意环境变量，不关闭 TLS 校验。
- 模型优先取 profile 的 `inferenceModels`（`name`、`labelOverride`）；未提供时对同一网关的 `/v1/models` 做一次只读 GET，5 秒超时、512 KiB 上限、禁止跳转。默认取列表首个，用户显式选择优先；显式模型不再可用时停止发送并提示同步模型，不静默切换。不会自动发验证任务。
- 子进程环境先清除继承来的 Code 供应商、模型、OAuth 与云端模式变量，再应用 profile 白名单。凭据只存在于该子进程环境内，不写日志、不经 IPC、不进命令行、不落工具箱配置。
- 偏好与本入口创建的 SDK 会话 ID 索引存在既有配置 kv 的 `claudeDesktop` 项，不存正文、不存凭据，不改表也不改 schema。索引上限 10,000，达到上限或索引损坏时明确停止，不静默丢弃、不混合历史。

## Code 入口的读取边界

- 只读用户目录（默认 `~/.claude`）的 `settings.json`，文件上限 512 KiB。缺失时沿用 Claude 原生认证；读取或格式错误时明确停止，不静默换供应商。
- 只提取固定的 Anthropic 路由、API Key／Auth Token、模型环境字段与顶层 `model`。不加载项目／local 文件，不执行 `apiKeyHelper`，不导入 hooks、MCP、权限、插件、任意环境变量或关闭 TLS 校验的设置。
- 连接初始化与每次发送都重读。模型优先级：工具箱手动选择 → `ANTHROPIC_MODEL` → 用户顶层 `model` → Claude 原生默认。
- 保持 `settingSources: []`，审批与默认计划模式不变。这么做是为了不把 CC Switch 写在用户配置里的路由当作可用——见下面的排障一节。

## Desktop Code 历史与续接

**来源与身份**

- 只读当前 `Claude-3p/claude-code-sessions` 下的 Code 会话描述，取 `sessionId`、`cliSessionId`、`cwd`，以 `cliSessionId` 关联 `~/.claude/projects` 的原生日志。桌面列表 ID 不作为会话身份。
- 按当前项目（规范化后的目录）过滤。普通 Chat、Cowork、云端／SSH／WSL、归档、失效描述都不进入可续接入口。
- 只显示同时存在 SDK 记录的可续接会话；Code 入口的历史列表排除这些 Desktop 来源 ID，避免从另一入口误用供应商。
- 来源索引最多 10,000；历史从当前项目最近 2000 项原生目录中筛选最多 200 条；正文上限 200 条／200,000 字符。元数据有界读取，拒绝符号链接与路径穿越、异常 ID、非绝对项目路径；BOM、缺失文件、无权限、损坏、超限都走明确失败，不静默通过。

**读取与续接**

- 正文通过官方 SDK 的会话列举与消息读取接口取得；不补建会话，读取失败不建。
- 历史首次展开、点刷新、空闲时重新点选、列表展开期间窗口重新获得焦点都会重读；任务运行或准备期间不自动重读，也不轮询、不后台连接。
- 用户明确发送时才用同一个 `cliSessionId` 走 SDK `resume`，沿用 Desktop 网关与工具箱权限，不复制成伪新会话，不继承元数据里的任意可执行配置。
- 续接默认计划模式；失败保留草稿、不自动重发、不扩大权限。读取历史不需要退出 Desktop。

**外部进程门**

- 首期拿不到外部桌面任务的运行锁，因此续接前用固定的 Windows 系统命令（`System32\tasklist.exe`，无表头 CSV、隐藏窗口、无 shell 插值）确认没有外部 Claude 进程。用无表头 CSV 是为了绕开零匹配提示的系统语言／编码差异。
- 存在进程、命令失败或输出无法识别时一律不发送，保留草稿并说明原因；不终止外部程序、不自动重试。Tool_box 自己的初始化查询必须先结束才会进入这一步。
- 这是检查时刻的快照，**不是跨应用锁**：不能阻止用户随后重开外部程序，也只能靠顺序切换使用。它有意保守，会挡住任何以 Claude 命名的相关进程，包括用户另一个无关的 CLI 任务。
- 这个门只作用于「续接 Desktop 原会话」；工具箱自己的 SDK 新会话不受影响。

## 可见性边界

- **单向**：工具箱新建的 SDK 会话不会自动出现在 Desktop 列表。Desktop 侧没有面向第三方的列表注册接口，刷新也不会出现，不要在任何文案里声称「已同步」。
- **反向也有限**：Desktop → 工具箱只覆盖「当前项目、已结束、状态可确认」的 Code 会话，不含普通 Chat、Cowork、云端／SSH／WSL、归档或正在等待处理的会话。
- 界面上要如实说明「仅含当前项目的 Code 历史」与「续接前需退出外部 Claude」，这两条放在连接设置的折叠说明里。
- 用户明确要求的是「无感后台同步」，并已否决「点一次打开 Desktop」的方案。结论：没有同时满足「不启动／不切换 Desktop、不额外点击、Desktop 开着也能自动出现并续接同一会话」的可靠公开接口，因此**后台登记未实施且已否决**，不新增「已后台同步」状态。

### 已核查且不采用的路线

| 路线 | 判断 | 依据 |
| --- | --- | --- |
| SDK 继续写原生日志 | 不足 | 原生日志已有，但 Desktop 维护独立列表；自建会话缺列表记录，用户已实测不可见 |
| 官方 CLI `/desktop`、`--desktop --resume` | 不符合 | 会打开 Desktop，且有订阅登录与平台限制，套不到第三方网关场景 |
| `claude://resume?session=<id>` | 不符合 | 执行导入后导航 Desktop，已检查的路由里没有静默参数，不是稳定公开契约 |
| 隐藏窗口启动、导入后切回／最小化 | 不符合 | 仍启动应用、改变应用状态，无法保证不闪、不抢焦点 |
| Desktop 退出时写私有记录，下次启动读取 | 未继续验证 | 启动确实会读本机记录，但依赖未公开的存储格式；索引一致性、归属、去重都未在隔离 profile 验证，也不覆盖 Desktop 运行时 |
| Desktop 运行时从外部写记录 | 不能交付 | 会话表在进程内维护，落盘文件不等于内存登记或界面刷新；并发保存、归档、删除与租约竞态未解 |
| 调用内部 renderer IPC、注入、修改安装包 | 不做 | 绑定内部协议与版本，改变原应用信任边界，未获授权 |

### 若重启这条线的最低门槛

- 只处理工具箱来源索引里明确自有、且任务已结束的会话；不把全部 CLI 日志混进 Desktop，不自动登记未知结果、归档、删除或其他账号的历史。
- Desktop 运行时排队等待，不在它写入的同一时刻宣称已同步；进程不存在不能当作跨应用锁，要处理「检查后又启动」的竞态。
- 先在独立 profile 验证最小记录与关联索引：可见、同一 CLI ID、正文完整、重复运行不重复、后续可续接、退出后不丢，再谈正式开关。
- 必须确定 profile、account、org 归属；多命名空间或状态不一致时不能猜「最近一个目录」。
- 原子创建、不覆盖已有记录，只保留新建自有记录的变更清单；遇到新格式或冲突立即停止。
- Desktop 升级要有版本／格式识别与降级；若需频繁追随私有字段，停止该路线。

## CC Switch 双路由排障

- Code 与 Desktop 是两条独立路由，`live-state.json` 里 `claude` 与 `claude-desktop` 可以指向不同供应商。
- 典型症状：Code 能连接，但发送返回 `API Error: 400 配置错误: Claude Provider 缺少 base_url 配置`。原因是 Code 路由指向了没有上游地址的官方配置，而 Desktop 路由指向了有地址的第三方供应商。连接成功只说明握手可用，不说明认证与上游可用。
- 处理顺序：在 CC Switch 选择 **Claude Code**，为 Desktop 正在用的那家供应商补一个对应的 Code 预设，填供应商原始认证与上游配置；再到路由页实际执行「路由到此」，确认卡片显示「路由中」。模型映射按 Code 预设配，**不要**把 Desktop 网关的本地地址当成上游。
- 改完不需要重新打包；在工具箱保持默认模型发一条短消息验证，必要时先断开重连。
- 适配边界：只支持用户主目录里的 Anthropic 兼容配置与模型映射。只在 CC Switch 配了 Desktop、没有写 Claude Code 用户配置的情况不自动推断；通过 `apiKeyHelper` 或专有云身份配置的供应商也不在本轮自动接入。
- profile 与 settings 的字段形状来自当前安装版本与 CC Switch 文档；未来格式变化、非 Bearer 认证、专有云身份都需要另行适配。

## 未验收风险

- 续接后回到 Desktop 原会话能否读到新增消息（含标题、叶节点、分支与压缩后的上下文是否一致）**未实机验证**；没通过就不能宣传双向同步，也不能把自动化结果当成证明。
- 真实第三方供应商的协议兼容、Desktop 的正文回显、真实网关模型元数据都还没跑过真实请求；现有证据来自合成 profile、合成 SDK 与合成网关。
- 打包安装后的完整退出（未连接、空闲、有运行任务三种状态）待人工确认；退出时曾出现 `Object has been destroyed`，已改为先撤订阅、再断运行时，并加窗口／WebContents 存活检查，但真实程序退出仍需用户复验。
- 外部进程门是快照，能挡住续接却挡不住事后并发；路径别名、日志缺失或超出读取上限会让历史不出现，此时不补建会话。
- macOS／Linux 的配置路径有代码分支，但没有实机验证；交付平台仍是 Windows。
- 索引丢失后不能可靠重建来源，需保留数据库备份；旧版本程序不识别 Desktop 草稿标识，降级时保留密文，不要为回退清空记录。
