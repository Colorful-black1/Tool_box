# 待办与提醒

本文件记录桌面「个人管理 → 待办清单」的字段、筛选、提醒时序与数据恢复边界。待办是本地普通数据，不用于保存密码、密钥或完整证件号。

## 数据与字段

- 待办表在 schema v5 引入；当前 schema v7，后续迁移未改该表。
- 字段：`id`、`title`、`details`、`priority`、`start_at_ms`、`due_at_ms`、`remind`、`completed_at_ms`、`archived_at_ms`、`start_notified_for_ms`、`due_notified_for_ms`、`created_at_ms`、`updated_at_ms`。
- 标题 1–120 字符，备注最多 4000 字符，ID 最多 64 字符；优先级为低 / 普通 / 高。
- 开始与截止均可为空；两者都有时必须开始不晚于截止。日期时间按本机时区输入 `YYYY-MM-DD HH:mm[:ss]`，存储为毫秒时刻。
- 默认未完成；快速新增只填标题即可。列表每页最多 100 条、默认 30 条。
- 筛选：全部、今日、待开始、逾期、已完成、归档；可按标题与备注搜索。
- 完成、重开、归档、恢复均保留记录，不物理删除。编辑中的内容仅在本次运行保留，退出前需保存。

## Agent 工具

- `todos_list` / `todos_get` 只读查询，返回确切 ID、日期、状态与分页；列表备注截断为 240 字符。
- `todos_save` 新建或修改待办与提醒，`todos_set_state` 完成、重开、归档或恢复；两者走审批，不物理删除。
- 写操作前先查询确切 ID；审批期间记录被修改则拒绝写入，不静默覆盖。

## 提醒

- 应用运行或驻留托盘时，每 30 秒检查一次，启动时先立即检查；系统从睡眠唤醒时补检。
- 开始与截止各提醒一次；完成或归档后停止；修改对应时间后重新安排。
- 退出应用后没有后台计划任务，不保证关闭后送达。
- 重启或唤醒漏过时合并补发；同一批最多处理 200 项，多条待办合并为一条通知。
- 已过截止的待办只补截止通知，不再单独补开始通知。
- 通知只含标题（最多 120 字符）与待办数量，不含备注；点击单条定位该事项，多条汇总打开待办清单。
- 提醒开关关闭时不通知；系统不支持通知或显示失败时在页面提示，不宣称已送达。
- 系统确认显示后才写去重标记；进程在显示与落库之间崩溃，可能在下次启动时重复提醒一次。
- 失败后约 60 秒再重试；测试通知有 10 秒冷却。

## v5 迁移与回滚

- 待办表在 v5 引入，迁移只新增 `todos` 表与提醒/列表索引，不改旧表；迁移与 `user_version` 更新在同一事务内。
- v5 升级前对已有文件库生成 `backups/toolbox-before-v5-<时间戳>-<随机ID>.db`。现行备份按目标版本命名（当前为 `toolbox-before-v7-...`），仍使用 `VACUUM INTO` 生成含已提交 WAL 数据的一致快照。
- 备份不覆盖已有文件；备份失败停止升级并提示。新空库不生成升级前备份。
- 回滚由用户手动执行：完全退出所有读写该库的应用；把当前 `toolbox.db` 及 `-wal` / `-shm` 移到独立备份目录；把选定快照复制为数据目录下的 `toolbox.db`；保持主密钥和数据目录其他文件不变。
- 不要把旧 WAL / SHM 留在恢复的快照旁，也不要在应用运行时覆盖数据库。回滚会丢失快照之后的新数据。
- 实现不自动降级、删表或重置用户数据库。旧版本程序仍可读取未改变的旧表，但不识别待办。

## 边界

- 首版不做重复任务、协作、附件或自动 AI 提取。
- 通知显示受 Windows 免打扰、通知中心和安装环境影响；`show` 成功只表示系统接受显示，不保证用户看到浮窗。
- 提醒检查允许约 30 秒延迟；系统时区变化后，已有待办的显示时间会变化。
- 待办与普通笔记同为本地普通数据，不扩展密码箱加密链路。
