## 1. 为什么是这四项，以及为什么是这个顺序

| 顺序 | 能力 | 用户价值 | 授权成本 | 为什么排这里 |
| --- | --- | --- | --- | --- |
| A | 密码健康报告 | 让"存进去的密码"第一次产生整体视角 | 零（纯渲染 + 既有数据） | 能在 1 轮内交付，先证明"增量轮"能落地 |
| B | 剪贴板历史 | 每天几十次的高频动作 | 新 IPC，零 schema | 桌面端独有优势，且不落盘就能交付 |

## 3. 能力 A：密码健康报告

### 用户场景
"我用了三年，存了八十条密码。哪些重复了？哪些还是 `abc123`？哪些早就该换？"

### 首版范围
- 入口：密码箱页面顶部工具条新增「健康检查」按钮（`.btn-ghost`），打开右侧 Sheet（复用现有弹层范式）。
- 指标（全部在渲染层用 `PasswordEntryView[]` 现算，不落盘、不发网络）：
  1. 条目总数 / 解密失败数；
  2. **重复密码组**：同一明文出现 ≥2 次，按组列出标题（**不显示明文**）；
  3. **弱密码条目**：`passwordStrength()` 的档位为弱，列出标题与档位；
  4. **长期未改**：`updatedAtMs` 超过 365 天；
  5. **空密码**：`password === ''`。
- 每组可点开看到条目标题，点击跳到该条目详情（复用现有详情打开逻辑）。
- 空库 / 全部健康时给明确空状态（沿用既有空状态样式，带一句下一步）。

### 非目标
- 不做"一键改密码"、不做泄露库查询、不做评分排行、不导出报告文件。
- 不改密码箱的列表/详情交互，只在页面加一个入口。

### 实现落点
- `src/shared/password-health.ts`：纯函数 `analyzePasswordHealth(entries)` + `分组/阈值` 常量，返回只含标题、id、档位、天数的视图对象；**返回值里不得含明文密码**。
- `src/shared/password-health.test.ts`：重复（含大小写不同算不同）、弱密码、空密码、解密失败不参与重复统计、边界条目。
- `src/renderer/src/components/password/password-health-sheet.tsx`：展示 + 跳转。
- `src/renderer/src/components/password/password-box-page.tsx`：加按钮与开关状态。

### 验收
- 造 3 条同密码 + 1 条弱密码 + 1 条解密失败：重复组 1 组 3 条、弱密码 1 条、失败数 1、失败条目不出现在重复组里。
- 全部健康时显示空状态并可关闭；Esc 关闭后焦点回到「健康检查」按钮（继承第 22 轮已修行为）。
- 磁盘、网络、日志、IPC 均无明文密码出现。

## 4. 能力 B：剪贴板历史

### 用户场景
"半小时前复制的那段报错，我想再粘一次。" / "刚复制的东西被覆盖了。"

### 首版范围
- 采集：主进程 `setInterval`（700ms）读 `clipboard.readText()`，与上次值比对；**Electron 没有剪贴板变更事件，必须轮询**。
- 规则：连续重复不重复记录；单条上限 10,000 字符（超出截断并标记）；空/纯空白忽略；最多保留最近 200 条；**仅本次运行有效，退出清空，不落盘**。
- 隐私：
  - 默认**关闭**，开启时明确提示"会记录你在本机复制的所有文本（含其他应用）"；
  - 「暂停记录 30 分钟」按钮；
  - 忽略规则：用户可维护一组关键词/前缀，命中不记录；
  - **密码箱自己的复制不打标记**：主进程 `system:copy` 写入剪贴板时记录内容哈希，采集到同一内容时跳过（复用现有 `copyText` 通道，改动一行）；
  - 不记录图片、富文本、文件路径列表（首版只文本）。
- 入口：命令面板增加「剪贴板历史」指令；工具页或侧栏不放新入口（避免导航变更）。
- 面板：列表（时间倒序）、搜索、点击回填（写回系统剪贴板并提示已复制）、固定项置顶、单条删除、清空全部。

### 非目标
- 不做跨重启保留、不做图片/文件历史、不做跨设备同步、不做自动粘贴到焦点窗口（需要系统级输入模拟，暂缓）。
- 不新增全局快捷键（现有快捷键管理器只支持一个组合，扩展属另一件事）。

### 数据结构
- 主进程内存队列（`ClipboardHistoryService`），不写数据库、不写 `kv`。
- 视图形状：`{ id, text, preview, capturedAtMs, pinned, truncated }`，**不含来源进程**（Windows 下拿不到可靠来源）。

### 实现落点
- `src/main/services/clipboard/clipboard-history.ts`：采集、去重、上限、暂停、忽略规则、固定。
- `src/main/ipc/register-ipc.ts`：新增 handler（走 `ipc/validation.ts` 校验）。
- `src/shared/ipc-contract.ts`：`system:clipboard:list | clear | pin | set-enabled | pause`；`WINDOW_EVENT.clipboard` 推送变更。
- `src/shared/bridge.ts` + `src/preload/index.ts` 对应段 + `src/renderer/src/stores/clipboard-store.ts`。
- `src/renderer/src/components/tools/panels/clipboard-panel.tsx`（按首版入口约束由命令面板打开；不在工具目录或侧栏新增入口）。

### 验收
- 复制 3 段不同文本 → 面板出现 3 条且顺序正确；重复复制同一段不新增。
- 在密码箱复制一条密码 → 面板不出现该内容。
- 关闭开关后复制 → 不新增；暂停期间不新增，30 分钟后自动恢复。
- 退出应用重开 → 列表为空（首版设计如此）。
- 超过 10,000 字符的文本被截断并标注。

## 5. 能力 C：文件工具箱 · 重复文件查找（只读）

### 用户场景
"这个目录里到底有多少重复的安装包和截图？"

### 首版范围
- 入口：工具注册表新增分组「文件」（只改 `TOOL_GROUPS`，**不动导航**），第一个工具「重复文件查找」。
- 流程：选目录 → 递归枚举（跳过 `.git`、`node_modules`、`out`、`release`、隐藏目录；最多 20,000 个文件、深度 12）→ 按大小分桶 → 只对同大小文件做流式 SHA-256 → 展示重复组（大小、份数、可释放空间）→ 组内可展开看路径。
- 约束：只读；不跟随符号链接；不跨盘；路径只能来自系统目录选择框，**渲染层不能传任意路径**；结果不含文件内容。
- 可取消、有进度、有上限提示（截断时明确说明"仅扫描前 N 个文件"）。

### 非目标
- 本批次**不做任何写操作**：不删除、不移动、不做硬链接替换。
- 不做批量重命名（另立一项，需要预览 + 撤销清单 + 二次确认）。
- 不做图片/视频感知去重，只按内容哈希。

### 实现落点
- `src/main/services/files/duplicate-finder.ts`：枚举、分桶、哈希、取消令牌、进度回调（纯 Node，无依赖）。
- `src/shared/file-tools.ts`：路径归一化、体积格式化、分组视图类型（纯函数 + 单测）。
- IPC：`files:choose-directory`、`files:find-duplicates`、`files:cancel-scan` + `WINDOW_EVENT.fileScan`。
- 面板：`src/renderer/src/components/tools/panels/duplicate-panel.tsx`。

### 验收
- 合成目录：同名同内容 / 异名同内容 / 同大小不同内容 / 0 字节文件 → 只把内容相同的归为一组；0 字节文件按既有规则单独说明（建议不参与重复组）。
- 取消后不残留进度；再次扫描结果一致。
- 20,000 文件上限触发时明确提示；扫描期间 UI 可操作（不冻结）。
- 结果只读，磁盘文件 mtime 不变。

## 6. 能力 D：备份与导出

### 先说清楚一个硬事实
主密钥由 DPAPI 封装（`password-master-key.json`），**绑定当前电脑 + 当前用户**。把 `toolbox.db` 拷到另一台机器，密码箱条目会全部变成"解密失败"。所以"备份"要拆成两种，语义不能混：

| 类型 | 内容 | 能恢复的场景 | 风险 |
| --- | --- | --- | --- |
| **本机快照**（本批次） | `toolbox.db` + `covers/` + `backgrounds/` + `ai-settings.json` + `password-master-key.json` | 误删、升级回滚、同机重装 | 包里含主密钥，外传即等于交出密码箱 |
| **可迁移导出**（后续单独评审） | 用用户口令派生的密钥重新加密的明文数据 | 换机、迁移 | 涉及加密链路，必须单独授权 |

**本批次只做「本机快照」的导出与恢复，不做可迁移导出。**

### 首版范围（R6 导出 / R7 恢复）
- 入口：系统 → 设置页新增「数据与备份」区块（复用现有设置卡片），两个按钮：`导出本机快照`、`从快照恢复`。
- 导出：
  1. 用户选择目标文件夹；
  2. 用 `better-sqlite3` 的 `db.backup()` 生成**一致性快照**（WAL 模式下不要直接复制 `.db` 文件）；
  3. 复制 `covers/`、`backgrounds/`、`ai-settings.json`、`password-master-key.json`；
  4. 写 `manifest.json`：版本号、schema 版本、生成时间、文件清单与大小、**"仅可在本机恢复"** 标记；
  5. 目标为**文件夹**而不是 zip（Node 标准库没有建 zip 的 API，不为此新增依赖）；
  6. 完成提示里给出路径与"请勿上传网盘/发给他人"的警告。
- 恢复：
  1. 二次确认弹窗，写明"会覆盖当前全部数据，覆盖前自动生成一份当前快照"；
  2. 自动前置快照 → 关闭数据库连接 → 复制覆盖 → 重启应用（提示用户手动重启，不静默重启）；
  3. manifest 版本或 schema 高于当前程序时**拒绝恢复**并说明原因；
  4. 恢复失败时保留当前库（先备份后覆盖，失败可回退）。

### 非目标
- 不做可迁移导出、不做云盘、不做定时自动备份、不做增量备份、不做 zip 打包。
- 不把备份写入用户文档目录以外的位置（由用户选择）。

### 实现落点
- `src/main/services/backup/backup-service.ts`：导出、恢复、manifest 校验、前置快照。
- IPC：`backup:export`、`backup:restore`、`backup:choose-folder`（恢复前的冲突/版本校验在 handler 内完成）。
- 设置页：`src/renderer/src/components/settings/backup-settings.tsx`。
- 文档：`README.md` 增加"备份与恢复"小节，写明"仅本机可恢复"。

### 验收
- 导出后目标文件夹含 `toolbox.db`、`manifest.json`、`covers/`、`password-master-key.json`；`toolbox.db` 能在另一目录用 sqlite 打开且 `user_version` 正确。
- 恢复：先自动快照、再覆盖；重启后书架、密码箱、笔记、待办数量与导出前一致。
- 目标文件夹已有同名备份时提示并让用户选择新目录，不静默覆盖。
- manifest schema 版本高于当前程序时拒绝并给出提示。
- 全程无日志输出主密钥内容。

## 8. 变更摘要（给评审看）

- **schema**：不变，仍 v5，不新增表、不新增列。

## 10. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 剪贴板记录到密码 | 严重（隐私） | 默认关闭 + 自身复制跳过 + 关键词忽略 + 不落盘 + 退出清空 |
| 备份包外传 | 严重（等于交出主密钥） | 导出时强警告 + manifest 标记 + README 写明；后续可迁移导出单独评审 |
| 恢复覆盖错库 | 严重（数据丢失） | 恢复前自动快照 + 二次确认 + 版本校验 + 失败保留当前库 |
| 大目录扫描卡死 | 中 | 上限、深度限制、可取消、分片哈希、进度事件 |
| 轮询剪贴板耗电 | 低 | 700ms 间隔、关闭时不轮询、仅在窗口存在时运行 |
| 健康报告在渲染层持有明文 | 中 | 只在内存计算、不写日志、不进 IPC、不返回明文给 UI |
