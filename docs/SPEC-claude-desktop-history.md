# Desktop Code 本机历史与退出销毁竞态

日期：2026-10-26。用户要求先提交既有工作，再按历史评估实施；同时报告退出时 `WebContents.send` 抛出 `Object has been destroyed`。

## 范围与流程

- 退出先撤销所有者／事件订阅，再断开原生运行时；IPC 发送前检查窗口及 WebContents 存活。仍执行原有任务停止、审批清理和 SDK 关闭，不吞掉其他业务错误。
- Desktop 入口只读 `Claude-3p/claude-code-sessions` 的本机 Code 描述，使用 `cliSessionId` 关联官方 SDK 历史，按项目验证。普通 Chat、Cowork、云端／SSH／WSL、归档和失效描述不纳入可续接入口。
- 列表和原文通过既有历史接口展示，不自动创建或发送。选中已结束的原生会话后，显式发送使用同一 CLI 原生 ID 的 SDK `resume`，沿用 Desktop 网关与工具箱权限。
- 首期无法可靠获得外部桌面任务的运行锁；因此读取允许 Desktop 运行，续接前使用固定 Windows 系统命令确认没有外部 Claude 进程。存在进程或查询失败时明确停止，保留草稿，不终止外部程序、不自动重发。当前 Tool_box 自有初始化查询已结束才会进行续接。
- 进程列表使用无表头 CSV，避免零匹配提示的系统语言／OEM 编码差异；只有完整识别进程列表且无 Claude 映像时才继续。这是检查时刻的快照，不是跨应用锁，不能阻止用户随后重开外部程序。
- 不重写 Desktop 的会话描述、游标、标题或状态；不承诺回到 Desktop 后自动更新或两边实时交互。

## 接口与存储

复用现有 `codingAgents.listSessions`／`resumeSession`／`send` 及 shared 类型，不新增 IPC 通道、数据库表、依赖或加密能力。原生 ID 只由适配器解释；主进程校验窗口所有者、项目和原生来源，渲染层不接收文件路径或原始元数据。

现有工具箱 Desktop SDK 来源索引保留；合并只读发现的 Desktop Code 来源，并将这些 ID 从 Code 历史中排除，避免从另一入口误用供应商。元数据有界读取，拒绝符号链接／穿越、异常 ID 和非绝对项目路径。SDK 原文与会话列举沿用现有显示上限；读取失败不补建会话。

## 实施和验证

1. 修复销毁顺序与 IPC 存活检查，补充窗口已毁、WebContents 已毁、窗口释放及退出回归。
2. 新增只读 Desktop Code 描述解析和续接进程门；补充损坏、缺失、超限、跨项目、运行中、归档与查询失败等合成用例。
3. 适配器合并原生来源，读取正文／恢复保持身份；每次续接重读来源，准备阶段停止或断开不能迟到执行。
4. UI 明示可读取 Code 历史及续接前退出外部 Claude 的要求，更新文档和合成预览。

仅按本次相对提交 `4312e57` 的增量判断编译门槛，不计入已提交内容；只有同时超过 500 有效代码行和 10 文件才执行类型检查 → 桌面 lint → 桌面测试，并按范围构建及合成 UI。否则仅静态审查。真实模型续接与原 Desktop 回显留给用户手动验证，不自动发送用户历史作为探针。

## 验收与风险

- 退出清理不会触碰已销毁窗口；所有运行时仍能完成资源释放。
- 历史发现不调用模型，仅匹配有效本机记录；跨项目和失效身份不能续接。
- 外部 Claude 未完全退出时，原生续接不会启动；普通工具箱 SDK 新会话不额外施加该门。
- 继续使用同一原生 ID，原有历史不复制为伪新会话；失败保留草稿、不自动重发或扩权。
- 私有元数据未来变化可能导致历史缺失；进程门有意保守，会阻止其他 Claude CLI 仍运行时续接。SDK 原生日志更新不等于 Desktop UI 自动同步。
