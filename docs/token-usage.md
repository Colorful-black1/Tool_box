# 本机 Agent Token 统计

只读扫描本机各 Agent 已落盘的用量记录，按日期 / Agent / 项目 / 模型聚合，不需要连接或启动 Agent。
本文写来源清单、统计口径、硬上限与缓存边界；本功能不做模型计价。

## 1. 范围

- 独立入口「开发工作台 → Token 统计」，也可用 `Ctrl+K` 搜索。
- 与对话完全解耦：不启动原生 Agent、不改原生配置、不请求模型、不上传用量。
- 默认自动发现数据源；找不到或使用自定义目录时才要求选择路径。
- 覆盖 14 类来源；未安装的工具不占据主视图，来源管理里可看检测情况、路径与兼容状态。

## 3. 统计口径

- 只纳入原生真实计数与可证明的直接换算；不按文本长度推算 Token，不引入计费估算。
- 只展示原生上报花费（当前仅 OpenCode 的 `cost`）并标注上报条数 / 总条数；未上报显示「未上报」。
- 展示输入、输出、缓存读取、缓存写入；推理有记录时单列，若已属于输出则不重复加进总量。
- 每个适配器自行声明缓存是否包含于输入，不用同一条求和公式处理所有客户端。
- 缺失字段保留未知：可以汇总已知部分，但必须显示覆盖不完整，不能冒充全部用量。
- 累计快照不能逐条相加；同一请求的增量、最终事件与会话总量不重复计入。
- 去重按「客户端 + 原生会话 + 请求身份」；处理分支继承、子 Agent、重试、多目录副本与重复扫描。
- 请求数只在能确认模型请求身份时展示，不用对话条数代替。
- 时间以调用记录为准；只有会话汇总时不把整份历史归到最后更新时间，也不伪造每日趋势。
- 项目 / 模型无法确认时归入未知，不从目录名猜测后当作事实。
- 日期筛选统一使用明确的本地时区边界。

## 4. 采集与只读边界

- 主进程负责白名单路径发现、只读采集、归一化、去重与汇总；渲染层只展示，不碰 Node API。
- SQLite 用只读连接并正确读取活动 WAL；不复制单个 DB 文件、不用 immutable 模式忽略未合并数据，也不执行原生迁移或写查询。
- JSONL 流式读取；文件未写完的末行延后处理；格式错误不阻塞其他来源。
- 超大行用有界缓冲跳过并继续读，不再让整份文件失败；只有 Codex 明确的 `compacted` / `response_item` 正文可免除缺失告警，且要求在 4,096 字符内解析出完整根头部。未知或用量类超大行仍标记不完整，前后已提交的有效用量保留。
- 不变文件用指纹缓存，变化文件整份重读并替换快照；不跟随入口与子项的符号链接。
- 扫描异步执行、刷新请求合并，不阻塞窗口；支持文件增长、截断、替换与版本变化。
- IPC 只接受受管窗口的顶层 frame，筛选参数在主进程校验；路径只由原生文件选择器提供。
- 不记录、不缓存会话正文、标题、认证数据与密钥。

## 5. 硬上限

| 项 | 上限 |
| --- | --- |
| 目录扫描深度 | 10 |
| 单根发现文件数 | 30,000 |
| 单文件 / 解压输出 | 256 MiB |
| 单行 | 8 MiB（超出跳过该行，不终止整份文件） |
| 单条 JSON | 32 MiB |
| 单个压缩帧 | 32 MiB |
| 统计缓存 | 64 MB / 200,000 条 |
| 查询单页 | 5,000 条 |
| CSV 导出 | 50,000 行 |

- 达到限制要报告来源问题，不能当作完整统计；超限只影响该来源，不阻塞其他来源。

## 6. 来源状态与配置

- 五种状态：已读取 / 部分可用 / 读取失败 / 未发现 / 暂无用量；不一致时显示具体原因，不统一显示零用量。
- 来源路径持久化在应用数据目录的 `agent-usage-sources.json`；支持选择目录 / 数据库与恢复自动发现。
- 支持单来源重扫：只扫描该来源，不影响其他来源的缓存。
- 有数据与异常来源置顶，未发现来源收进折叠区，并显示记录数与耗时。

## 7. 缓存与刷新

- 统计缓存落应用数据目录的 `agent-usage-cache.json`（版本 1、原子写 tmp + rename、只含 Token 元数据）。
- 启动先展示上次结果，再按需增量扫描；缓存损坏、版本不符或超限时静默回退为重新扫描。
- 页面可见时每 60 秒检查一次，隐藏或离开后停止周期扫描，保留手动刷新。
- 周期与筛选（含排序）写入 `localStorage`，换页返回后保留。
- 缓存只保存客户端、会话 ID、项目路径、模型、Token 与原生花费。

## 8. 页面与导出

- 指标卡：总 Token、请求数、会话数、缓存命中率、缓存写入、推理；有原生花费时增加「原生上报花费」。
- 趋势：按 Agent 堆叠，7 / 30 / 90 天，按自然日窗口截取，只为有记录的日期画柱，受 Agent / 项目 / 模型筛选影响。
- 排行：按模型、按项目 Top 8，可点击转为筛选条件。
- 明细：服务端排序（时间 / 各 Token 字段 / 花费）、粘性表头、会话详情抽屉、分页。
- CSV 导出按当前筛选分页取数，最多 50,000 行，UTF-8 BOM，列名固定。

## 9. 隐私

- 只保留统计所需元数据；不保存或输出正文、标题、凭据。
- JSONL 正文只在单行解析期间短暂存在；SQLite 只投影所需列，不取认证表与原始请求体。
- 不上传用量，不修改原生数据与配置。
- 日志只含来源、条数、耗时与错误码。

## 10. 已知边界

- 原生花费只有 OpenCode 提供，其它来源显示「未上报」，不能把已知花费当成全部费用。
- Codex 累计补差记录没有时间与模型，累计视图会提示字段不完整，不伪造每日或模型用量。
- 本机记录可能缺失、被裁剪或字段不完整；来源格式升级需要维护适配器。
- 未实现按字节偏移尾读，变化文件整份重读；超大日志的耗时取决于文件大小。
- 不做模型计价、余额查询，也不与各原生应用的界面总量逐项对账。

本机实际发现并读取了部分来源，其余来源由合成样本覆盖；「解析用例通过」不等于「本机真机通过」。
