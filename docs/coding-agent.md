# 编程 Agent

Tool_box 的编程 Agent 是一个统一工作台：OpenCode、Codex、Claude Code、Claude Desktop、DeepSeek Harness（DSH）五个入口共用一套运行时、事件与审批契约，各自保留原生会话、权限与草稿。Kimi 只保留枚举，不进入选择器，也不因缺少程序而代装软件。手机端自 2026-10-23 冻结，本工作台不做跨端适配。

## 范围与入口

| 入口 | 原生方式 | 备注 |
| --- | --- | --- |
| OpenCode | 复用 Desktop 内置 CLI（ACP） | 不另装 CLI，沿用其登录与权限 |
| Codex | 安装版 App Server stdio | 协议随版本演进，不把 alpha 支持推断成所有版本 |
| Claude Code | 官方 Agent SDK，读 `~/.claude` | 供应商细节见 [Claude 接入](claude-providers.md) |
| Claude Desktop | 官方 Agent SDK + CC Switch 网关 | 同上 |
| DSH | 独立 ACP | 独立启动 cwd，见下节 |

- 每种运行时首版一个默认原生 profile，不支持同一运行时混用多个账号或自定义 profile。
- 运行时与模型分开选择：换模型不换运行时。
- 不提供任务表、自动团队、并行 worktree、Paperclip 或插件市场入口。
- 交接专用角色管理已取消，旧角色配置只做兼容校验，不自动清空。

## 身份与事件契约

- `runtimeId` 标识入口；`connectionId` 是每次连接／尝试连接的代次，只用于隔离旧事件；`sessionRef` 是内存中的不透明引用，绑定运行时、连接、项目与原生会话 ID；`runId` 对应一次顶层发送，与原生轮次分开；`revision` 在同一次连接内单调递增，旧事件不得覆盖新视图。
- 重连可以重建 `sessionRef`，但必须恢复用户选择的同一个原生会话，不能补建。本地引用与正文只留在内存，完整历史由原生工具管理。
- 新建与恢复是两种意图；缺失会话参数不得被当作隐式新建；发送必须携带 `sessionRef`。
- 用户首次点击发送时，renderer 依次调用既有的连接、新建、发送方法；不为这三次调用新增复合 IPC。切入口、读历史与消息转用都不发送。
- 事件只投递给连接所属窗口，带 `runtimeId`、`connectionId`、`revision`；会话快照带 `runId`。同一运行只有一个终态；增量与最终正文按原生条目标识核对，不重复追加。
- 会话视图只含最近一页消息，用 `messageWindow`（是否还有更早、最早／最新序号、总条数、被截断条数）描述窗口；`truncated > 0` 必须显式提示，更早内容按序号回取。
- 能力值只有 unknown / supported / unsupported；历史、恢复、子任务详情、独立取消、用量、Desktop 可见性分别记录，不用一个布尔值概括。
- 外部输入统一经 `ipc/validation.ts` 校验：运行时白名单、原始字符串长度、非空与布尔值。不开放任意 RPC、shell 字符串、通用文件访问或凭据接口；未知审批只拒绝或提示不支持。
- 取消只作用于对应运行；超时或断连显示结果未知；不自动重发，也不向其他运行广播。
- 保留 `window.toolbox.opencode`、原生类型与旧 IPC：统一服务包装同一个 OpenCode 实例，新旧入口共用运行互斥与连接所有权，renderer 只消费一条事件流。旧 preload 下给出明确降级提示，不伪造其他 Agent 可用。

## 运行时与原生适配

- 主进程维护适配器注册表、连接所有权、操作互斥、会话引用，以及按运行时划分的顶层运行槽位。
- 原生程序只按受限绝对路径与固定参数启动，`shell: false`、隐藏窗口；提示词经协议传递，不拼命令行。
- 检查程序只执行有界的版本命令，不调用模型。
- 不复制认证文件、不读 key 内容、不把 Tool_box 的 AI 配置注入原生运行时。Codex 启动时过滤已知的其他 Agent／供应商认证变量，保留其自身认证环境；OpenCode 保持既有多供应商环境兼容逻辑。
- 主进程日志只记录运行标识与状态，不记录任务正文、原始 stderr、认证结果或请求头。
- 通信侧限制单条消息大小、缓冲区、待处理请求数、审批数量与响应时间；协议失败时清理待处理项。未知反向请求返回不支持。
- 关闭只处理 Tool_box 自己启动的进程，不杀独立 Desktop 窗口；关闭时清理计时器、审批与订阅。结果未知的运行保留提示，不重试写操作。
- 退出顺序固定：先撤销窗口所有者与事件订阅，再断开运行时；向 renderer 发事件前检查窗口与 WebContents 存活（顺序错误曾在退出时抛 `Object has been destroyed`）。
- stdio 连接把进程退出、启动失败、输入管道关闭、输出超限、协议格式异常分开上报；日志只留安全原因、退出码与未决数量。

### OpenCode 的既有约束

- 复用 Desktop 内置 CLI 与握手，不启动第二个 OpenCode。
- 模型可见性只读 Desktop 偏好：`ai.opencode.desktop/drafts.sqlite` 的 `state` 表中 `name=opencode.global.dat`、`key=model`；只解析用户可见性，不读对话、草稿或登录信息。规则为显式 hide 优先、显式 show 显示、未指定时取近期各供应商／家族／免费档的最新模型，保留无有效发布日期的默认可见项。
- 候选模型经内置 CLI 的 `api model.list`（按项目目录）取得，只提取 id、供应商、家族、发布日期与费用档位；读取失败明确报错，不回退展示全量模型。当前模型被隐藏后需重新选择才能发送。
- 原生标题：恢复时沿用历史摘要标题并消费 `session_info_update.title`（上限 100 字符）；任务结算后读一次、10 秒后补读一次，不持续轮询；断连清理计时器，旧响应不能回写。
- 目录不是安全沙箱；初始 fs／terminal 能力不宣称支持；ACP 版本、配置选项或 Plan 缺失时拒绝创建可发送会话；断线或超时不自动重发，结果可能未知。

### DSH 的启动与历史

- 宿主进程使用 Tool_box 固定的临时空目录启动，项目路径只经 ACP 的 `session/new`、`session/resume`、`session/list` 的 cwd 传入。原因是 DSH 会读取启动 cwd 下的 `.env`，项目里出现 `DEEPSEEK_BASE_URL` 时它直接拒绝启动；改用空 cwd 后项目 `.env` 可原样保留，不必删变量也不必注入启动环境。
- 历史与 Desktop 共用 `~/.dsh/sessions`。ACP 能列出 Desktop 创建的非空会话；标题读 `session_projcache/sessions/<id>.json`，隐藏 `blank` 或无标题且无 `lastPromptAt` 的空会话。Desktop 仍会把空会话显示为「未命名」，需要在 Desktop 侧删除，Tool_box 不写也不删 DSH 数据。
- 打开历史时只读解析 `session.v4.jsonl.zstd` 的连续 zstd 帧，恢复用户／助手文本，跳过注入消息（agent-instructions、runtime-context、skill-catalog）、推理块与工具块；上限 200 条／20 万字符，格式失败回退为空。
- ACP 恢复只续接上下文、不回放旧正文，所以先恢复正文再请求原生 resume；resume 失败（例如会话正被 Desktop 占用）仍返回已读正文并标记为已断开，提示关闭 Desktop 会话后重试，不自动恢复、不重发、不改写 DSH 数据。
- 归组是用户主动动作：`coding-agent:session:workspace` 只接受已打开会话，按项目路径匹配 Desktop 的 `storages/workspace.json`，校验版本 2，写前留 `.toolbox-backup`、原子替换并取消该会话归档；不自动创建或删除工作区。

## 工作台交互

- 保留导航「编程 Agent」，直接切换五个入口，各自恢复已选项目、会话与草稿；只有从未选过项目的入口才继承当前项目。切换不连接、不创建、不发送。
- 选好项目后输入任务，首次点「开始对话」才按需连接、新建并发送；模型不可用时保留草稿与已建会话供选择。
- 程序路径、版本、手动连接／断开收进连接设置；模型、权限与审批保持可见。
- 未安装或未接入要显示具体原因；一个入口不可用不影响其他入口。
- 新对话按钮只进入项目草稿，首次发送才创建原生会话。历史入口连接并列出原生记录，点选即恢复，已打开的会话按原生身份去重。
- 恢复失败保留原因，不转成新建；重连后保留旧草稿与失效选择，不能把它们隐式发送到新会话。
- 发送按钮绑定当前会话；每个运行时一次只有一个顶层任务。

### 会话标签与历史浮层

- 已打开的会话以顶部标签呈现，标签带状态点、标题截断与关闭按钮；方向键只移动焦点，Enter 打开；选中已加载的标签复用本地会话，不重复请求恢复，已断开的会话走明确恢复。
- 关闭支持点击按钮与聚焦标签后按 Delete。关闭当前标签后优先选右侧相邻，否则左侧，全部关闭回到「新对话」。历史面板仍合并已关闭的缓存记录，用户明确打开时重新显示；晚到的会话更新不会自己把标签重开。
- 任务执行／停止中、发送准备中、连接或会话操作处理中不接受关闭，也不会顺带停止任务；会话缓存重建时清理旧关闭引用，关闭状态不持久化。
- 历史以浮层呈现（搜索图标触发），内含搜索、刷新与原生恢复，选中后收起；每次展开都重新读取，不使用旧缓存，也不轮询或后台连接。
- 已打开的历史在刷新列表、空闲时重新点选、列表展开期间窗口重新获得焦点时会重读正文；任务运行或准备期间不自动重读。只允许明确的历史重读更新正文，原有事件流仍受终态保护；失败保留旧正文，不补建、不重发。
- 「打开 Desktop」这类外部入口按钮只在 OpenCode 显示；`coding-agent:desktop:open` 对其余运行时直接返回「桌面会话可见性尚未验证」，不要把它当通用唤起接口。

### 消息分页与存储预算

- 主进程为每条消息分配会话内单调的 `seq`（按消息 id 复用）；游标只用 `seq`，因为 ACP 的 `native-*` id 可能缺失或重复。
- `coding-agent:session:messages` 按 `beforeSeq` 分页；单页同时受 40 条与 30,000 字符两个约束，先到者为准。
- 会话事件只推尾页，并附 `messageWindow`（`hasMore` / `earliestSeq` / `latestSeq` / `totalMessages` / `truncated`）；`truncated` 必须显式提示。
- 存储预算 4,000 条 / 4,000,000 字符，超出丢弃最旧并计数，界面提示「更早的 N 条已超出本机缓存」。
- 四个入口都不再因为显示上限停止任务；渲染层缓存已加载的更早页，接近顶部时预取；插入前记 `scrollHeight`、插入后按高度差补偿 `scrollTop`（仅在用户位于顶部时生效），到顶与截断各有独立提示，单页 IPC 负载约 100KB。
- 已知遗留：主进程内存随会话长度增长（靠存储预算兜底），事件仍携带尾页全量文本，未做增量差分与虚拟滚动，滚动触发也只有「到顶自动预取」一种。

### 输入与模式

- 输入框 Enter 发送、Shift+Enter 换行。中文输入法正在组词、229 确认键以及长按重复事件都不触发发送；空输入、运行中、准备中同样不发送。草稿恢复不自动发送。
- 模式／权限、模型、思考强度直接摆在输入框底栏，不藏在「更多」里；模型只列已启用项，运行或准备中不可切换。其他原生选项也直接显示，参数只来自己打开的原生会话，不编造。
- Claude 两入口提供四档：Auto（`auto`）、Manual（`default`）、Accept edits（`acceptEdits`）、Plan（`plan`），默认 Plan。只映射原生 `permissionMode`，不在工具箱伪造自动审批，不提供 Bypass 或跳过权限的标志。
- 监听原生初始化／状态消息里的实际模式：例如 Auto 未生效而落回 Manual 时，同步选择器并提示。未支持的模式中止任务，不自动扩权。Auto 是否可用取决于程序、供应商与模型，工具箱选项不能保证。
- 「＋」集中提供引用文件、命令、Skill、MCP，复用输入框上方的候选面板；选入口不自动发送，候选支持方向键、Enter／Tab、Esc 与输入法确认。
- 上下文占用与本轮耗时收在底栏右侧；发送／停止用图标按钮，保留可访问名称、悬浮提示与危险样式；接近正文限额时才显示计数。

## 项目隔离与并行

- Agent 已选项目不被来源项目覆盖：首次使用时可以继承当前项目作起点，检测到自己保存过的项目则优先恢复，用户明确选择的项目最高优先。
- 不同 Agent、不同项目可以同时准备、执行并接收结果；同一个 Agent 仍一次一个任务；同一规范项目路径不并发执行顶层任务，避免同时写入。
- 查看后台任务、停止、取消发送准备、审批都指定运行时与会话。某个任务结束、失败或断开只释放它自己的状态。发送确认的忙碌锁不阻塞审批与停止这类控制请求。
- 后台任务展示 Agent、项目与状态；存在审批时可直接进入对应会话。切换页面不停止、不重发、不新建任务。
- 原生事件沿用 `connectionId` / `sessionId` / `runId` / `revision` 检查，旧连接与迟到事件不得清除其他任务的状态。
- 文件候选与未发送引用必须随 Agent／项目切换失效，不能把来源项目的引用带进目标任务。
- 开发工作台里的切换只改变当前查看的 Agent，不改变其他 Agent 的项目、历史、草稿或运行状态。

## 项目记忆与转用

- 每个入口独立保存自己的项目，复用既有配置 kv，规范键集中在 `src/shared/agent-projects.ts`；Claude Desktop 同时兼容旧 `claude-desktop` 别名与 `claudeDesktop` 键，不会把两者当成两个 Agent。
- 项目记忆与「当前实际连接目录」分开表达：检测结果里的 `projectDirectory` / `projectError` 表示记忆与错误，旧 `directory` 继续代表当前连接或原生偏好，不能用选择动作伪装成连接切换。
- 用户确认目录选择器即由主进程 realpath、目录与可访问性检查后保存，不要求连接成功；连接成功后再用原生规范目录回写。
- `chooseDirectory(runtimeId?)` 无参时仍只做选择／授权；带参时校验并保存该 Agent 的项目。`coding-agent:project:select` 只接受 `{ runtimeId, directory }`，保存选择并返回规范路径，不启动模型、不修改连接，供「返回原项目」使用。
- 页面初次检测优先记忆目录，只有从未选择过时才继承。草稿文档仍是 v1，只恢复草稿与最后查看入口，其中的单一选择字段不得覆盖各 Agent 的项目记忆；恢复期间不主动读原生历史、不建会话。
- 目录无效时保留可理解的项目选择与错误提示，允许重新选择；不创建目录、不删除记忆、不崩溃。配置补丁按字段合并，保留程序路径与扩展设置。
- 同项目消息转用不新增确认；原有「新对话草稿将被覆盖」的确认保留。
- 目标入口已有不同项目时，转用前一次性确认：离开原项目、连接在发送时才替换、草稿保留、原生历史仍可重读；如果目标来源项目的新对话草稿也会被覆盖，合并进同一次确认。取消不修改目标状态。
- 确认后只准备目标的新对话草稿，不连接、不断开、不恢复、不发送。提示条显示来源 Agent、来源项目与目标原项目；连接描述依据真实连接状态，不能提前声称已断开。
- 返回只恢复原项目的新对话草稿与项目选择，不恢复原生会话。原历史会话的未发送草稿仍保留在原目录／原生会话键下，用户明确打开那条历史后才恢复；转用文字不得进入原项目的历史草稿。
- 返回时同时保留来源项目尚未发送的转用草稿。目标处于运行、准备或忙碌时禁止返回或再次转用；确认期间身份、连接或草稿变化则作废旧确认。
- 目标尚未拥有项目时按首次继承处理，不制造不存在的「原项目」，也不额外弹确认。目标本次启动还没打开过时，先只读检测其记忆目录，按局部快照比较、确认后再生效；取消不创建目标工作台，也不把记忆写进目标选择。

## 协议硬边界

每个入口能做什么由原生协议决定，界面按原生声明展示；没有可靠协议就不做按钮，也不用一段文本假装原生命令。

### 原生回退

- **Codex**：只对原生声明 `historyMode: paginated` 的会话开放；能力由所选 CLI 只读导出的 schema 判定，并按可执行文件大小与修改时间缓存，不从版本号猜。
- 回退以原生轮次为锚点，移除所选提问所在轮次及其之后；执行前复核窗口、连接、会话、运行、项目互斥与历史摘要，执行后回读权威历史再更新界面。预览凭据短期单次有效（约 5 分钟），历史在上次预览后变化则拒绝执行。
- 快照上限：100 轮、200 条可见消息、200,000 字符、2 MiB 原生分页内容。超出即拒绝，不截断执行。
- 文件始终保留；同一轮内多条用户输入暂不支持按单条回退。
- 原生接口没有跨进程历史 CAS：工具箱内会复核完整快照并锁住同项目操作，但外部原生客户端同时修改同一会话仍可能不一致，回读确认不等于跨客户端事务隔离。
- 失败、超时或回读不符一律按「结果未知」处理：保留旧显示、阻止盲重试，先核对原生历史。
- **OpenCode**：ACP 没有消息级回退；原应用的 session revert 位于本地服务 API，且带文件恢复语义，与 ACP 的整会话 fork 不是一回事。要支持必须单独评估端口、认证、进程生命周期与会话归属；不用 `/undo` 文本冒充，也不写它的私有数据库。
- **Claude**：回退锚点是 chain UUID，不能用正文 `message.id`；`resumeDropsTurn` 会校验被丢弃的尾部，拒绝后不能盲重试。文件回滚是独立的 checkpoint 操作，不随编辑默认启用。每轮结束会关闭 Query，上下文读数只能在该 Query 存活期取。
- **DSH**：ACP 只提供提交与取消、配置、通用工具状态与上下文用量；不提供回退、创建 fork、历史回放与交互式 elicitation。原生 UI 有的能力不代表 ACP 有，不通过改写本地日志或私有 WebSocket 伪造。

### 能力发现与命令

- 三类执行语义必须在界面上分清：本地界面操作（不发模型任务）、原生操作或命令（有真实原生结果）、工具箱工作流（消耗模型用量、可能写文件）。
- 命令目录只来自原生发现结果：OpenCode 消费 ACP 推送、Codex 用受控 RPC 目录、Claude 用 SDK 初始化列表、DSH 明确不提供。
- 未知或已失效的 `/xxx` 在发送前拦截，不自动降级为收费对话；用户明确选择后才按普通文字发送。
- 压缩：Codex 走专门 RPC、OpenCode 与 Claude 用已公布命令、DSH 不支持。受理不等于完成，按原生终态结算，超时与断连按结果未知处理。
- 初始化目标文件不同：OpenCode、Codex 为 `AGENTS.md`，Claude 原生为 `CLAUDE.md`；目标已存在时不覆盖，只提供查看或建议。
- 缺少查询接口时显示「当前接入无法查询」，不能显示成「未配置」。

### 结构化表单

- 最多 4 个平面字段、每字段最多 12 个选项；支持文本、数值与整数、布尔、枚举与枚举数组、可选项。
- 答案在主进程逐字段复核并映射成原生值，不透传任意响应对象；空的可选字段省略，空的必填数组按原生 `minItems=0` 返回 `[]`。
- 拒绝 URL 登录、秘密字段、嵌套对象、正则与未知约束，并提示回原生客户端；不执行原生正则、不保存秘密答案、不打开链接。
- 表单与 Agent、项目、连接、原生会话、运行和请求引用绑定；切换标签不改变回答对象。超时、取消、任务结束与断线都会释放待回答状态。

### OpenCode Go 的两类错误

| 原生返回 | 界面提示 | 边界 |
| --- | --- | --- |
| `Account.TrainingNotAllowed`／`This Go model trains on request data.` | 当前模型开启了请求数据训练限制 | 属工作区模型隐私设置，不是路径或技能问题；不代改用户设置，可换模型或由用户在控制台确认 |
| `Insufficient account funds` | 当前模型供应商余额不足 | 只做提示，不重试、不改计费与配置 |

只在这两类已知标记出现时映射固定中文说明；其他错误继续走通用脱敏，不透传原始报文、`stderr` 或凭据。映射与否都不改变任务结算与不自动重发的规则。

### 个人 Skill 与 MCP 索引

- `/` 菜单统一检索本地快捷操作、原生命令、Skill 与 MCP，支持中文用途检索。
- 个人 Skill 按固定顺序发现：项目专用目录 → 项目 `.agents/skills` → 对应用户目录 → 用户 `.agents/skills` → `.cc-switch/skills`。读取有界 frontmatter；Windows 符号链接与 junction 解析真实落点，规范路径必须落在已知技能根内。
- 同名时原生 Skill 优先；原生明确禁用的项与 `user-invocable: false` 不会被文件索引重新开放。
- 文件来源的 Skill 标为「本机文件引用」：只加入临时引用，发送时重新校验路径与文件状态，由原生 Agent 按自身权限读取；不安装、不复制、不代为执行。
- MCP 只做元数据合并：原生状态，加上 Codex `config.toml`、OpenCode 用户／项目 JSON(C)、Claude CLI `.claude.json` 与项目 `.mcp.json`；Claude Desktop 只补项目 `.mcp.json`；DSH 无可靠的本机配置发现。
- 配置索引只返回名称与开关，绝不返回 command、URL、env、headers 或认证；仅有配置的服务标注「仅发现配置 · 未验证连接」。
- 目录发现不启动 MCP、不加载 hooks、不改变扩展开关；少见 YAML／TOML 语法与嵌套技能目录不做推测解析。

## 问答与执行详情

- Claude 问答／计划确认、Codex 用户提问、OpenCode／Codex 的 MCP form 共用待回答区：选项不自动提交，也不批准后续工具。
- 原生子任务与工具合并进折叠的执行详情，按原生接口展示已知摘要与父子关系；缺详情时明确提示，不生成虚构进度，也不在别的运行时建镜像。

## 草稿加密与恢复

- 存储位置是既有配置存储中的独立键，草稿正文不进入普通配置读取，也不与密码数据共用载荷格式。
- 草稿整体使用独立信封：AES-256-GCM、每次随机 IV、AAD 固定用途标识；密码仍用原载荷与同一个受系统保护的主密钥文件，两者读写互不影响。
- 文档版本号固定，保存所选运行时与项目，以及 `{ runtimeId, directory, nativeSessionId, content }` 数组；新对话的原生会话 ID 为空。路径按 Windows 规则规范化、统一大小写与分隔符，身份键用元组序列化。
- 读取返回修订号，保存以该修订号为期望值；主进程串行写入并递增，冲突需重读合并，避免旧写入覆盖新输入。
- 配额：每条 1–50,000 字符、最多 100 条、整文档明文 UTF-8 不超过 2 MiB。达到限额提示管理草稿，不静默淘汰未发送内容。
- 覆盖范围只有编程 Agent 输入框里未发送的文字（含转用内容）；笔记、密码、JWT 与日志临时输入不纳入。
- 恢复只准备输入栏：不自动连接、不新建原生会话、不发送、不恢复运行状态；不持久化连接引用、审批、执行锁与流式消息。
- 重启后恢复上次的 Agent、项目与可用草稿；历史草稿在用户选中对应历史后才绑定；原生会话失效时保留可取回草稿，不偷偷新建替代会话。
- 界面显示保存中／已保存／保存失败；读取期间的新输入优先，迟到的加载不覆盖已输入内容；发送成功后只清理对应旧文字。
- 正常退出请求窗口做有界刷新并等待确认，超时未确认时由用户选择返回或仍然退出；异常终止可能丢失最后一个防抖窗口（约 500 毫秒）内的文字。
- 密钥缺失、损坏或不可读时直接失败，不生成替代密钥、不覆盖文件；系统安全存储不可用时保留内存草稿并说明不能落盘，不降级为明文；解密失败保留原记录并提示，禁止覆盖成空白。
- 支持单条与全部草稿的主动清除，清除需确认；草稿绑定本机安全存储，不承诺跨机器迁移。


## 视觉与布局约定

- 沿用星轨主题令牌与三套主题，至少核对 1280×820 与 1024×680。
- 左侧树形导航用轻量选中态：只保留当前项的文字／图标颜色，不加选中底色、圆框、阴影、发光竖条或图标放大；键盘焦点轮廓必须保留。
- 工作台内的可见控件用既有 `Dropdown`，原生 `<select>` 只留给设置页表单。弹层走 Portal，避免被滚动区域裁切，并支持方向键、Home／End、Tab 离开、Esc 与点击外部关闭，关闭后焦点回到触发按钮。
- 公共按钮尺寸与圆角统一；主按钮圆角不能裁掉键盘焦点轮廓；危险按钮具备独立的基础样式；禁用态明确。
- 正文限制阅读宽度，宽表格与代码块仍可横向滚动；输入区与正文居中，三套主题共用既有令牌。
- 会话标签的当前项用金色强调，长标题截断，状态以圆点区分；字数计数只在接近限额时出现并变色。
- 移除重复说明：首次发送提示、Auto 可用性说明、空状态示例、快捷键说明（改到输入框悬浮提示）。正常保存状态只在草稿按钮提示里表达；保存失败、未选项目、恢复风险仍要显式显示。

## 通用边界

- 工作目录不是操作系统沙箱，原生权限也不会随来源会话转移。
- 不扩展手机端；`shared/` 的变更不再触发手机验证。
- IPC 订阅统一在 `App.tsx` 挂载与清理；Zustand 按字段订阅，避免整店订阅造成渲染循环。
- 收起历史面板期间外部新增的会话，依赖重新展开时的重读；没有轮询，也没有后台连接，所以「实时出现」不是承诺。

## 已知未验收

下列各项未实机验证，合成协议、隔离数据库与模型桩不能替代真实结论。

- **Claude**：一次真实只读回复；标准模式下的单次允许与拒绝；等待审批时停止；生成过程中停止；真实原生历史续接。
- **DSH**：实际配置模型的提交后回复；单次允许与拒绝；取消；会话被 Desktop 占用时的表现；`acp` profile 与日常 Desktop 历史范围是否一致。
- **表单**：真实 OpenCode／Codex MCP 服务触发的 form，以及不同原生版本下的字段类型与约束。
- **回退**：Codex 分页会话已用本机 CLI、独立 `CODEX_HOME` 与确定性模型桩验证过一轮；非分页历史、旧版本、附件与排队输入，以及外部客户端并发修改同一会话均未验证。Claude、OpenCode、DSH 的回退尚未开放。
- **Codex 历史权限**：历史正文恢复与执行权限映射曾合并校验，导致原生完全访问、联网或额外可写目录等不能映射的策略使整份历史被拒；现在可浏览，但未选权限前不能发送，新会话仍须确认只读。该修复需要真实会话确认；损坏记录、项目不符与仍在执行中的会话仍会被拒绝。
- **退出**：保存失败时选择「返回」或「仍然退出」的实际路径；系统强制终止下的最后防抖窗口。
- **桌面互见**：Claude Desktop 与其他客户端是否实时显示同一会话；跨机器密钥迁移；自定义安装与 WSL；非 Windows 平台。
- **Skill 与 MCP**：发现文件不代表原生已执行；外部目录权限、模型是否可用、Skill 实际步骤仍需真实任务确认。
