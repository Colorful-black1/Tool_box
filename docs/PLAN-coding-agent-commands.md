# 编程 Agent 文件引用、命令与扩展能力计划

日期：2026-10-27

状态：用户于 2026-10-27 授权按计划实施；A–C 已落地，运行时能力差异保留明确降级。
实际范围、协议与验证结果见 [交付记录](coding-agent-commands-verification.md)。下文保留原调研与设计依据，不能把官方能力当作本机全部实测通过。

## 1. 结论与目标

可行，但不能把所有 Agent 的终端命令原样塞进统一输入框。Tool_box 当前只传普通文本，缺少文件候选、命令发现、结构化 Skill 引用以及命令运行状态；部分命令可能已经被原生进程识别，但界面没有提供可靠的入口和反馈。

推荐在现有编程工作台的输入区补齐三个入口：`@` 选文件、`/` 找命令、快捷菜单查看 Skill / MCP。上下文压缩和项目初始化放进同一个命令菜单，不新增独立管理页面。

判断标准沿用 [工作台规格](SPEC-coding-agent-workbench.md)：完成同一个任务，应比打开原应用少找入口、少复制路径、少重复配置；没有公开接口且需要绕路的功能，先不做。

默认方案是保留现有 ACP / app-server / SDK，逐个补上真实能力。备选是内嵌终端或控制原应用；它们更接近完整原生指令集，但增加窗口、焦点、安装与权限问题，本计划不采用。不会为了几个命令切换全部运行架构。

## 2. 调研范围与证据边界

### 2.1 实际接入范围

以当前 `src/shared/coding-agents.ts` 的 `WORKBENCH_AGENT_IDS` 和适配器实现为准：

| 工作台入口 | 当前控制方式 | 本轮范围 |
| --- | --- | --- |
| OpenCode | `opencode acp`，stdio JSON-RPC / ACP v1 | 纳入 |
| Codex | `codex app-server --stdio` | 纳入 |
| Claude Code | Claude Agent SDK，读取既有 Claude / CC Switch 供应商配置 | 纳入 |
| Claude Desktop | 同一 Claude 适配器的独立配置入口，结合本机 Desktop Code 历史 | 纳入；仅本机 Code 场景 |
| DeepSeek Harness（DSH） | `dsh --profile acp`，官方自动化 ACP | 纳入 |
| Kimi Code | 有枚举预留，没有工作台适配器 | 不纳入实施 |
| Pi、WorkBuddy、ZCode 等 | Token 统计来源不等于编程接入 | 不扩展运行时 |

Claude Desktop 入口仍由 SDK 执行任务，并非操作 Desktop 窗口。Desktop 的 Chat / Cowork、云端会话、账户连接器以及 UI 专属功能，不能因此视为已接入。也不恢复此前暂缓的后台双向同步。

### 2.2 核验方式

- 已阅读仓库契约、preload / IPC、统一服务、五个入口对应的适配器与输入组件；未执行模型任务。
- Claude SDK 在 `package.json` 固定为 `0.3.310`；已对照本机 `sdk.d.ts`，确认命令发现、MCP 状态、Skill 和配置来源相关类型存在。
- OpenCode / Codex / DSH 使用外部程序，版本随用户安装变化。旧交付记录中 OpenCode 为 `2.1.2`、Codex 为 `0.163.0-alpha.10.2`，这只是历史探针结果，不能当成本轮重新检测结果。
- 联网核对官方文档、协议及 DSH 官方源码。OpenCode 同时有 V1 / V2 文档，本文涉及更完整 ACP 行为时明确引用 V2，不推断旧版相同。
- 本轮没有启动 Agent、创建原生会话、连接 MCP、读取凭据或测试真实命令。下文的“可接入”表示接口有依据；各安装版本仍需实施阶段验证。

## 3. 各 Agent 命令调研

### 3.1 OpenCode

原生 TUI 支持 `@` 文件搜索，以及 `/compact`（别名 `/summarize`）、`/init`、`/new`、`/sessions`、`/models`、`/undo`、`/redo`、`/export` 等。`/init` 面向 `AGENTS.md`；撤销 / 重做可能同时改变项目文件，不能作为普通菜单操作随意映射。[官方 TUI 文档](https://opencode.ai/docs/tui/)

自定义命令与 Skill 应分别处理：命令有模板和参数；Skill 由原生 `skill` 工具按需加载，不能假定每个 Skill 在每个版本都会自动生成同名斜杠命令。[自定义命令](https://opencode.ai/docs/commands/)、[Agent Skills](https://opencode.ai/docs/skills/)

V2 的 ACP 文档明确：创建 / 加载会话后推送 `available_commands_update`；命令包含当前目录命令和内置 `compact`，已公布的命令通过 `session/prompt` 调用；文件可通过 `resource_link` 提交。未识别的 `/xxx` 会作为普通提示发送。因此应先消费原生命令列表，再允许菜单执行；不能把“请求正常返回”当成命令已执行。[官方 V2 ACP](https://dev.opencode.ai/v2/docs/cli/acp/)

MCP 工具本来可以由模型调用，不必先点菜单启动。工具箱当前创建会话时传 `mcpServers: []`，这表示没有注入额外服务器，不能据此判断原生配置中没有 MCP。[MCP 文档](https://opencode.ai/docs/mcp-servers/)

**建议**：优先补 ACP 命令发现和文件引用；压缩优先用公布的 `compact`；初始化仅在对应版本确有可执行命令时使用原生命令。官方 HTTP API 另有命令、初始化、摘要和文件搜索接口，但当前项目没有使用该传输，不为首版额外启动一套 HTTP 后端。[官方 Server API](https://opencode.ai/docs/server/)

### 3.2 Codex

原生 CLI 提供 `/compact`、`/init`、`/skills`、`/mcp`、`/mention`、`/model`、`/permissions`、`/new`、`/resume`、`/review` 等；Skill 的原生显式引用方式是 `$名称`。这些是客户端操作入口，并不意味着 app-server 接受同样的聊天字符串。[官方命令参考](https://learn.chatgpt.com/docs/developer-commands)、[官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)

app-server 有明确的程序化接入点：`skills/list` 发现 Skill，`turn/start` 可携带 `skill` 输入项；`thread/compact/start` 压缩上下文，需等待后续事件；`mcpServerStatus/list` 查询 MCP。文档没有提供通用的“执行全部 CLI 斜杠命令”入口，也不能凭空构造通用 `file` 输入类型。[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)

**建议**：Tool_box 的 `/skills` 打开 Skill 选择器，选中后生成原生 `$名称` 和结构化引用；`/compact` 调专门 RPC。`/init` 作为清楚标注的“工具箱项目初始化”工作流，通过普通模型任务生成项目说明，不能宣称是直接执行 CLI `/init`。文件先使用明确路径引用；模型读取仍受原生工具权限控制。

### 3.3 Claude Code

原生常用命令包括 `/compact`、`/context`、`/clear`、`/init`、`/model`、`/permissions`、`/mcp`、`/resume`、`/plan`，以及用户 / 项目 / 插件 Skill。这里 `/init` 默认目标是 **`CLAUDE.md`**，与 OpenCode / Codex 的默认文件不同。[官方命令表](https://code.claude.com/docs/en/commands)

SDK 可以发现并派发无终端依赖的命令；初始化信息有 `slash_commands`，普通提示可执行会话可用的 `/<name>`，包含 `/compact`。不能使用的终端指令应过滤；未知命令在部分新版会回落到普通模型对话。历史压缩有 `compact_boundary` 等原生事件，不能仅靠助手说“压缩好了”判断。[官方 SDK 命令与 Skill](https://code.claude.com/docs/en/agent-sdk/skills)

本机 SDK 类型还确认：`supportedCommands()` 返回 Skill 元数据，不应把它单独当作所有内置命令的完整清单；`mcpServerStatus()` 返回 MCP 状态。Skill 加载受 `settingSources` 管理，而当前适配器明确设为 `[]`，没有完整继承原生文件配置。这是目前本机 Skill / MCP / 项目说明能力不足的直接原因之一。

MCP 的 **Prompt** 可以显示为斜杠命令；**Tool** 是模型使用的工具，二者不是一回事。命令名称应取实际发现结果，不硬编码历史前缀。[官方 MCP Prompt 说明](https://code.claude.com/docs/en/mcp)、[SDK MCP 接入](https://code.claude.com/docs/en/agent-sdk/mcp)

**建议**：先明确配置来源与项目信任策略，再通过 SDK 初始化和发现结果提供菜单。`/compact` 续接原 session ID；`/init` 仅在该会话确实支持时派发，并明示创建的是 `CLAUDE.md`。需要通用 `AGENTS.md` 时提供独立的工具箱工作流，不偷偷替换原生命令含义。

### 3.4 Claude Desktop Code

Desktop Code 原生提供 Skill / 命令选择，也能连接 MCP；官方说明本机会话可以加载个人及项目 Skill。[Desktop 官方文档](https://code.claude.com/docs/en/desktop)

**工具箱的接入边界**：两个 Claude 入口虽然共用 SDK，但供应商 / 环境配置隔离，Desktop Code 历史读取也有独立校验。新功能应复用代码、分别发现当前会话能力；不能把 Claude Code 的列表直接套给 Desktop。账户侧同步 Skill、连接器和 Desktop UI 交互未在 SDK 会话中发现时，不显示成可用。

继续保留原会话归属和空闲检查；不向正由 Desktop 执行的会话发压缩、初始化或 Skill 任务，不写 Desktop 私有登记文件。

### 3.5 DeepSeek Harness

DSH 交互式 UI 有独立的人类命令注册系统；官方包明确说明 ACP 自动化不提供这一命令界面。交互式 `/compact` 有专门插件，不能把相同文本发进 ACP 就认为已触发压缩。[官方命令注册包](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/interaction/commands/README.md)、[官方压缩命令包](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/command-compact/README.md)

Skill 是另一条能力：官方 Skill 包支持模型通过 `skill` 加载，也支持用户 `/name` 手势，但需要所选组合实际挂载对应插件。存在 Skill 包不代表当前 ACP 已提供可枚举的 Skill 列表。[官方 Skill 包](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/skill/tool-skill/README.md)

官方 ACP 支持文本、资源链接和 MCP 挂载；明确不提供 commands、客户端文件系统、历史回放等界面能力，并且 MCP 当前只消费 tools，不消费 prompts / resources。[官方 ACP 契约](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/acp/acp/README.md)、[官方 ACP 源码](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/acp/acp/src/index.ts)

**建议**：首版支持经过验证的文件路径引用、现有模型 / 会话操作；不提供假的原生 `/compact`、`/init` 或完整命令列表。不新增社区 ACP 替代程序。Skill 若无法从该组合可靠发现和确认执行，显示“当前接入未提供”，不扫描目录后伪装成原生可用。

## 4. 能力矩阵与产品取舍

下表描述推荐接入方式，**不是已经实现的功能表**。“条件支持”必须由实际版本 / 会话能力确认。

| 能力 | OpenCode | Codex | Claude Code | Claude Desktop Code | DSH 官方 ACP |
| --- | --- | --- | --- | --- | --- |
| `@` 搜索当前项目文件 | 工具箱搜索，ACP 链接 | 工具箱搜索，明确路径 | 工具箱搜索，明确路径 | 同左，单独校验目录 | 工具箱搜索，已验证的资源链接 / 路径 |
| 原生命令发现 | ACP 推送 | 没有通用 CLI 命令枚举；按公开 RPC 建立受控目录 | SDK 初始化列表 + Skill 元数据 | 独立发现，不照搬另一入口 | 官方未提供 |
| 手动压缩 | 公布 `compact` 时支持 | 专门 RPC | 公布 `/compact` 时支持 | SDK 当前会话支持时可用 | 本接入暂不支持 |
| 显式 Skill | 以原生命令发现为准；缺失时不伪造调用 | 列举 + 结构化引用 | SDK 发现 + 命令派发 | 同左，取本入口实际列表 | 组合相关；首版不承诺列表 |
| MCP 状态 / 工具列表 | ACP 没有通用状态查询，不能承诺面板完整 | 有状态接口 | SDK 有状态接口 | SDK 所见范围 | ACP 未提供统一查询 |
| MCP Prompt 作为命令 | 仅采用原生公布结果 | 不伪造通用 Prompt 命令 | 发现后显示 | 发现后显示 | 官方未消费 |
| 项目初始化 | 原生支持则用；否则工具箱工作流 | 工具箱工作流生成 `AGENTS.md` | 原生 `/init` 指向 `CLAUDE.md` | 本入口支持时同左 | 工具箱普通模型工作流，可选 |
| 新对话 / 历史 / 模型 / 权限 | 复用现有能力 | 复用现有能力 | 复用现有能力 | 复用现有能力 | 只展示原生提供的选项 |

必须区分三种执行类型，并在命令描述中写清楚：

1. **本地界面操作**：打开模型选择、历史列表、新对话；不发送模型任务。
2. **原生操作 / 命令**：调用协议接口或明确公布的命令，有真实运行结果。
3. **工具箱工作流**：把明确任务提交给 Agent，例如生成项目说明；消耗模型用量，也可能请求文件写入，不冒充原生命令。

## 5. 推荐交互

### 5.1 `@` 定位文件

1. 在输入框键入 `@`，或点输入区的文件入口，出现当前项目文件候选。
2. 输入名称 / 路径片段，候选显示文件名和相对路径；方向键选择，Enter / Tab 插入，Esc 关闭候选。
3. 选中的引用在输入框旁显示可移除的小标签；正文保留清楚的路径，发送前可核对。
4. 用户照常输入任务并发送。支持结构化链接的运行时提交链接；其他运行时提交明确路径，并由 Agent 按权限读取。界面分别标注“文件上下文”和“路径引用”，不假装都已上传全文。

边界要求：

- 只搜索当前已选项目，文件名优先、相对路径次之；默认不遍历 `.git`、`node_modules`、构建目录和明显的密钥文件。
- 搜索只返回元数据，不提前把文件全文读进 renderer。首版不索引磁盘、不做全文搜索、不选整目录、不加文件上传管理器。
- 主进程校验绝对目录、规范路径及符号链接 / junction 的真实落点；越出项目根的路径拒绝，不能只用字符串前缀判断归属。敏感文件默认不进入候选；首版不提供“显示全部敏感文件”。
- 文件已删、改名、权限不足或链接落点变化时，在提交前说明该引用失效并保留草稿。文件大小和类型限制按运行时接入确定；不静默截断内容。
- 搜索采用短防抖、取消 / 序号隔离、最多 50 个候选和单次扫描上限；大仓库提示继续输入，不能卡住输入框。
- 普通邮件地址、代码块或正文中的 `@` 不触发解析；只处理明确的输入触发位置和用户选中的引用，不把所有 `@文本` 自动当文件。

### 5.2 `/` 命令菜单

沿用现有输入框，不添加常驻的大工具栏。消息开头输入 `/` 打开一个可搜索菜单，按中文用途与原生命令名都能找到。

| 输入 / 菜单项 | 行为 |
| --- | --- |
| `/compact` · 压缩上下文 | 当前 Agent 原生可用时执行；不可用则解释本接入限制 |
| `/init` · 初始化项目说明 | 显示实际文件和执行类型；Claude 原生为 `CLAUDE.md` |
| `/skills` · 选择 Skill | 打开当前 Agent 的可用 Skill 列表，选中后准备引用和任务 |
| `/mcp` · MCP 工具 | 展示能可靠查询的服务 / 工具状态和可用 Prompt |
| `/new` · 新对话 | 复用现有新对话草稿流程，保留原会话 |
| `/history` · 历史会话 | 复用现有历史入口，不另建列表 |
| `/model` · 模型 | 聚焦现有模型选择；不发送字符串让模型改设置 |
| `/permissions` · 操作权限 | 打开已有原生选项；没有的选项不补造 |
| 原生自定义命令 | 原生命令名、简介、参数提示；发现且适配过才可执行 |

`/history` 等明确标为工具箱快捷入口；原生同名命令优先展示真实含义，冲突时本地入口用中文菜单操作，不覆盖原生名字。Codex 选 Skill 后显示原生 `$名称`，不强迫用户记两套命令。

- 菜单打开时，Enter 只选候选，不顺便发送；填完参数或任务后再按 Enter 执行。纯本地操作选中即打开相应控件。
- 候选关闭后保留现有 Enter 发送、Shift + Enter 换行；中文输入法组合期间不执行；Esc 先关菜单，不把工具箱窗口一起关掉。
- 已知但不支持的命令不能降级成收费聊天；未知 `/xxx` 默认提示“未识别为命令”，提供明确的“作为普通文字发送”入口，正文 / 代码中的斜杠不拦截。
- 有必填参数才显示参数提示，不为每条命令另开确认弹窗。命令展示用途与是否调用模型；普通文件选择和查询不重复询问。
- 未连接时仍可使用本地入口；原生列表展示“连接后读取”。用户主动展开原生能力时可连接，但不创建空会话或发探测提示。协议只有建会话后才有列表时，优先使用已有会话，否则显示首次发送后可用。

### 5.3 Skill 与 MCP

Skill 选择后填入当前草稿，用户补充任务再发送；不复制一大段 `SKILL.md` 到聊天，也不由 Tool_box 自己执行 Skill 脚本。Skill 名、描述、来源按原生数据收敛，禁止将未知条目“补全”为已加载。

MCP 首版以“知道有哪些、能否用、怎么让 Agent 用”为主：

- 有接口的 Agent 显示服务名、状态、工具名 / 简介；字段做白名单输出，不透传服务器配置、认证头、环境变量或原始错误。
- 有 MCP Prompt 的，作为原生命令候选；只有 Tool 的，提供“让 Agent 使用此工具”的草稿引用，明确这是任务意图，实际调用以工具事件为准。
- 没有状态接口时显示“当前接入无法查询 MCP 状态”，不要显示成“未配置 MCP”；Agent 已经可以用的原生工具继续由它使用。
- 不做第二套 MCP 安装器、OAuth 客户端、任意参数直接调用面板，不把 Tool_box 内部密码箱 / 数据库工具自动开放给外部 Agent。
- 后续如果需要从本地配置导入 MCP，另行确定可信来源、进程启动与凭据边界；首版不把任意配置文件读入后直接启动其中的命令。

### 5.4 压缩上下文

压缩针对当前会话，不新建会话、不生成交接文档、不清空界面消息，也不改写原生日志。

- 只有已建立且空闲、可续接的会话可执行；运行中提示等待或使用现有停止按钮，不排队暗中执行。
- 纳入现有顶层运行互斥、停止、审批、断连和事件归属机制；压缩请求受理不等于完成。
- Codex 等待原生压缩 / turn 终态；Claude 消费原生压缩事件和结果；OpenCode 按该版本提供的终态展示，缺少统计时不编造“节省 Token”。
- 超时 / 断连按结果未知处理，保留身份，不自动再压一次；不能回退成“请总结上下文”并把普通回复当原生压缩。
- 当前适配器还有本地显示上限，压缩后并不会自动减少 `messages.length` 或界面字符数。实施时要允许控制操作在显示上限下执行；保留已有截断说明，不能用压缩来解除无限制 UI 存储或删除历史。

### 5.5 项目初始化

菜单直接写明结果文件：OpenCode / Codex 的 `AGENTS.md`，Claude 原生的 `CLAUDE.md`。另提供“生成通用 AGENTS.md”工具箱工作流，按需使用，不把两个文件自动互相覆盖。

- 已存在目标文件时，默认提供查看 / 让 Agent 提出更新建议；用户明确选择更新后才能进入修改任务，不自动覆盖旧规则。
- 新文件走当前原生模式和审批；计划 / 只读模式只生成建议内容，并提示切换已有写入模式才能保存，不替用户提权。
- 初始化读取范围限当前项目，遵守项目已有协作规则；忽略依赖目录、构建产物与敏感配置，不把密钥写入说明。
- 工具箱工作流明确是一条普通 Agent 任务；任务结果与实际文件检查分别显示，模型声称“已创建”不能单独作为文件存在的依据。无公开读取接口时提示用户到项目核对，不伪造检查结果。
- 原生 `/init` 若依赖工作台尚未实现的问答，标记暂不可用，改由明确的工具箱工作流入口提供建议；不使用布尔审批代替用户问答。

## 6. 配置与安全边界

Claude 的 `settingSources: []` 不能简单改成全量加载就算完成：用户 / 项目配置还可能带入 hooks、插件、MCP 子进程、环境变量与权限规则。

推荐保留隔离默认行为，在连接设置增加一次性的“使用本机 Agent 扩展配置”选择，按 Agent + 规范项目目录记录。实施前需列明官方加载机制的实际范围和副作用，再确认该业务流程 / 配置变更；本计划不替用户作出授权。

- 开启后才按已选来源通过官方机制发现扩展；不读取另一 Agent 的配置，不把 Claude Code 的 CC Switch 路由套给 Desktop。
- 不以启用 Skill 为理由设置 `bypassPermissions`、新增通配允许规则或覆盖原生拒绝项；原生已批准的操作不一定经过 Tool_box 的 `canUseTool`，文案不能承诺“所有操作逐次询问”。
- 若官方机制不能在保留必要边界的情况下加载指定范围，应继续隔离并说明限制，不能自行解析并执行 hooks 来模拟。
- 能力列表按运行时 + 连接 + 规范目录 + 会话缓存；切项目、重连、配置变化立即失效，迟到事件不能污染新会话。
- 路径、Skill、命令、MCP 元数据都按不可信输入校验；限制长度、数量和参数，命令名 / 引用必须由当前发现记录解析。
- renderer 不获得原生 RPC、任意 shell、任意文件读取、MCP 认证等通用权限。
- 元数据读取不发模型任务，但原生初始化可能启动已配置的 MCP / hooks，不能把所有“查询”描述为完全无副作用；扩展未授权时不主动启动它们。

### 7.3 拟议 IPC 范围（待确认）

建议最小接口按职责划分，最终名称和参数在实施前规格化：

- `coding-agent:capabilities:read`：读取当前能力目录 / Skill 元数据 / 可公开的 MCP 状态；普通缓存读取不创建会话，不发送任务。主动刷新另带明确意图。
- `coding-agent:files:search`：在已选项目范围按路径片段查询，返回有限候选和受归属约束的引用；不返回文件全文。
- `coding-agent:command:execute`：执行当前公布且已适配的命令或本地登记工作流，通过不透明引用绑定会话，不接收任意 RPC 名或 shell。
- 现有 `send` 增加可选的文件 / Skill / 工具意图引用；旧 `{ content }` 调用保持兼容。引用种类用判别类型区分，主进程再次校验并转换成原生输入。
- 既有事件增量增加能力变化 / 操作状态；沿用 runtimeId、connectionId、sessionRef、runId、revision 归属。不要为每种命令开一套事件总线。

本地的新对话、历史、模型选择继续调用现有接口，不经过新的执行 IPC。压缩和其他会触发原生执行的命令才占用运行槽；停止须能命中准备期、受理后和运行中的相应操作。

**存储范围**：首版不改 SQLite 表、schema、加密算法或主密钥。草稿保留可读路径 / Skill 标记；结构化临时引用不直接当作重启后仍有效。恢复草稿时标成路径 / 文本引用，需重新解析后才能显示为已绑定引用；不能把旧连接的 token 或能力列表原样复活。如果要求标签完整跨重启恢复，再单独设计加密草稿载荷的版本兼容，不借本轮暗改格式。

**授权范围**：原调研阶段仅编写计划；用户后续明确要求“按照你的计划实现”，本轮按上述范围扩展接口与发送流程，并为本机扩展保留运行期主动开启选择。不涉及新增依赖、数据库结构或加密链路变更。

## 9. 验收与风险

### 9.1 人工验收场景

| 场景 | 预期 |
| --- | --- |
| 五个入口分别输入 `/` | 只出现其真实能力；DSH 不出现假的原生压缩 |
| Windows 中文、空格、同名前缀目录和 junction | 正确引用；越界拒绝；不能发往错误项目 |
| 文件搜索 / 菜单打开时输入中文并按 Enter | 不误选、不误发，Esc 只关最上层候选 |
| 连续选择多个文件后编辑正文 / 移除引用 | 文本、标签和最终提交内容一致，无残留引用 |
| 新对话首次发送文件 / Skill 任务 | 沿用一次点击准备流程，不额外手动建会话、不双发 |
| 已有会话压缩，原生请求先返回受理 | 仍显示处理中；收到终态才结算 |
| 显示上限、停止、断网、切项目后收到旧事件 | 不卡死、不自动重试、不串项目、不假报成功 |
| 已有 AGENTS.md / CLAUDE.md 后点初始化 | 先查看或提出建议，未选更新不覆盖 |
| Claude Code 使用 CC Switch，同时切 Desktop 入口 | 模型 / 配置 / 扩展来源不互串 |
| MCP pending / failed / needs-auth | 状态准确，错误脱敏；缺少查询能力不等于无 MCP |
| 重启恢复含引用的草稿 | 文字保留；过期引用重新解析，不冒充已绑定 |
| 1280×820，深色 / 浅色主题 | 候选对齐输入区，不裁切 / 不溢出，焦点清楚 |

### 9.2 验证纪律

实施时优先准备合成协议用例：建会话响应前命令推送、列表替换、失效引用、未知命令、原生受理与完成分离、压缩取消、配置隔离、路径越界。新增测试也须有实际风险覆盖，不写镜像实现的机械断言。

是否执行编译 / 测试，严格按当时 `AGENTS.md` 门槛：仅本次改动同时超过 500 行有效代码且超过 10 个文件时，才允许按顺序执行 `npm run typecheck` → `npm run lint -- --ignore-pattern "mobile/**"` → `npm run test -- --exclude "mobile/**"`；未达到时只做静态审查，由用户手动验证，不启动开发服务或构建。模型 / MCP 真机验收另按实际任务授权进行，不用收费请求代替只读发现。

### 9.3 主要风险与控制

- **版本差异**：官方当前文档不等于本机版本，能力发现 + 适配白名单共同决定可执行项，不靠品牌硬编码全开。
- **配置副作用**：加载本地配置可能运行 hooks / MCP 或改变原生规则；在明确来源和用户选择前保留隔离。
- **文件隐私与路径穿越**：限定项目、排除敏感项、真实路径校验、发送时再核对；不后台上传项目。
- **命令伪成功**：未知 `/xxx` 可能退化成普通对话；必须验证命令身份，按原生事件 / 结果结算，缺少可观测性就明确限制。
- **压缩误判**：原生上下文、本地显示缓存和 Token 历史统计是三个不同对象，不用 UI 删消息模拟压缩，也不把摘要长度当节省量。
- **兼容成本**：旧 preload、旧原生版本或扩展缺失时，普通聊天继续可用，新能力明确降级；不自动升级用户程序或依赖。

原调研轮仅新增计划；后续实施的实际差异与限制统一记录在交付记录中。未改依赖、数据库结构、加密算法、主密钥位置或手机代码，未提交 Git。
