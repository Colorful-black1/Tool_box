# 编程 Agent 易用性优化方案

日期：2026-10-23

状态：用户已授权实施，核心流程已落地；实现范围与最新验证见 [交付记录](coding-agent-verification.md) 和 [任务清单](../tasks/todo.md)。下文保留方案目标与验收标准，不把设计目标当作真实模型验证结论。

## 1. 目标与判断标准

让使用者只打开 Tool_box，就能方便地在 OpenCode / Codex 中处理本机项目，并在需要时把已有内容交给另一 Agent。

目标用户是自己操作编程 Agent 的桌面使用者。最常见的事情只有三件：开始对话、继续之前的会话、请另一 Agent 接着处理或审查。

采用一个明确标准：同一任务，如果在 Tool_box 中比直接使用原应用更绕，优先减少步骤；减少后仍无独立价值，就取消该功能。

这里的方便包括少点击、少填写、少重复说明，也包括始终知道请求发给谁、在哪个项目执行、当前允许做什么。不能以隐藏目标或扩大权限换取步骤减少。

### 当前依据

- 用户已实测：不打开 OpenCode Desktop，当前工具箱也可以连接并对话。这是当前环境的使用证据，不推断其他版本或所有后台服务的状态。
- 当前 OpenCode / Codex 适配器都由 Tool_box 启动原生后台进程。Codex 关闭桌面应用后的完整对话仍需单独实机确认。
- 当前交接默认抽取最后一条用户消息和助手回复，diff 由用户填写，目标会话需要离开面板准备，最后只填入草稿。
- 用户可以直接让来源 Agent 生成交接文档，再让目标 Agent 阅读。新方案应减少这个流程的机械操作。

### 范围与默认选择

本方案面向 Windows 桌面端，沿用现有工作台、原生运行时、会话存储和星轨设计系统。手机端保持暂停维护。

默认选择：精简统一工作台，取消复杂交接表单，增加消息直接转用，以及可选的来源 Agent 交接说明生成。

备选选择：只精简工作台，跨 Agent 内容全部由用户复制。实现成本最低，但仍要重复选择目标、粘贴和核对项目。若后续验证消息转用没有比复制更省事，应采用此备选，继续删减。

本文不启动自动团队、任务数据库、并行工作区、额外运行时或其他后端。旧规划已作为历史基线保留，相关规格与任务清单已同步当前流程。

## 2. 保留、调整与取消

| 功能 | 决策 | 使用者获得的收益 |
| --- | --- | --- |
| OpenCode / Codex 统一入口 | 保留，作为主线 | 一个窗口完成实际对话与操作 |
| 项目、模型、原生权限选择 | 保留，减少重复设置 | 知道在哪里执行、使用什么能力 |
| 流式回复、停止、原生审批 | 保留 | 能查看过程并随时介入 |
| 原生历史与会话恢复 | 保留，合并到一个会话列表 | 不必先点读取，再到另一下拉框选择 |
| Prompt / 工具结果填入输入框 | 保留 | 复用工具箱已有内容，不重复复制 |
| 当前手动交接表单 | 取消 | 不再手填上下文、diff、版本或准备目标会话 |
| 交接角色预设与模板快照界面 | 取消 | 少一套配置；普通 Prompt 模板库继续使用 |
| 消息版本号、交接来源按钮和引用队列 | 退出用户主流程 | 不再维护一套容易失效的交接导航 |
| 消息复制与“用于另一 Agent” | 提供轻量操作 | 从选定内容直接到目标输入框 |
| 来源 Agent 生成交接说明 | 可选快捷操作 | 用来源会话已有上下文总结，避免用户重写 |
| 原生工具 / 子任务详情 | 折叠到执行详情 | 需要时可查，不挤占对话与输入区 |
| 程序路径、版本、重新检测、断开、打开原应用 | 放入连接设置或更多菜单 | 正常工作时不面对连接调试面板 |
| Kimi / Claude 待接入占位项 | 从日常选择器移出 | 日常只看到已实现的 Agent；不删除既有类型 |
| 自动调度、自动回传、团队角色、交接文档库 | 本方案不建设 | 不为偶尔切换 Agent 增加管理成本 |

取消交接专用角色不影响普通 Prompt 模板的查看、编辑和使用。已有 `agentRoles` 配置不自动清空或改写，不新增配置迁移流程。

## 3. 开始对话：点击发送时完成准备

### 第一次使用

1. 选择 OpenCode 或 Codex。
2. 选择项目，输入任务。
3. 点击“开始对话”。Tool_box 顺序完成连接、新建原生会话、发送这一次任务。

按钮旁明确提示“首次发送会新建会话”；已有会话时按钮使用“发送”。首次准备前显示原生默认模型与安全模式说明，会话建立后显示实际模型与原生权限；程序路径仅在未检测到程序或主动展开设置时显示。

正常路径不要求用户依次点击“连接”“新建会话”“发送”。连接或模型选择失败时停在相应步骤，保留任务草稿，提供就地修复入口。

### 后续使用

- 沿用当前项目和仍然有效的连接，普通消息直接发送。
- 点击“新对话”进入空白输入状态，实际原生会话延迟到首次发送时创建，避免留下空会话。
- 进入页面和切换 Agent 不创建会话、不发送任务；不通过后台主动启动两个运行时实现所谓快速切换。
- 第一版不新增最近项目管理器、跨项目标签系统或会话收藏功能。

这里调整的是“发送”所包含的显式操作：用户点击一次，即授权为所选 Agent / 项目准备会话并发送当前内容。不能把该意图扩展成自动恢复任意历史、自动重发或切换其他 Agent。

### 项目与权限

当前项目在 OpenCode / Codex 之间沿用，同项目首次使用另一 Agent 时无需再次打开目录选择器。

若目标 Agent 已连接其他项目，转用内容进入来源项目的新对话草稿，显示将要使用的目录；不覆盖另一项目的原草稿，不把内容塞进旧项目会话。实际发送时再准备对应连接。

需要恢复其他项目的历史时，由用户明确选择该项目。每个原生会话保持自己的 Agent 和目录归属，不因顶部切换而改写。

权限沿用目标运行时自身的已确认设置或安全默认值，不继承来源 Agent 的写权限，不为实现一步发送自动升级权限。模型缺失时要求选择，不能静默换模型。恢复历史时保留原生会话的实际模式，不静默降级或扩大权限。

## 4. 继续历史：列表里直接打开

会话侧栏只保留“新对话”和当前项目会话列表。打开历史区域时，已连接则读取原生列表；未连接则由这次明确的打开操作连接并读取。列表项点击后恢复该会话，不再要求先点“读取历史”，再到下拉框选择。

- 读取历史不创建、不恢复、不发送；点击具体条目才恢复。
- 已打开会话与原生历史按原生身份去重，不能只凭标题去重。
- 历史多时在列表内搜索，不再新建一层管理页面。
- 刷新放在列表标题处；刷新失败保留已显示内容并提供重试。
- 恢复失败保留原因与原草稿，不转成新建，不替用户发送。
- 重启后按原生记录恢复；本方案不新增 Tool_box 会话正文数据库，也不承诺原应用实时显示相同会话。

## 5. 跨 Agent：从消息直接转用

### 常用路径：已有内容，直接交给 Codex

以 OpenCode 转给 Codex 为例：

1. 在选定的助手回复下点击“用于 Codex”。
2. Tool_box 切到同项目的 Codex 新对话草稿，显示来源和正文；用户可在普通输入框补充要求。
3. 用户点击“开始对话”或“发送”，才准备目标连接 / 会话并执行。

“用于 Codex”只准备目标草稿，不请求摘要、不调用目标模型、不要求预先连接或建会话。正文沿用用户明确选中的回复，不再猜测哪一问一答是完整任务。

默认进入新对话草稿，避免把材料混入任意旧会话。若用户确实想继续某条 Codex 历史，可在目标草稿的一处“改用已有会话”入口中选择；不把会话选择设为必填项。

来源名称与项目作为简短标记；接手要求默认说明“先核对当前项目状态，再根据以下内容继续处理”。正文可以编辑，不能把源回复当成已验证事实，也不自动授予写入或 Git 操作权限。

只有两个可用 Agent 时，消息操作直接显示另一 Agent 的名称。默认只露出“复制”“用于 Codex / OpenCode”，其他低频动作进入更多菜单，键盘聚焦时同样可用。

### 可选路径：需要完整上下文，先生成交接说明

会话更多菜单提供“生成交接说明”。这个动作向当前来源会话发送一次明确的总结请求，使用来源 Agent 自己掌握的会话上下文，不调用另一个摘要模型，也不抓取全历史重新拼接。

请求的默认要求：

> 请依据本会话已有信息，为接手任务的另一个编程 Agent 输出一份简洁的交接说明。包含任务目标、关键约束、已完成工作与涉及文件、重要决定、验证结果、未完成事项及建议下一步。区分事实与推测；没有执行的验证写明“未执行”，无法确认的内容写明“待核对”。仅输出说明，不为总结执行命令、调用工具或修改文件，不包含密钥及其他敏感内容。

生成结果作为普通助手回复展示，完成后仍使用“用于 Codex”。取消当前生成沿用现有停止能力。来源任务还在执行时不排队、不自动停止，提示等待或由用户停止后再生成。

如果输入框已有草稿，生成说明不能替换或清空该草稿；保留用户正在写的内容。请求通过现有发送链路处理，仍受原生权限和审批控制；总结提示词本身不被当成安全边界。

已有合适内容时直接转用即可。生成说明会增加一次模型请求和等待，应只在用户主动点击时执行。若这个快捷项实测不比手写一句“给我交接说明”省事，可移除快捷项，保留消息转用。

### 文档文件按需使用

第一版默认转用回复文本，不自动往项目写 `handoff.md`，不要求用户起文件名，也不建设附件读取器。

用户已有交接文档时，可照常把路径发给目标 Agent，由目标按原生权限读取。用户也可以直接要求来源 Agent 写文档。工具箱不拦截这种方式，不把普通文件操作包装成另一套管理功能。

### 草稿保护

- 目标已有未发送内容时，默认保留并提示；仅在确实会覆盖时询问“替换草稿 / 保留原稿”。
- 无效连接、目标改变、取消和失败都不能吞掉来源内容或目标原草稿。
- 正在流式生成的回复不提供转用，避免复制半份结果；已结束或明确停止的内容可以复制或转用。
- 超过发送上限时明确提示缩短内容或改用文档路径，不静默截断、不自动发多轮。
- 待转用材料仅在内存中保留，不进入偏好配置。离开页面可在本次应用中继续，退出应用不承诺恢复；普通复制始终可用。

## 6. 主界面只呈现当前操作需要的信息

沿用当前星轨主题、Dropdown、按钮和布局，不重做视觉系统。

- 顶部：当前项目、OpenCode / Codex 选择、简短状态、更多菜单。只有两个 Agent 时优先使用直接可点的切换按钮，减少展开选择器。
- 左侧：新对话、当前项目历史与必要的搜索；窄窗压缩列表宽度，沿用主导航折叠，不额外增加会话栏开关。
- 对话上方：当前模型与权限 / 模式。思考强度等选项按原生能力展示，较低频的放更多设置。
- 对话区：内容优先，消息旁可复制或转用；普通成功不挂常驻大横幅。
- 底部：输入框和当前主要动作，执行中显示停止；错误显示在发生的位置并提供具体下一步。
- 执行详情：工具和原生子任务合并为一个折叠入口；有待审批时仍立即显示审批卡，不能为了清爽隐藏。
- 版本、程序路径、协议说明、Desktop 互见边界放在设置或帮助。登录失效、错误项目等会影响决策的信息仍须及时显示。

文案使用“项目”“会话”“发送给 Codex”等直接表达，连接代次、内部消息版本、profile 等实现名词不进入正常任务流程。

## 7. 可靠性决定能否省事

将连接、新建、发送合成一个用户动作后，必须处理重复点击、取消与结果未知，否则省下的点击会变成重复任务。

| 状态 | 期望行为 |
| --- | --- |
| 程序未找到或认证未完成 | 保留输入，在当前界面给出选程序或完成原生登录的入口 |
| 点击发送后切换 Agent / 项目 | 本次操作固定使用点击时的 Agent、目录、权限和正文，迟到结果不覆盖新草稿 |
| 连接或新建中重复点击 | 单次准备过程只接收一个发送意图；明确的失败重试复用已知有效会话 |
| 已新建但发送尚未开始时取消 | 保留正文，可复用已创建会话；不为撤销操作自动删除原生记录 |
| 请求已发出但连接中断 | 标记结果未知，不自动重发；引导核对原生记录 |
| 当前有 Tool_box 任务执行中 | 保留全局串行，可浏览、准备草稿，不能悄悄排队发送 |
| 运行任务不在当前页面 | 提供“查看运行任务”和“停止”入口，停止命中实际运行身份 |
| 用户在原生应用另开任务 | 不宣称 Tool_box 能管控所有外部执行；不以本地空闲状态保证文件无并发修改 |

不自动安装运行时、不复制认证文件、不自动提交、建分支、stash 或重置代码。本方案不新增默认文件扫描、后台 Git 检查或收费请求。

## 8. 与当前实现的对应关系及影响

本节是落地范围提示，不是已完成记录。实施前仍需按仓库要求核对完整调用链。

| 区域 | 拟调整内容 | 影响与边界 |
| --- | --- | --- |
| `components/opencode/opencode-workbench.tsx` | 精简主栏，取消旧交接弹层入口，统一发送意图 | 改变首次发送流程，不能与旧入口重复触发 |
| `opencode-connection.tsx` / `opencode-sessions.tsx` | 折叠连接细节，统一历史列表，延迟新建 | 保留可恢复的错误与原生身份 |
| `opencode-messages.tsx` | 复制、用于另一 Agent 的消息操作 | 转用明确消息，不复制隐含全历史 |
| `opencode-activity.tsx` | 折叠执行详情，保持审批即时可见 | 不变更原生审批与停止语义 |
| `stores/coding-agent-store.ts` | 单次连接 / 建会话 / 发送流程、跨页面待转用草稿 | 按 Agent / 项目 / 会话隔离，保留连接与版本检查 |
| `components/opencode/agent-handoff.tsx` 等旧交接实现 | 方案实施时移除相关专用流程及失去调用的代码 | 对照引用逐项清理；普通 Prompt 与既有用户配置保留 |
| `services/coding-agents/*` / OpenCode 服务 | 仅按实际阻碍补充适配 | 特别核对历史恢复时模式处理，保留全局互斥、所有权与取消 |
| 桌面验证与使用文档 | 更新流程、场景与真实验证边界 | 不能继续把“必须手工预建目标会话”作为新方案验收要求 |

连接、新建、恢复、发送优先复用现有桥接方法顺序调用，不为一个快捷按钮新增复合 IPC。历史模式若需调整，在原有适配方法内保持主进程校验。

预计无需第三方依赖、SQLite schema 或加解密变更，不涉及手机。是否需要共享类型或 IPC 调整只能在实施检查后确定；若必要，先单独说明具体影响并按仓库授权规则处理。

实施已移除旧交接专用代码，未删除用户数据或旧配置。工作区中已有其他任务改动，本轮通过开工前快照单独统计差异。

## 9. 建议落地顺序与退出条件

| 顺序 | 可独立评审的交付 | 完成判据 |
| --- | --- | --- |
| 1 | 工作台入口精简与首次发送准备 | 正常任务不用先连接再新建，目标、项目与权限仍明确 |
| 2 | 历史列表与运行任务定位 | 从会话列表直接继续，切换后可定位并停止实际任务 |
| 3 | 消息复制、跨 Agent 草稿转用，替换旧交接表单 | 不预建目标、不填写角色和 diff，明确消息可直接进入目标草稿 |
| 4 | 可选的来源会话交接说明快捷项 | 一次主动请求生成普通回复，失败和停止均不丢用户草稿 |
| 5 | 清理旧交接专用代码、同步规格与验收记录 | 没有双入口、失效按钮或两套相互矛盾的说明 |

每个交付再按关联调用链拆成小改动，不一次性重写工作台。第 4 项不是第 1–3 项交付前置；收益不足就取消，不为完善“交接体系”继续加功能。

仅隐藏入口而永久保留整套无人使用的交接状态不算完成清理。实际清理应在功能替代后核对引用，不自动删除历史文档、用户文件或配置数据。

## 10. 手动验收与便利性指标

点击数按用户动作统计，不包含输入正文、首次文件选择器内部导航和真实权限审批。目标是设计上限，尚无本轮实机测量结果，不把网络、模型等待算成界面性能收益。

| 场景 | 目标 |
| --- | --- |
| 程序与项目已记住、无当前会话 | 输入后点击一次开始对话，完成连接 / 新建 / 发送 |
| 已有效连接并选择会话 | 点击一次发送，不增加确认层 |
| 同项目切到另一 Agent | 直接切换，无重复目录选择；输入后一次发送 |
| 已打开会话列表，历史读取完成 | 点击一条记录即可恢复，无额外读取按钮或下拉层 |
| OpenCode 完整回复转给可用 Codex | 点击“用于 Codex”，检查后点击发送，正常路径共两次点击 |
| 需要完整交接说明 | 来源会话一次主动生成，完成后按上一条转用；不填写交接表单 |

必须手动核对的场景：

1. OpenCode Desktop 未打开时，从工具箱完成新对话、流式回复和停止；已有用户对话证据，优化后再检查回归。
2. Codex Desktop 未打开时单独验证同样路径，不以后台进程启动成功代替真实对话成功。
3. 同项目切换 Agent，输入框和权限可见，来源内容不会进入错误项目；目标已有其他项目连接时也一样。
4. 当前 / 目标均有未发送草稿时转用，拒绝覆盖、取消、断连均保留内容。
5. 生成交接说明时保留原草稿；不触发第二个运行时请求，不主动执行额外命令或写交接文件。
6. 重复点击、连接中切换、发送中断等情况不产生两次任务；未知结果不自动补发。
7. 历史恢复失败不新建；读取与刷新不重复建会话；原生模式按实际状态显示。
8. 切到其他页面后可继续待转用草稿；原生审批可见，运行任务能定位和停止。
9. 三主题、1280×820 与 1024×680 下输入和主要按钮可用；键盘可完成切换、转用和发送，菜单不被裁切。
10. 与“两个原应用 + 手动复制”完成同一小任务作比较，记录点击、填写和来回切换次数。若新流程没有减少操作，继续收缩，不因已实现而保留。

方案撰写阶段仅做静态阅读与文档检查；授权实施后的实际验证见 [交付记录](coding-agent-verification.md)，与下列仓库门槛一致。

后续实现必须只统计该任务实际变更；仅当有效代码改动超过 500 行且改动文件超过 10 个时，才允许按顺序执行：

```text
npm run typecheck
npm run lint -- --ignore-pattern "mobile/**"
npm run test -- --exclude "mobile/**"
```

其他构建或运行验收同样受仓库门槛限制，不运行 `npm run rebuild`，不把既有未提交改动计入门槛。未达到门槛时由用户手动验证，并使用规定说明：“本次修改影响范围有限，未执行编译验证。”

## 11. 交付取舍

第一版做到：一个入口直接开始对话、一份列表继续历史、一条消息转给另一 Agent。复杂交接表单和交接角色管理退出工作流程。

后续是否再增加能力，只看真实任务里能省下什么操作。没有证据说明需要的功能，不加入默认流程和本轮任务清单。
