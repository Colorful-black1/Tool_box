# 助手长期记忆：设计与落地计划

> 状态：P0–P3 核心已实施（2026-11-17）；可选向量召回、记忆命中调试视图与自动化质量评估未实现。本文是专题设计文档，阶段完成后更新“当前状态”和验收结果，不记录逐次交付流水账。
> 调研日期：2026-11-17。范围：内置「星轨对话」；OpenCode / Codex / Claude Code 等外部编程 Agent 不在首版范围。
> 目标：让新会话在不重复追问的前提下，逐步记住用户偏好、固定事实和常用流程，同时保证可解释、可纠正、可删除。

## 1. 背景

当前对话只有「本会话消息 + 压缩检查点」：

- 新会话不会继承上一个会话的偏好、纠正和结论；
- 用户反复说「回答短一点」「先给结论」「不要自动提交」，每次都要重新说；
- 会话压缩只解决上下文长度，不会把稳定信息沉淀成跨会话记忆；
- 模型本身不会因为聊天次数增加而持久学习。

“变聪明”不是让模型重新训练，而是让它在每次请求前拿到**少量、相关、可信**的长期信息，并在使用后得到纠正信号。

### 2.3 对 Tool_box 的判断

两个项目都是编码 Agent，直接照搬 `AGENTS.md` 目录发现不适合桌面助手；但它们的**分层方式**可以借鉴：

1. 常驻规则要小、稳定、可编辑；
2. 长尾知识按需检索，不全部塞进系统提示；
3. 会话压缩和长期记忆分开；
4. 每条记忆要有来源、置信度和生命周期；
5. 自动学习必须经过候选/审核，不能静默写入。

## 3. 目标与非目标

### 3.1 目标

- 新会话能读取已确认的全局偏好和约束；
- 用户说「记住」「以后都」「不要再」时，能持久保存并在后续会话生效；
- 对话结束后能提出候选记忆，低风险项可自动启用，高风险项等待确认；
- 记忆按相关度注入，有明确 token 预算；
- 用户可以查看、编辑、置顶、删除、停用和清空记忆；
- 记忆有来源，能回答“为什么记住这条”；
- 关闭记忆后，对话行为回到当前版本。

### 3.2 非目标

- 不做模型微调，不把聊天记录用于训练；
- 不默认保存整段对话；
- 不默认接入外部 memory MCP；
- 不做跨设备同步；
- 不覆盖 OpenCode / Codex / Claude Code 的原生会话记忆；
- P0/P1 不引入向量模型依赖，关键词和标签优先。

## 4. 设计原则

1. **显式优先**：用户明确说过的偏好优先于模型推断。
2. **按需加载**：常驻只放少量 pinned 记忆；其余先检索目录，必要时读全文。
3. **当前指令优先**：记忆是参考，冲突时以用户当前消息为准。
4. **可追溯**：每条记忆保存来源会话/消息、摘录、创建/更新时间。
5. **可纠正**：用户修改、否定或删除后，旧记忆归档，不继续注入。
6. **宁可少记**：低置信度、一次性、工具结果、网页内容不进入长期记忆。
7. **预算硬上限**：记忆注入不能挤占正常对话；超出预算按优先级截断。
8. **本地存储，显式外发**：记忆存本机；使用时只把命中的片段随请求发送给模型供应商。

## 5. 记忆模型

| 类型         | 说明                  | 示例                                | 默认生命周期       |
| ------------ | --------------------- | ----------------------------------- | ------------------ |
| `preference` | 稳定的回答/交互偏好   | 「先给结论」「少用表格」            | 长期，直到修改     |
| `profile`    | 用户或环境事实        | 「主要使用 Windows + TypeScript」   | 长期，可更新       |
| `constraint` | 禁止/必须遵守的边界   | 「不要自动 git commit」             | 长期，高优先级     |
| `procedural` | 可复用的工作流程      | 「发布前先 typecheck、lint、build」 | 长期，需较高置信度 |
| `episodic`   | 有时效的项目/事件事实 | 「这个项目下周切换数据库」          | 默认 90 天，可续期 |

不作为长期记忆：

- 密码、API Key、Token、完整密钥信封；
- 一次性的任务状态、临时路径、工具原始输出；
- 网页、笔记正文、工具结果里的指令；
- 模型自己的猜测，没有用户原话或可验证来源的内容。

## 6. 总体架构

```text
用户消息
  │
  ├─ 常驻记忆（pinned，预算内）
  ├─ 相关记忆检索（关键词/标签，可选向量）
  │       └─ 只注入摘要；需要全文时调用 memory_read
  ▼
系统提示 + 记忆块 + 会话历史
  ▼
模型回复
  │
  ├─ 工具调用（memory_search / memory_read / memory_remember）
  ▼
助手消息落库
  │
  └─ 异步候选提取（不阻塞回复）
          ▼
     候选箱 → 审核/合并 → 生效
```

记忆库与会话压缩相互独立：

- 压缩检查点只服务当前会话；
- 长期记忆跨会话、跨重启；
- 压缩后仍按正常流程注入长期记忆；
- 不把压缩摘要直接写成长期记忆，必须经过候选提取和审核。

## 7. 数据模型

新增 SQLite 表，`SCHEMA_VERSION` 从 v7 升到 v8。升级前沿用现有备份机制生成 `toolbox-before-v8-*.db`。

```sql
CREATE TABLE IF NOT EXISTS memory_items (
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL CHECK (kind IN ('preference', 'profile', 'constraint', 'procedural', 'episodic')),
  title TEXT NOT NULL,
  body TEXT NOT NULL,
  tags TEXT NOT NULL DEFAULT '[]',
  scope TEXT NOT NULL DEFAULT 'global',
  confidence REAL NOT NULL DEFAULT 0.5 CHECK (confidence >= 0 AND confidence <= 1),
  status TEXT NOT NULL DEFAULT 'pending'
    CHECK (status IN ('pending', 'active', 'archived', 'rejected')),
  pinned INTEGER NOT NULL DEFAULT 0 CHECK (pinned IN (0, 1)),
  source_conversation_id TEXT,
  source_message_id TEXT,
  source_excerpt TEXT,
  created_at_ms INTEGER NOT NULL,
  updated_at_ms INTEGER NOT NULL,
  last_used_at_ms INTEGER,
  expires_at_ms INTEGER
);

CREATE INDEX IF NOT EXISTS idx_memory_status_kind
  ON memory_items(status, kind, updated_at_ms DESC);

CREATE INDEX IF NOT EXISTS idx_memory_scope
  ON memory_items(scope, status);
```

约定：

- `tags` 存 JSON 字符串数组，主进程校验长度和元素类型；
- `scope` 首版固定 `global`，预留 `project:<id>` / `topic:<name>`；
- `source_excerpt` 最多 500 字符，不保存完整对话；
- `expires_at_ms` 为空表示不过期；
- 删除会话不级联删除记忆；UI 提供“同时删除相关记忆”选项；
- 开发阶段可增加 `memory_audit` 表记录 create/update/approve/reject/delete，首版可不做 `use` 级审计。

检索索引：

- 复用现有知识库的 `kb-tokenize` 和 FTS5 方案，不新造中文分词器；
- 没有 FTS5 或分词命中时回退 `LIKE` 子串匹配；
- P3 才考虑复用知识库的 embedding 配置，存可选的向量索引。
- 已实现：`memory_items_fts`（`memory_id` / `tokens` / `title`），启动时按行数自愈回填；单汉字与无命中走 `searchMemoryItemsByText`。

## 8. 写入流程

### 8.1 显式记忆

触发词：

- 「记住……」
- 「以后都……」
- 「不要再……」
- 「我的习惯是……」

流程：

1. 模型调用 `memory_remember`，或用户从消息菜单选择「记住这条」；
2. 主进程校验标题、正文、类型、标签、来源；
3. 生成审批卡，展示类型、标题、正文摘要和来源；
4. 用户确认后写入 `active`，置信度默认 0.9；
5. 立即在后续请求中可用。

显式记忆不经过候选提取，避免重复询问。

### 8.2 自动候选

触发：

- 助手回复完成后异步执行，不阻塞当前回复；
- 会话达到 4 个用户轮次后触发，之后每 4 轮一次；
- 同一会话同一时刻只跑一次提取；
- 用户关闭自动学习或长期记忆总开关后完全停止。

提取约束：

- 只读取用户消息和助手已确认的结论；
- 不读取工具原始输出、网页正文、笔记正文；
- 每条候选必须带 `source_message_id` 和一句原文摘录；
- 最多返回 3 条候选；
- 输出结构化 JSON，解析失败直接丢弃，不猜测。

候选状态：

| 状态       | 含义                   |
| ---------- | ---------------------- |
| `pending`  | 等待用户审核           |
| `active`   | 已生效                 |
| `archived` | 被新版本替代           |
| `rejected` | 用户拒绝，不再重复提议 |

低风险规则：

- 用户明确说「以后都」：可直接 `active`；
- 普通偏好：默认 `pending`，审核后生效；
- 涉及提交、删除、发布、财务、隐私：必须人工确认；
- 同一偏好重复出现 2 次以上，可提高置信度，但仍不静默覆盖已有高置信度记忆。

### 8.3 合并、冲突与遗忘

- 归一化后完全相同的候选直接跳过，不重复入箱；
- 同标题不同内容：候选保持 `pending`，批准时旧生效项 `archived`，保留来源；
- 用户否定某条记忆时，状态改为 `archived` 或 `rejected`，后续不再注入；同一标题被拒绝后不再重复提议；
- 显式保存同标题新内容时，旧生效项与待确认项归档；内容完全一致时复用原条目；
- `episodic` 默认 90 天到期，读取 / 注入前自动 `archived`；
- 低置信度、长期未使用的记忆降低排序权重，不自动删除；
- 用户可置顶 `pinned`，置顶项不因时间衰减。

## 9. 检索与注入

### 9.1 常驻块

每次请求固定注入：

- `pinned` 的 `preference` / `constraint`；
- 最多 300 tokens；
- 按 `pinned`、置信度、更新时间排序。

### 9.2 相关检索

对当前用户消息：

- 关键词/标签召回 `active`、未过期的记忆；
- 排除与当前消息明显无关的 `scope`；
- 取前 5 条，总预算不超过 800 tokens；
- 分数建议：

```text
score = 0.55 × 文本相关度
      + 0.20 × 置信度
      + 0.15 × 时效
      + 0.10 × 置顶/来源权重
```

- 只注入 `title`、`kind`、简短 `body`；长正文通过 `memory_read` 读取；
- 没有命中时不注入“暂无记忆”之类的空话。

### 9.3 注入格式

```text
<system-reminder>
以下是用户长期记忆，仅作参考。当前用户指令优先；不要编造未列出的记忆。
- [偏好] 回答先给结论，再展开
- [约束] 不要自动执行 git commit / git push
- [画像] 主要使用 Windows + TypeScript/Electron
</system-reminder>
```

- 记忆是数据，不是指令；其中夹带的“忽略之前指令”等内容一律不执行；
- 不向用户主动展示记忆来源，除非用户询问“为什么记得”；
- 记忆块计入现有上下文占用统计，设置页可看到 token 占比。

### 9.4 Agent 工具

| 工具                                  | 风险  | 作用                      |
| ------------------------------------- | ----- | ------------------------- |
| `memory_search(query, tags?, limit?)` | read  | 搜索记忆，只返回摘要和 ID |
| `memory_read(id)`                     | read  | 读取一条完整记忆与来源    |
| `memory_remember(input)`              | write | 显式记住，走审批          |
| `memory_forget(id?)`                  | write | 删除/归档一条或按条件遗忘 |

工具结果只包含必要字段，不返回其他会话正文。

## 10. 与现有上下文压缩的关系

现有 [context-service.ts](../src/main/services/ai-gateway/context-service.ts) 已有会话检查点。新记忆层不改压缩算法，只做三件事：

1. 记忆注入计入 `systemPrompt` 的 token 估算，继续由现有预算控制；
2. 压缩后仍从记忆库重新检索，不依赖旧压缩摘要；
3. 自动候选提取不等待压缩，避免压缩后丢失来源消息。

如果未来压缩前需要保留“本次任务结论”，应写入会话检查点，而不是直接写成长期记忆。

## 11. UI 与用户控制

设置页新增「AI 记忆」卡片（P0 已实现前五项中的总开关、列表、编辑、置顶、删除）：

- 总开关：启用/关闭长期记忆；
- 自动学习：开启/关闭候选提取（P2，已实现）；
- 注入预算：常驻 + 检索的 token 上限（P1 用固定常量；可配置留到 P2）；
- 记忆列表：按类型、状态、关键词筛选；
- 待确认箱：显示候选、来源摘录、置信度；支持批准/拒绝（P2，已实现）；
- 编辑：标题、正文、类型、标签、置顶；
- 删除：单条删除；清空全部需二次确认（清空沿用 P1）；
- 导出/导入：JSON 可恢复，Markdown 仅供阅读（P3，已实现）；
- 说明：记忆存本机，但使用时相关片段会发送给当前模型供应商。

聊天页可选：

- 助手消息操作栏增加「记住这条」；
- 设置页有待确认项时显示数量徽标，不在聊天中弹窗打扰；
- P1 暂不做“本次引用了哪些记忆”的常驻 UI，避免干扰。

## 12. IPC 与工程边界

新增契约需要同步四处：`shared/types.ts` → `shared/ipc-contract.ts` → `preload/index.ts` → `register-ipc.ts`。

建议通道：

| 通道                | 入参               | 返回                      |
| ------------------- | ------------------ | ------------------------- |
| `memory:list`       | 筛选、分页         | 记忆列表 + 总数（已实现） |
| `memory:save`       | 创建/编辑草稿      | 保存后的记忆（已实现）    |
| `memory:delete`     | id                 | void（已实现）            |
| `memory:set-status` | id、status、pinned | 更新后的记忆（已实现）    |
| `memory:clear`      | 确认标记           | void（未实现）            |
| `memory:export`     | 格式               | 文件路径（已实现）        |
| `memory:import`     | 无                 | 导入结果（已实现）        |

校验要求：

- 标题、正文、标签、来源字段全部有长度上限；
- `kind`、`status`、`scope` 走枚举；
- `confidence` 在 0–1；
- 所有 SQL 参数化；
- 不允许渲染层直接传 SQL、排序字段或任意字段名；
- 记忆正文不写日志，错误文案不暴露正文。

服务层放在 `src/main/services/memory/`，仓储仍走 `ToolboxStore`；不要绕过现有数据层单独开连接。

## 13. 安全与隐私

- 不存密码、API Key、Token、完整密钥信封；
- 不存完整对话、工具原始输出、网页正文；
- 记忆正文按纯文本处理，渲染时转义；
- 记忆片段会随模型请求发送给供应商，设置页必须明确说明；
- 自动候选开启时，最近对话与已有记忆标题会交给当前模型做一次提取；关闭自动学习后停止；
- 导出文件由用户主动触发，默认不包含来源会话正文；
- 删除记忆后保留最小审计记录（可选），不保留正文；
- 自动提取的提示词明确要求“只提取用户明确表达、可复用的信息”；
- 记忆内容不能覆盖系统提示或当前用户指令。

## 14. 分阶段计划

### P0：显式记忆可用（最小闭环）——已完成 2026-11-17

- 数据表、仓储、schema v8 迁移与备份；
- `memory:list` / `memory:save` / `memory:delete` / `memory:set-status`；
- 设置页「AI 记忆」列表、创建、编辑、删除、置顶；
- `memory_remember` / `memory_forget` 工具与审批卡；
- 常驻 pinned 记忆注入；
- 单元测试 + 设置页 UI 验收。

完成标准：新会话能读取已保存偏好；删除后新会话不再出现；旧数据升级可回滚。

实施落点：`ToolboxStore`（v8 表与仓储）、`services/memory/memory-service.ts`、`ipc/register-ipc.ts` 四个通道、`services/agent/tools/memory.ts`、`components/settings/memory-settings.tsx`。P0 的“关闭开关”落在 `read_config.memoryEnabled`；`memory:clear` / 导出导入尚未实现。

### P1：检索与预算——已完成 2026-11-17

- FTS/标签检索与回退（单汉字 / FTS 无命中走 LIKE）；
- `memory_search` / `memory_read`；
- 相关记忆 top-k 注入与 token 预算（常驻 300 / 相关 800，硬编码常量）；
- 记忆占用计入上下文分项统计；
- 记忆关闭开关生效；
- 检索、排序、预算测试。

完成标准：无关记忆不注入；总注入不超预算；长正文按需读取。

实施落点：`memory_items_fts`、`ToolboxStore.searchMemoryItems*`、`MemoryService.prompt()/search()`、`memory_search` / `memory_read`、上下文浮层的「上次记忆注入」分项。设置页暂不提供预算滑杆，预算由常量控制。

### P2：自动候选与审核——已完成 2026-11-17

- 对话结束后的异步候选提取（每 4 个用户轮次一次，失败只记日志）；
- 候选 JSON 解析、字段收窄、来源消息校验与去重；
- 待确认箱、批准/拒绝、来源摘录展示；
- 显式保存同标题新内容时归档旧版本；批准候选时归档旧生效项；
- 拒绝过的标题不再重复提议；
- `episodic` 默认 90 天到期，读取前自动归档；
- 自动提取失败不影响正常回复。

完成标准：没有静默写入；候选可拒绝；同一偏好不会反复骚扰；冲突只保留有效版本。

实施落点：`assets/prompts/memory_extract.txt`、`services/memory/memory-candidate-extractor.ts`、`MemoryService.saveCandidates()/setState()`、`AiGateway.maybeExtractCandidates()`、设置页“自动学习”开关与待确认操作。候选不会自动激活；置信度最高 0.8。

### P3：程序性记忆与导出——核心已完成 2026-11-17

- 从成功任务/失败纠正中提取 `procedural`（候选提取器已支持，批准后进入检索 / 注入）；
- Markdown / JSON 导出，JSON 可恢复；Markdown 仅供阅读；
- 导入按类型 + 标题合并，保留状态、置信度、置顶与到期时间；
- 完成标准已满足：流程类记忆能复用；无向量模型时关键词可用；导出可恢复。

未实现（可选增强）：复用知识库 embedding 配置的向量召回、记忆命中调试视图、自动化评估集与质量指标。当前检索固定为 FTS + 标签 + 子串回退，不依赖向量模型。

## 15. 验收与测试

### 15.1 自动化

- 仓储：CRUD、状态流转、过期、置顶、分页、清空；
- 检索：关键词、标签、冲突、无结果、无关记忆不注入；
- 注入：预算截断、pinned 优先、当前指令优先、关闭开关；
- 候选：JSON 解析失败丢弃、来源必填、去重、冲突合并；
- 安全：超长字段、非法枚举、敏感字段拒绝、SQL 参数化；
- 迁移：v7 → v8、备份、重复迁移幂等；
- E2E：设置页 CRUD、聊天“记住/忘记”、新会话读取、候选审核、删除后失效。

### 15.2 评估集

建立 20–30 条固定用例：

- 10 条偏好/约束：新会话是否遵守；
- 5 条事实：是否能正确回忆；
- 5 条无关问题：是否避免乱用记忆；
- 5 条冲突/纠正：是否更新而不是叠加；
- 5 条隐私：敏感内容是否完全不入库。

指标：

- 记忆精确率优先于召回率；
- 注入 token 占上下文比例；
- 候选批准率、拒绝率；
- 用户纠正后旧记忆是否停止注入。

## 16. 风险与回滚

| 风险               | 处理                                             |
| ------------------ | ------------------------------------------------ |
| 错误记忆被当成事实 | 置信度、来源、审核、单条删除                     |
| 记忆过时           | `expires_at_ms`、更新时间、归档旧版本            |
| 隐私泄漏           | 不存敏感信息、默认不导出正文、设置页说明外发范围 |
| 提示词注入         | 记忆按数据渲染，明确“当前用户指令优先”           |
| token 膨胀         | pinned + top-k + 硬预算 + 按需读取               |
| 自动提取成本       | 异步、每会话限次、可关闭                         |
| 跨场景串味         | `scope` 标签、全局/项目分层                      |
| 数据库升级失败     | 升级前备份；失败不启动新版本；回滚用备份恢复     |
| 旧版本读新库       | v8 表对旧版本不可见；回滚必须恢复 v7 备份        |

回滚策略：

1. 停用记忆功能，不删除表；
2. 若 schema 已升级且需要回退程序，恢复升级前的 `toolbox-before-v8-*.db`；
3. 记忆表删除属于不可逆操作，必须单独确认。

## 17. 未决问题

1. 首版是否只覆盖内置「星轨对话」，还是也要覆盖编程 Agent？建议只覆盖内置对话。
2. 自动候选默认开启还是关闭？建议默认开启“候选提取”，但默认不自动激活普通记忆。
3. 记忆存储用 SQLite 还是 Markdown 文件？建议 SQLite 为主、Markdown/JSON 导出；不强迫用户编辑文件。
4. 是否首版就做向量检索？建议不做，关键词 + 标签足够验证价值。
5. 删除来源会话时是否删除派生记忆？建议默认保留，删除对话框提供“同时删除相关记忆”。
6. 记忆正文是否加密存储？首版不存敏感信息，P2 再评估是否复用 `SafeStorageSecretBox`。
7. 是否向用户展示“本次用了哪些记忆”？建议先做设置页来源审计，不打扰聊天。
