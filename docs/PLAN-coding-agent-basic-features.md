# 编程 Agent 基础交互与会话能力补齐计划

日期：2026-10-29
状态：用户已要求先提交基线并开始实施；首批基础交互已落地，原生历史变更及后续批次仍按各自边界推进。具体范围与验证见 [交付记录](coding-agent-basic-features-verification.md)。
目标：日常编程不再因缺少编辑、上下文状态或追问入口频繁切回原生应用。没有真实能力支撑的按钮不做，已有功能不重复建设。

## 1. 建议先补什么

建议第一批按以下顺序交付。顺序表示依赖和收益，不表示所有 Agent 一定能做到完全一致：

1. **消息取回编辑**：每条用户消息可一键放回输入框，保留原草稿；已有引用重新校验，缺失元数据的附件需重选，不立即发送。
2. **上下文状态**：显示当前上下文百分比、已用 / 可用窗口与数据时点；压缩上下文有清楚入口和结果反馈。
3. **结构化追问和计划确认**：Agent 问问题、请求选择方案时能直接回答，避免 Claude 等入口因此中止任务。
4. **明确的失败恢复**：区分未发送、明确失败、用户停止、结果未知；提供恰当的取回输入、重读原生会话及继续入口。
5. **真正的消息回退 / 编辑后重发**：用户需求优先级高，但必须先验证各原生协议；有可靠接口的入口先上线，不以界面删行冒充撤回。

第二批补齐执行详情 / 文件 Diff、对话正文查找、代码块复制、图片粘贴等常用操作。
原生上下文回退受协议限制，不能用第一项“取回编辑”替代后就宣称已完成第五项。

### 1.1 本计划的默认选择

- 保留现有 OpenCode ACP、Codex app-server、Claude SDK、DSH ACP，不为通用基础交互整体更换架构。
- 消息“编辑”的通用基础操作先明确命名为 **取回编辑**；原地回退或分叉编辑另按真实能力提供。
- 已发送消息的默认回退只针对会话上下文；文件恢复是另一项操作，不默认联动。
- 有原生上报就展示；没有可靠数据就显示“未提供”，不伪造百分比、速度或成功状态。
- 不添加价格维护、模型计费表或新的 Token 统计面板。
- 只维护 PC 桌面端；五个已接入入口纳入评估，Kimi 枚举预留和其他 Token 来源不算已接入编程运行时。

## 2. 候选能力图

本文先划分模块与交付顺序，不替代各模块实施前的详细规格和协议审批。

| 模块 ID | 职责 | 依赖 | 建议阶段 |
| --- | --- | --- | --- |
| runtime-capabilities | 识别安装版本与真实操作能力，保留消息 / 轮次的原生定位信息 | 现有 adapter / service | A，基础 |
| message-actions | 取回编辑、原生回退、编辑重发、从此处分叉 | runtime-capabilities；纯取回编辑可先独立交付 | A / C |
| context-insight | 当前上下文、轮次用量、压缩反馈、数据新旧状态 | runtime-capabilities | A |
| human-interaction | 结构化问题、计划确认、取消与失效处理 | runtime-capabilities | B |
| run-recovery | 发送状态、失败恢复、明确的重试 / 继续、耗时 | runtime-capabilities；重生成依赖 message-actions | B / C |
| execution-insight | 工具输入输出、文件改动 / Diff、任务步骤 | runtime-capabilities | D |
| conversation-navigation | 正文查找、跳到用户提问、代码复制与原文查看 | 现有消息渲染 | D，可独立 |
| attachments | 图片粘贴、拖入文件、能力与格式校验 | runtime-capabilities、现有引用机制 | D |
| session-organization | 会话重命名、归档、导出、更多历史分页 | runtime-capabilities | E |
| queued-input | 运行中的待发消息、修改 / 取消 / 手动发送 | run-recovery、现有每 Agent 独立草稿 | E，后置 |

建议构建顺序：

`取回编辑 → 能力与原生身份 → 上下文状态 → 结构化交互 / 失败恢复 → 有条件的原生回退 → 阅读与执行体验 → 其他`

能力互相独立，适合小批交付；不为了“统一所有 Agent”阻塞能直接改善体验的部分。

## 3. 已核对的项目现状

下列结论来自当前工作区代码，包括此前尚未提交的改动，不只依据 README。

| 范围 | 已有能力 | 本次看到的缺口 |
| --- | --- | --- |
| 消息展示 | 历史与新回复共用 Markdown；助手消息可复制和转用 | 用户消息没有复制 / 取回编辑；没有真实回退、重生成与分叉入口 |
| 项目与任务 | 各 Agent 独立项目记忆、按项目 / 原生会话隔离草稿、不同项目并行 | 新操作必须继续遵守原有归属和同项目互斥，不能另造一套会话状态 |
| 输入 | Enter 发送、Shift+Enter 换行、输入法保护、运行时可继续编辑草稿 | 缺少明确编辑模式、待发消息状态和附件粘贴 |
| 文件与命令 | @ 文件、/ 命令、Skill、MCP 目录、部分原生压缩与初始化 | 不应重新规划为“待新增”；缺的是操作完成反馈和更多结构化交互 |
| 任务控制 | 准备取消、停止、单次权限审批、后台任务定位 | 用户问答、计划确认不等于二选一工具审批 |
| 运行信息 | 状态、工具名称 / 状态、部分子任务结果 | 无会话级上下文读数；工具正文、Diff、轮次用量和时间信息不足 |
| 历史 | 按标题筛选、原生恢复、部分入口刷新正文 | 标题筛选不等于正文查找；摘要只有 id / title，元数据和分页能力有限 |
| 安全恢复 | 连接 / runId / revision 保护，不自动重发未知任务 | 没有把不同失败语义转换成明确的下一步操作 |

### 3.1 关键代码证据

- `src/shared/coding-agents.ts`：消息仅 `id / role / content`；会话没有上下文、轮次用量、原生回退边界、结构化问题等字段。`capabilities.usage` 仍只有粗粒度状态。
- `src/shared/bridge.ts`、`src/preload/index.ts`、`src/main/ipc/coding-agents-ipc.ts`：已有发送 / 停止 / 审批 / 命令 / 历史接口，没有消息回退、分叉和用户问题回答接口。
- `src/main/services/coding-agents/adapter.ts`：适配器没有消息级操作或上下文查询边界。
- `src/main/services/coding-agents/acp-codec.ts`：只映射正文、工具摘要、标题和配置；忽略 `usage_update`，消息采用本地序号并按相邻角色合并，未保留 ACP 的 `messageId`。
- `src/main/services/coding-agents/codex-adapter.ts`：未接 `thread/tokenUsage/updated`；只处理部分工具审批，其他反向交互请求拒绝。当前适配逻辑不能直接套用最新协议的全部历史方法。
- `src/main/services/coding-agents/codex-codec.ts`：保留部分 item ID，但没有稳定的轮次边界；模型目录只保留选择所需字段。
- `src/main/services/coding-agents/claude-adapter.ts`：用户消息以本地 UUID 插入；助手正文 ID 与 SDK 链条 UUID 没有完整映射。`AskUserQuestion / ExitPlanMode` 当前会停止任务，结果用量未投影到会话。每轮结束会关闭 Query，不能假定页面随时有可查询的活跃 SDK 对象。
- `src/main/services/coding-agents/dsh-adapter.ts`：接收 ACP 更新，但共用 codec 未消费用量；历史正文已有本地日志只读恢复，不能再将“DSH 不回放历史”泛化成工具箱完全看不到历史。
- `src/main/services/coding-agents/agent-action-catalog.ts`：当前特意过滤 `undo / redo / rewind` 等操作；后续应新增明确的操作契约，不能直接把它们放回普通命令列表。
- `src/renderer/src/components/opencode/opencode-messages.tsx`：用户消息仅正文，助手操作仅复制 / 转用；共用渲染历史和增量。
- `opencode-activity.tsx`、`agent-composer.tsx`、`coding-agent-store.ts`：可复用现有审批区、输入区、草稿协调和独立工作台状态。

## 4. 上游调研：能借鉴什么，不能直接等同什么

### 4.1 核验范围与版本

本轮只阅读代码、官方文档与本地 SDK 类型，没有启动任何 Agent、创建会话、发送模型任务、读取认证配置或变更用户数据。

- OpenCode：读取 `dev` 分支的固定提交 `aaa0d7c8f6775a211185951a3f16fec840e648a4`。
- DSH：读取 `master` 分支的固定提交 `f3803c96974ad4a94195fb97e5c637e9c2a3afe3`。
- Claude：本项目固定 SDK `@anthropic-ai/claude-agent-sdk@0.3.310`，直接检查已安装 `sdk.d.ts`。
- Codex：核对当前官方 app-server 文档，并与本项目适配器比较；未确认本机外部程序已升级到该协议。
- 上游开发分支不等于用户已安装版本；源代码证明“存在实现”，不证明当前连接一定支持。实施必须先探测本机协议 / Schema / 已公布能力。
- 第二个用户链接中的中文标点按仓库地址 `https://github.com/deepseek-ai/deepseek-harness` 处理。

### 4.2 OpenCode

**可借鉴的交互与技术：**

1. 原应用明确区分 `recall` 与 `revert`：前者只恢复输入；后者先中断并等待执行完全结束，再阶段性回退，恢复草稿，还提供撤销回退的入口。[原应用回退控制器](https://github.com/anomalyco/opencode/blob/aaa0d7c8f6775a211185951a3f16fec840e648a4/packages/app/src/session/revert.ts)
2. 回退不是简单删除正文。底层会处理消息边界和文件快照，默认路径可能恢复文件；源码有 `files: false` 的分离语义，是否能从目标版本的公开接口调用仍需核实。[回退服务](https://github.com/anomalyco/opencode/blob/aaa0d7c8f6775a211185951a3f16fec840e648a4/packages/core/src/session/revert.ts)
3. 原应用支持从选定用户提问前分叉，复制上下文到新会话并把问题放回输入框。这适合作为保留原分支的编辑方式。[分叉控制器](https://github.com/anomalyco/opencode/blob/aaa0d7c8f6775a211185951a3f16fec840e648a4/packages/app/src/session/fork.ts)
4. 当前 ACP 实现发布 `usage_update { used, size }`，本轮完成时计算当前用量并附带模型窗口；工具箱可沿用 ACP 接收。当前 ACP 也声明会话 fork，但源码调用的是整会话 fork，不能据此宣称支持“任意历史消息处分叉”。[ACP 用量](https://github.com/anomalyco/opencode/blob/aaa0d7c8f6775a211185951a3f16fec840e648a4/packages/cli/src/acp/turn.ts#L328)、[ACP 服务与能力](https://github.com/anomalyco/opencode/blob/aaa0d7c8f6775a211185951a3f16fec840e648a4/packages/cli/src/acp/service.ts)
5. GUI 上下文视图选择当前有效历史范围中的最近一次有效助手用量，结合该模型窗口，而非把整段会话累计消耗除以窗口。[上下文视图](https://github.com/anomalyco/opencode/blob/aaa0d7c8f6775a211185951a3f16fec840e648a4/packages/gui-plugins/src/context/tab.tsx#L111)

**对 Tool_box 的判断：**

- 上下文读数是当前架构可优先补的能力。
- 原生回退和任意位置分叉不应直接复用聊天文本 `/undo`；当前 ACP 服务表未提供与原应用回退 API 等价的操作。
- 如确认必须支持 OpenCode 的完整回退，可单独评估其公开本地 Server API。那是有额外端口、认证、进程与同一会话访问归属要求的接入升级，不能为了一个按钮偷偷再开一套后端，更不能依赖私有数据库写入。
- UI 实现框架不同，借鉴状态和操作语义即可，不复制整套 UI 或构建依赖。

### 4.3 DeepSeek Harness

**可借鉴的交互与技术：**

1. 原生 UI 通过 context-pressure 投影显示占用比例；缺少分子或窗口时不展示。详情把总占用与启发式组成分开，并标注近似值；模型切换后没有新窗口就关闭旧详情。[占用计算](https://github.com/deepseek-ai/deepseek-harness/blob/f3803c96974ad4a94195fb97e5c637e9c2a3afe3/packages/client/ui-conversation/src/client/context-occupancy.ts)、[ContextMeter](https://github.com/deepseek-ai/deepseek-harness/blob/f3803c96974ad4a94195fb97e5c637e9c2a3afe3/packages/client/ui-conversation/src/client/skeleton/ContextMeter.tsx)
2. 当前 ACP 已发送 `usage_update`：有用量记录、模型窗口与 token-meter 时，返回当前测量值 `used` 和 `size`。来自已提交助手消息，不意味着原始 Token 实时流。[ACP 更新](https://github.com/deepseek-ai/deepseek-harness/blob/f3803c96974ad4a94195fb97e5c637e9c2a3afe3/packages/acp/acp/src/updates.ts#L87)
3. 原生客户端有会话 fork，并按权限控制入口；普通 fork 复制选定历史并独立继续。这种“保留原会话”的交互值得借鉴。[客户端 Fork](https://github.com/deepseek-ai/deepseek-harness/blob/f3803c96974ad4a94195fb97e5c637e9c2a3afe3/packages/client/ui-workspace/src/client/session-actions/ForkSession.tsx)、[独立分叉说明](https://github.com/deepseek-ai/deepseek-harness/blob/f3803c96974ad4a94195fb97e5c637e9c2a3afe3/docs/upgrade-guide/v0.2.1-rc.3/independent-session-forks/guide.md)
4. **DSH ACP 是明确收窄的自动化接口**：公开说明支持提交 / 取消、配置、通用工具状态和上下文用量；不支持创建 fork、删除、完整历史回放、命令、计划、交互式 elicitation 等。原生 Web / Desktop 的能力不等于 ACP 都能用。[ACP 契约](https://github.com/deepseek-ai/deepseek-harness/blob/f3803c96974ad4a94195fb97e5c637e9c2a3afe3/packages/acp/acp/README.md#protocol-contract)

**对 Tool_box 的判断：**

- 可先通过 ACP 补上下文与通用工具输出，不需要为了百分比更换架构。
- 目前不能承诺 DSH 真撤回、历史处分叉和原生问答接入；先提供明确的取回编辑。
- 进一步接入公开 SDK / host API 需要独立验证配置继承、会话写入独占、版本兼容和 Desktop 历史；不得拼接私有 WebSocket、改写日志或注入官方插件来伪造支持。
- 不新增“看起来在流式输出”的打字动画，也不把正文显示上限当作上下文窗口。

### 4.4 其他现有入口

**Codex**：当前官方文档有线程用量通知、分叉与 `thread/revert`；后者面向持久化分页历史，回退对话不恢复文件。旧 `thread/rollback` 已移除。本机版本、旧格式历史和目标轮次的可用性必须另验；不能直接照最新方法替换当前适配器。文档也提供用户输入请求等交互路径。[官方 app-server](https://learn.chatgpt.com/docs/app-server)

**Claude Code / Desktop**：本地 SDK 类型具备 `getContextUsage({ detail: 'summary' })`、上下文窗口和结构化用量类型，以及 `forkSession`、`resumeSessionAt`、`resumeDropsTurn` 等恢复控制。链条 UUID 与正文 `message.id` 不可混用。文件回滚是要求开启 checkpoint 的独立 `rewindFiles`，不应随编辑默认启用。现有适配器每轮关闭 Query，需在其真实存活期取得上下文，不后台创建新 Query 来“刷新百分比”。以上为静态类型依据，尚非供应商路由实测。

## 5. 功能清单与优先级

| 编号 | 功能 | 优先级 | 体验目标 | 成本 / 主要限制 |
| --- | --- | --- | --- | --- |
| F01 | 用户消息复制、取回编辑 | P0 | 无需手工框选，点一次回到输入框，支持取消 | 小；复用草稿与引用重校验 |
| F02 | 真撤回、回退到此处、编辑后重新提交 | P0，条件交付 | 实际改变下一轮模型上下文，有清楚影响范围 | 大；协议与消息边界是前置条件 |
| F03 | 上下文百分比 / 已用与窗口 / 压缩状态 | P0 | 发送前知道上下文压力，压缩后能看到更新 | 中；数据来源、时点、窗口定义须一致 |
| F04 | 结构化追问、方案选择、计划确认 | P0 | 不因 Agent 追问被迫返回原应用 | 中至大；多种原生问答协议 |
| F05 | 失败恢复、明确重试、继续、轮次状态与耗时 | P0 | 知道是否已发送，下一步操作无需猜测 | 中；结果未知时不能直接重发 |
| F06 | 工具输入输出、错误展开、文件 Diff / 改动列表 | P1 | 看得见正在做什么、具体改了哪里 | 中至大；当前契约已丢弃大量结构化内容 |
| F07 | 会话正文查找、上一处 / 下一处、定位用户提问 | P1 | 长对话找信息方便，不只按标题找会话 | 小至中；先搜索已加载范围 |
| F08 | 代码块复制、长行换行开关、Markdown 原文查看 | P1 | 无需框选代码，原文与渲染切换 | 小；复用现有 Markdown，复制不带语言标签 |
| F09 | 粘贴截图 / 拖放图片及文件、附件预览与移除 | P1 | 直接发错误截图，路径引用更直观 | 中；必须按模型和原生协议判断图片支持 |
| F10 | 从此处分叉并编辑、分支来源提示 | P1 | 试另一种方案而不破坏原上下文 | 大；整会话 fork 不等于按消息 fork |
| F11 | 会话重命名、归档、更多历史、Markdown 导出 | P1 / P2 | 常用会话能整理、完整历史可检索 | 中；按原生 API 提供，导出标明范围 |
| F12 | 运行时待发消息、修改 / 取消、可选原生 steering | P2 | 写完下一条不会丢，也不会误打断当前任务 | 大；先单条待发，不造复杂任务队列 |
| F13 | 思考过程、计划步骤 / Todo 的折叠显示 | P2 | 有需要再展开，不挤占正文 | 中；只展示公开事件，不推测隐藏推理 |
| F14 | 完成 / 待回答提醒与任务定位 | P2 | 后台 Agent 需要注意时能快速回去 | 中；先应用内，系统通知另确认 |

P0 不是要求一次交付所有入口所有能力。F02 在不支持的入口保持不可用，不能用一个“撤回”按钮换来更严重的状态不一致。

## 6. 关键操作语义

### 6.1 重新编辑分成三个明确动作

| 动作 | 历史是否改变 | 是否自动发模型任务 | 建议入口 |
| --- | --- | --- | --- |
| 取回编辑 | 不改变，修改后默认是追加新消息 | 否 | 所有用户消息的基础操作 |
| 编辑并重新提交 | 原生回退到该用户轮次前，再以修改内容继续 | 只有用户最终点发送才执行 | 原生回退和稳定边界可用时 |
| 从此处分叉编辑 | 新原生会话保留此前历史，原会话不变 | 不自动发送 | 按目标消息分叉可用时 |

**F01 第一批交付细节：**

- 用户消息操作条提供“复制”“取回编辑”，键盘聚焦时同样可见，不只依赖 hover。
- 取回后聚焦输入框，提示“已取回原文，发送将作为新消息追加”；不得误称原消息已被修改。
- 当前草稿不同且非空时复用 confirmDialog 确认替换；取消保持草稿、会话和选中项不变。
- 运行期间允许继续编辑下一条草稿，但不并发发送；不为取回文本中断当前任务。
- 已有文件 / Skill 引用需按当前目录和原生能力重新解析，失效则提示重新选择，不能复制旧的临时引用 ID。
- 当前消息仅保存纯文本时，A1 只能恢复原文和其中的路径文字，不能声称已恢复原生附件；完整引用恢复依赖后续消息元数据，不从文本猜造附件。
- 真编辑模式另显示目标轮次与“取消编辑”；进入 / 退出编辑模式不立即修改原生历史。
- 修改内容不能提前写入原历史消息，也不能污染其他 Agent / 项目的草稿。

### 6.2 撤回不是删除聊天气泡

区分三种情况：

1. **仍在本地、尚未提交的待发消息**：可取消并恢复草稿，不调用原生回退。
2. **已经提交且正在运行**：不能承诺模型没看到；先明确停止并确认原生已结算，再决定回退。停止不等于撤销文件、命令或其他副作用。
3. **已结束的原生轮次**：有可靠原生接口才提供撤回。撤回旧轮次会影响它之后的整个对话尾部，按钮应称“回退到此处”，预览影响轮次，而不是“只删除这一条”。

执行流程：

`选择原生锚点 → 主进程预览影响 → 用户确认 → 再验归属 / 历史版本 / 空闲状态 → 原生操作 → 重读权威历史 → 更新界面`

- 只删除 renderer 数组、传一句“忽略上一条”、重建新会话后只塞摘要，都不算真撤回。
- 默认仅处理对话，文件保留；若某入口不能单独回退对话，就先不开放该入口的真回退。
- 文件恢复将作为独立高风险功能评估，需变更预览和明确确认，不自动执行 git reset / checkout / clean。
- 原生操作超时属于结果未知：先重读核对，不自动重试变更请求；确认不能继续使用。
- 有可逆原生 staging / redo 才提供“撤销回退”；已不可逆提交的历史不能承诺可一键恢复。

### 6.3 上下文读数的口径

建议输入区底部紧凑显示：

`上下文 42% · 54K / 128K · 上次响应后`

点击小面板可看来源、模型、测量时间、已知的输入 / 输出 / 缓存分项和“压缩上下文”。

必须区分：

- **上下文占用**：当前有效上下文的压力，压缩 / 回退后可下降。
- **本轮或累计 Token 消耗**：请求消耗，可持续增加；不能用它直接计算占用百分比。
- **模型硬窗口与压缩策略窗口**：原生给的是哪个，就明确用哪个，不能混用。

具体规则：

- 只用同一语义来源的 `used / size`，或原生已经计算好的百分比；不根据模型名称维护硬编码窗口表。
- 缓存命中通常属于输入组成，不能跨来源用统一加法重复计算。
- DSH meter、Claude summary 等有估计成分时标“约”；Tool_box 不再另用字符数 / 4 估算。
- 分子缺失或窗口无效时不显示 0%；有分子无窗口可显示数量，百分比显示“—”。
- 图形进度限制在 0–100%，真实读数超过 100% 时保留超限提示，不能把 108% 的文本也悄悄截成 100%。
- 压缩 / 回退 / 切模型后令旧值失效，收到对应新模型 / 新历史版本的读数才恢复；断开或只读旧历史标明旧快照。
- ACP 用量事件若未携带模型身份，只能按其原生 used / size 展示已知事实；不能把迟到事件强行归给刚切换的新模型，无法确认代次就保持失效或显示旧快照。
- 不以高频计时器触发模型请求，也不把 `/context` 作为普通聊天文字偷偷发送。
- 默认不调用 Claude `detail: full` 的额外计数请求；summary 失败就降级，不为了状态栏增加后台消费。
- 先给一行读数，不新增一屏仪表盘；80% / 95% 可用作工具箱的视觉提醒阈值，须标明只是 UI 提醒，不伪装成原生压缩阈值。

### 6.4 原生问答与计划确认

- 复用现有输入区上方的交互区，支持少量单选、多选和自由文本问题，提供提交 / 取消，不用普通聊天回答代替协议回复。
- Claude 的 AskUserQuestion、ExitPlanMode 分别处理；计划确认不能默认等同于授予全部工具权限。
- Codex 用户输入与 MCP 表单按各自 schema 映射；OpenCode 先检查并声明所支持的 elicitation 能力。
- DSH ACP 当前不提供该能力，不伪造问答事件；未来换接入方式再评估。
- 请求与 Agent、项目、连接、原生会话、运行和 requestRef 绑定；切换标签不改变回答对象。
- 支持请求撤销 / 已解决 / 任务结束 / 断开后的失效，旧表单不能回答新任务。
- 初版不自动打开 URL 登录表单、不保存秘密答案，不接未知 JSON schema 的任意表单。
- 不再像现状一样把可支持的追问全部转换成任务失败；真正不支持时给可理解的说明并正确结算。

### 6.5 失败、重试与“重新生成”

| 当前事实 | 建议操作 | 禁止行为 |
| --- | --- | --- |
| 原生明确未接纳 | 取回输入，用户修改后发送 | 重复插入同一条本地用户消息 |
| 原生明确失败且已结束 | 显示原因，允许用户明确再次发送；说明已有副作用可能保留 | 自动恢复文件、自动重试工具 |
| 用户已停止 | 保留部分结果，可继续提问或选择原生回退 | 宣称任务未执行过 |
| 断连 / 超时，结果未知 | 先重连并读取原生历史，核对原轮次 | 一键盲目重发旧任务 |
| 希望得到另一版回答 | 原生回退 / 分叉支持时提供“重新生成”；否则明确“追加重试” | 把“再回答一遍”当成真正重生成且隐藏原上下文 |

本轮耗时可用发送受理到终态的本地单调时钟记录；未知历史时间不补造。
无原始 Token 分片的入口不显示虚构 Token/s，首条“提交后回复”的耗时也不冒充模型首 Token 延迟。

## 7. 各入口接入判断

符号：**可补**＝当前传输 / 本地类型有依据但需实施实测；**条件**＝需版本或独立协议验证；**不开放**＝所选传输明确未提供。

| 入口 | 取回编辑 | 上下文 | 真回退 / 编辑重发 | 分叉 | 问答 / 计划确认 |
| --- | --- | --- | --- | --- | --- |
| OpenCode ACP | 可补 | 可补，usage_update | 当前 ACP 不开放等价回退；公开 Server API 另评估 | 当前源码可整会话 fork，按消息需另验证 | 条件：新版本 elicitation 能力 |
| Codex app-server | 可补 | 可补，线程用量事件 | 条件：按本机 schema 和历史格式判断 revert / 旧接口差异 | 条件：保留轮次锚点并验证 lastTurnId | 可补，按实际反向请求能力 |
| Claude Code SDK | 可补 | 可补，Query 存活期 summary / 原生上下文事件 | 条件：链 UUID、丢弃轮次校验、恢复边界 | 本地 SDK 有依据，先验证元数据操作 | 可补，AskUserQuestion / ExitPlanMode |
| Claude Desktop 入口 | 可补 | 同 SDK，供应商可能不返回完整数据 | 同 SDK，限当前支持的本机 Code 会话 | 同 SDK；不保证新会话出现在 Desktop 列表 | 同 SDK，不等于支持普通 Desktop Chat |
| DSH ACP | 可补 | 可补，已提交回复后的 usage_update | 不开放；不能靠改写日志实现 | 不开放创建；原生 UI 有不代表 ACP 有 | 不开放 |

**推荐技术取舍：**

- 上述“可补”先保持既有传输并完成，不以迁移为前提。
- 真回退先攻关 Codex / Claude，OpenCode 先做公开 API 可行性验证，不向用户承诺全入口同批上线。
- 若 OpenCode 需升级传输，独立评审单连接归属、本地回环监听、随机认证、进程生命周期及原生配置兼容。
- DSH 的 SDK / host 扩展列为后续备选，不能把维护私有 API 的成本塞进基础按钮。
- 最终显示哪项操作，应由运行时和当前消息能力决定，而非只按 Agent 名称写死。

## 8. 建议的技术边界

### 8.1 先补能力与原生定位

当前三个问题必须先解决：

1. UI 消息 ID 有合成序号，Claude 也可能只保留 provider message ID，不能直接作为回退定位。
2. 历史加载、增量分片和最终消息要映射到同一原生消息 / 轮次，不能生成重复或错误的编辑目标。
3. 不同接口里的“可撤回”“可整会话分叉”“可按消息分叉”不能共用一个支持开关。

建议由 adapter 保留原生消息 / 轮次 / 日志链条定位，service 返回不透明 actionRef。
renderer 只提交本地引用，不接受任意原生 UUID、回退条数、日志偏移或文件路径。

能力按具体操作细分，保留 supported / unsupported / unknown 与简短原因；缺失字段按未知处理，兼容旧 preload。
未知时不提供可执行按钮，能力说明放进现有连接设置，避免一排永远点不了的按钮。

### 8.2 会话展示契约候选

实施前再形成具体类型；这里仅定义需要承载的语义：

- 消息：稳定展示 ID、角色、原文、可用动作、不透明锚点引用。
- 会话：historyRevision（只在历史结构变化时更新）、当前有效上下文快照、当前轮次用量、压缩状态、待回答请求。
- 上下文：used / window、模型、窗口口径、来源、原生报告或近似测量、时间与失效状态。
- 执行详情：可安全展示的工具输入 / 输出摘要、结果类型、受限文件改动引用；不把任意原生对象透传 renderer。
- 历史摘要分页：可选 cursor、时间等元数据，旧 id / title 调用继续兼容。

破坏性操作使用 historyRevision 或主进程生成的预览凭据检查边界；不能拿每次工具 / 用量推送都变化的普通 view.revision 当作历史版本，否则确认框会不断无故失效。

### 8.3 IPC 与分层候选

- 取回编辑、正文查找、复制、原文切换先在 renderer 完成，不为纯 UI 操作增加 IPC。
- 上下文推送优先扩展既有 session 事件；主动元数据刷新仅在原生提供安全只读能力时考虑。
- 原生变更分成“预览影响”和“确认执行”，输入含 runtimeId、sessionRef、actionRef、预期历史版本。
- 问答新增回答接口，使用 requestRef 和逐字段白名单校验，不提交原生任意响应对象。
- service 统一检查窗口归属、连接 / 运行身份、项目规范路径、原生会话匹配和互斥；adapter 才解释具体协议。
- 主进程返回可序列化视图，错误脱敏；用量和工具输出限频 / 限长，避免流式每字都重建全部历史。
- 不写 Tool_box 聊天表，不把编程会话全文复制进数据库；现有加密草稿继续复用。原生回退由原生 API 修改其权威历史。
- 所有新协议必须同步 shared 契约、IPC、validation、preload、调用方，并获得用户对具体范围的同意；本文不是授权。

## 9. 分批实施与交付门槛

每批都先核对已提交 / 未提交的前序成果，按最小文件集合完成，不覆盖现有任务。

| 批次 | 建议内容 | 主要落点 | 结束条件 |
| --- | --- | --- | --- |
| A1 | F01 用户消息复制 / 取回编辑，草稿覆盖和取消 | messages / composer / store | 五入口都能取回原文，不连接、不发送、不改历史 |
| A2 | runtime-capabilities、稳定消息 / 轮次映射、上下文 DTO | shared、codec、adapter、service | 同一条历史 / 增量只有一个身份，旧桥接兼容 |

| B1 | F04 Claude 问答 / 计划确认，随后 Codex / OpenCode | 反向请求 handler、请求视图、答复 IPC | 合法回答只结算原请求，断开和取消不留悬挂 |
| B2 | F05 失败分类、原文恢复、历史核对和耗时 | adapter、store、消息操作 | 结果未知无盲重发，失败不新增幽灵会话 |

| E | 会话整理、分页、待发消息、可选提醒 | 既有历史与草稿架构 | 另评审持久化、通知和执行意图，不自动扩大本计划首批 |

C0 如果涉及创建 / 回退原生会话，即使没有模型消费，也必须只使用明确授权的隔离测试数据；不拿用户现有会话做实验。

### 9.1 不建议为了凑齐功能而做

- 全入口显示相同的撤回按钮，点击后只删本地正文。
- 把旧消息覆盖成新内容，却让原生上下文保持原样。
- 手动篡改 OpenCode DB、Claude transcript 或 DSH JSONL 来实现编辑。
- 用累计 Token、字符长度或静态模型名估算百分比，并不标来源。
- 自动重发超时任务、自动文件回滚、自动执行压缩或追问确认。
- 为基本交互引入内嵌终端、桌面自动点击或私有 WebSocket。
- 新建复杂消息树、独立命令管理后台、全局定价 / 预算管理。
- 承诺 Claude Desktop 无感后台双向同步，或趁本轮恢复手机维护。

## 10. 交互与视觉

- 用户消息右下方紧凑操作条；助手操作沿用复制 / 转用，原文与代码操作按需出现。
- 输入框在取回编辑 / 真编辑 / 分叉草稿时给清楚但不同的状态文案；发送意图不靠用户猜。
- 上下文读数放输入区底部，详情向上展开；没数据用简短占位，不常驻一条大警告。
- 待回答请求靠近输入区，任务仍显示“等待回答”，提交后恢复运行；不得挤掉停止入口。
- 执行详情保留折叠默认，长输出按需展开；本任务原生 Diff 与“当前工作区 Diff”分开命名，后者可能包含用户自己的修改。
- 复用 Dropdown、confirmDialog、status-banner、btn-ghost / btn-gold 和主题变量；Esc 先关闭局部弹层，不误关闭工具箱。
- 支持键盘、输入法、多项目后台任务与历史加载；在 1280×820 和三套主题下验收。
- 所有非必要信息放详情，避免为了展示 Token 把对话区压缩成仪表盘。
