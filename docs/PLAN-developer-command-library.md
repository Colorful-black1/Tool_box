# 开发工作台：命令速查计划

日期：2026-10-29  
状态：方案草案，仅规划，尚未实施；新增 IPC 的范围待实施前确认。

## 1. 目标与默认方案

开发时忘记 Docker、Linux 等命令，可以在工具箱中通过用途或命令片段找到记录，直接复制；遇到值得保留的命令，也能快速新增。

默认在「开发工作台」下新增独立入口 **命令速查**，与编程 Agent、Token 统计、工具并列。以本机、离线、搜索和复制为主，不需要配置模型或连接 Agent。

本轮按以下假设规划，用户可在实施前调整：

- 既有开箱可查的内置命令，也允许用户保存自己的命令。
- 命令按用途记录，不按项目隔离；项目专用说明可以写入备注或标签。
- 首版只记录和复制，不执行命令，不连接 Docker、SSH、WSL 或终端。
- 中文用途说明配合原始命令，界面少放解释，必要边界放进条目详情。

### 方案比较

| 方案 | 优点 | 代价 | 选择 |
| --- | --- | --- | --- |
| 独立「命令速查」 | 入口直接，搜索、收藏与复制针对命令设计 | 增加一个工作台入口 | 推荐 |
| 作为「工具」里的一个面板 | 改动入口较少 | 每次查命令需先进入工具，长列表空间较小 | 备选 |
| 用记事本记录 | 无需开发 | 需自行整理文档，缺少逐条复制、分类与命令检索 | 不作为本需求的实现 |

## 3. 首版范围

### 3.1 查找与复制

- 支持搜索标题、命令原文、用途说明、分类和标签。
- 输入即筛选；不依赖联网、AI、额外搜索库或数据库全文索引。
- 支持中英文混合、大小写不敏感、多关键词同时匹配。
- 搜索规范化只作用于检索副本，绝不改动保存或复制的命令原文。
- 排序以标题／命令命中优先，其次用途／标签，再以收藏和稳定顺序打破并列。
- 分类和视图过滤与搜索共同生效；可一键清空，显示结果数与无结果状态。
- 每条结果直接展示标题、命令和复制按钮，不必先打开详情。
- 复制完整命令原文；多行、引号、反斜杠和缩进保留，不附加说明或 Markdown 围栏。
- 剪贴板成功后才短暂显示「已复制」，失败可重试，绝不显示虚假成功。

示例查询是用户可能输入的用途：`容器日志`、`端口占用`、`磁盘空间`、`compose`。需要命中的中文别名写入条目说明或标签，不承诺语义搜索和自动同义词推断。

### 3.2 分类、收藏与个人记录

- 左侧按分类筛选，顶部有「全部／收藏／我的／归档」视图；归档记录默认不参与其他视图搜索。
- 支持新增、编辑、收藏、取消收藏；个人记录可以归档和恢复，首版不做物理删除。
- 记录字段：标题、命令、分类、用途说明、标签、适用 Shell、注意事项等级。
- 新增时标题、命令必填；默认分类「其他」，默认 Shell「未指定」，其他字段可不填。
- 分类可从已有名称选择或填写新名称，不单独建设分类管理系统；重命名某条记录的分类不批量修改其他条目。
- 编辑使用现有弹层范式；未保存时取消或离开需确认，保存失败保留输入。
- 内置记录只读，提供「另存为我的命令」，另存后独立编辑，升级不覆盖个人内容。
- 收藏持久化；不增加最近使用、自动排序写盘、版本管理等首版非必要能力。

### 3.3 内置内容

首版建议约 50 条常用记录，以高频问题为主，避免堆砌完整手册：

| 分类 | 主要用途 |
| --- | --- |
| Docker／Compose | 容器与镜像列表、日志、进入容器、启动停止、端口映射查看、服务状态与重建 |
| Linux | 文件查找、文本搜索、权限、进程、端口、磁盘／目录占用、日志跟踪、压缩解压 |
| Git | 状态与差异、分支、日志、临时保存、提交定位 |
| Node.js／npm | 依赖与脚本查看、安装、缓存和版本查询 |

实施时逐条核对官方文档和适用环境；不在计划阶段把命令语法视为已验证。每条记录只放一个明确用途的命令或连续步骤，不把多个可替换方案塞进同一个复制块。

- 明确区分 Bash、PowerShell、CMD 或 Shell 无关的写法；Linux 专用命令不能标成 Windows 原生可用。
- 使用命名占位符，例如 `<容器名>`、`<文件路径>`；原样复制，由用户在终端替换。
- 涉及修改或删除数据的内置条目用短标签和注意事项说明影响；复制不额外弹确认。
- 首版不提供占位符填写器、命令拼装器或执行按钮。

## 4. 页面与操作路径

布局草图：

```text
开发工作台 → 命令速查

[搜索标题、命令或用途……                              ] [新增命令]
[全部] [收藏] [我的] [归档]                         [Shell 筛选]

分类                 命令结果
全部分类             查看容器日志                ☆  复制  更多
Docker               命令原文……
Linux                用途摘要 · Bash
Git
Node.js／npm         查看目录占用                ☆  复制  更多
其他                 命令原文……
```

- 命令正文用现有等宽字体；长行在代码区域内横向滚动，多行保持原格式。
- 查看参数说明／注意事项时展开条目，不默认铺满长篇说明；编辑、归档等操作收进更多菜单。
- 新增只需填写标题和命令即可保存；默认值允许后续补充。
- 页面保留本次搜索和分类，切到 Agent 再回来无需重新输入；首版不持久化搜索词。
- Ctrl+F 在该页面聚焦搜索，不占用其他页面快捷键；输入搜索后不抢焦点。
- 列表项聚焦后支持上下移动、Enter 展开详情；复制按钮有明确名称，文本框内快捷键不触发列表动作。
- Esc 先关闭菜单或编辑弹层，再交给既有窗口行为；复用 `use-overlay-dismiss`。
- Dropdown、Popover、`confirmDialog`、`.btn-ghost`、`.btn-gold`、`.status-banner` 与主题变量全部复用。
- 三套主题一致；1280×820 保持对齐，窄窗分类可收起或折叠，不产生页面级横向溢出。

典型路径：

1. 忘记命令：打开命令速查 → 输入用途 → 点击复制 → 粘贴到自己的终端。
2. 保存经验：新增命令 → 填标题和命令 → 保存；需要时再补说明、分类和标签。
3. 调整内置命令：另存为我的命令 → 修改 → 保存，原内置记录仍在。

## 5. 数据与接口方案（待确认）

### 5.1 本地存储

- 复用 `kv` 表，新键 `developer_commands_v1`，由 `ToolboxStore` 提供专用读取／写入方法。
- 文档保存 `version: 1`、递增 `revision`、个人条目和收藏 ID；归档时间保存在个人条目内。
- 内置命令放在纯 TypeScript 目录数据中，以稳定的 `builtin:` ID 引用；个人 ID 由主进程生成并使用独立前缀。内置正文不重复落库。
- 缺少 kv 记录时按空个人库打开；首次写入才创建该键。读取损坏或版本不兼容时提示并禁止覆盖保存，保留原记录。
- 写入在主进程中读取最新文档、核对 revision、应用单项操作，再原子保存。并发编辑冲突返回可读提示，保留当前编辑内容，用户刷新后重新采用；不静默覆盖。
- 页面进入／重新获得焦点时可重新读取；不新增持续轮询或广播事件。编辑中的表单保留其原始 revision，不被刷新覆盖。
- 不存放密码、Token 等凭据；示例使用占位符。此处为普通命令笔记，不提供密码箱的加密承诺，不改变现有加密链路。
- 回退到旧版应用时忽略该 kv 键，不需要数据库降级或清库；不要自动删除该记录。

建议上限：个人命令 500 条、标题 80 字符、分类 32 字符、命令 8000 字符、说明 2000 字符、标签 8 个且各 24 字符，搜索 100 字符，整个保存文档最多 2 MiB（UTF-8）。个别字段与总量限制同时校验，超限明确提示。

### 5.2 专用桥接

建议新增 `window.toolbox.developerCommands`，不复用含糊的 config patch：

| 方法 | 拟定通道 | 行为 |
| --- | --- | --- |
| `read()` | `developer-commands:read` | 读取个人库、收藏与 revision |
| `save(input)` | `developer-commands:save` | 新建或更新一条个人记录，校验预期 revision |
| `setFavorite(input)` | `developer-commands:favorite:set` | 设置内置或个人条目收藏，校验存在性与 revision |
| `setArchived(input)` | `developer-commands:archive:set` | 归档／恢复个人记录，校验归属与 revision |

所有写接口返回最新快照；同页写入串行，避免快速点击造成旧状态覆盖。内置编辑、归档和未知 ID 在主进程拒绝。归档保留收藏状态，但收藏视图排除已归档条目，恢复后重新显示。

入参在 `ipc/validation.ts` 校验类型、枚举、长度、数组、ID 与 revision；不能只做前端校验。命令原文保留空白，只判断是否全空及长度，不执行插值、不拆分运行、不写入日志。错误不回显整段命令。

链路：页面 → 专用 Zustand store → preload → IPC 校验 → 命令库 service → ToolboxStore kv。渲染进程不访问 Node、数据库或 shell。

**影响范围**：新增桥接方法、通道和类型；增加 kv 读写；不升级 schema、不新增依赖、不修改渲染安全配置、不改 Agent 运行、Token 统计、密码加密或手机端。新增 IPC 的实施授权需要按仓库约束确认；当前仅记录拟定范围。

## 8. 首版排除与边界

首版不做终端执行、SSH／WSL 连接、AI 问答或生成、自动读取 shell 历史、云同步、命令市场、批量导入导出、参数表单、项目绑定、逐条命令全局搜索与 Agent 自动调用。后续只有实际使用表明必要时再扩展。

主要边界是命令与环境的差异：内容标注 Shell 和用途，复制仍需用户核对当前终端、目录和占位符。内置目录不可能涵盖所有版本，实施时明确来源和适用范围；不承诺复制后能在任意环境直接运行。

本轮交付只有该方案和任务索引，不改代码、不修改实际数据库／IPC、不运行编译测试、不提交 Git。
