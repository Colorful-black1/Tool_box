## Codex 历史恢复兼容修复（当前轮）

用户反馈：切换项目后点选 Codex 历史，出现“会话或权限策略不受支持”而无法打开。
根因：上一轮把历史内容恢复与执行权限映射合并校验，原生完全访问、联网、额外可写目录或其他不能映射的策略导致整份历史被拒绝，并非缺少目标会话。

修复范围：`codex-adapter.ts`、对应回归用例、`opencode-workbench.tsx` 与使用说明。历史身份、项目归属和运行中会话检查保留；恢复成功后，无法映射的权限使用未选择状态，允许浏览，界面提示选择权限后继续。
主进程发送前也校验是否明确选择权限，未选择时不追加请求消息、不发起原生任务。同步模型不会把未选择状态变成默认只读。新会话仍必须确认只读权限，不能沿用未知策略。

未新增 IPC、数据库、依赖或权限档位，不改原生认证 / 配置，不扩大访问权限，不自动发送、补建或重发。
新增回归用例覆盖完全访问历史正文可读、原生 resume 不带权限覆盖、同步后仍需选择、显式只读后可发送、未知 / 联网 / 外部目录策略以及新会话只读校验。

本轮仅 3 个代码文件调整，不满足“超过 500 有效代码行且超过 10 文件”的同时条件；没有执行类型检查、lint、测试、构建或启动服务，新增用例尚未执行，只完成静态调用链和差异审查。
本次修改影响范围有限，未执行编译验证。以下上轮的 518 项测试与 UI 结果不代表本修复已验证通过，本轮没有重新构建 `out/`。

用户手动验证：手动构建并重启项目构建版本 → 切换项目 → 选择 Codex → 打开历史。原来报错的记录应能显示正文；权限需重新选择时发送保持禁用。选择只读后再发送一个只读任务；新会话和普通支持策略的历史仍应保持原行为。
潜在边界：未确认你这条历史具体采用了哪一种原生策略，修复覆盖截图对应的整个权限拒绝分支；损坏记录、项目不符、仍在执行中的会话仍会明确拒绝。需要真实会话手动确认，不能以静态审查代替实测。

## 用户实机检查

1. 在编程 Agent 顶部选择 Codex，确认检测到程序，选择项目并连接；登录提示异常时先回原生 Codex 登录。
2. 手动新建或读取并选择历史会话，发一个只读短任务，检查流式文本、停止和原生名称。先核对版本与项目。
3. 需要写入时手动选择项目写入，核对单次审批和实际改动；原生组织策略可能额外限制操作。
4. 在 OpenCode 完成任务后打开交接，删去无关内容，选择已准备的 Codex 会话，核对目录 / diff / 权限后填草稿，再手动发送。
5. 自行核对 Codex Desktop 是否显示同一会话；尚未确认前，不以实时互见作为数据恢复方式。
