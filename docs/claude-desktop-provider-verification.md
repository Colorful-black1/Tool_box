# Claude Desktop 独立入口交付记录

日期：2026-10-25。

## 改动及原因

用户已确认 Code 路由可用，但期望像 CC Switch 一样分别支持 Code／Desktop。新增 `claude-desktop` 工作台入口与独立适配器实例：Code 继续读取 `~/.claude/settings.json`，Desktop 只读当前 `Claude-3p` 第三方 profile；不再需要在 Code 页面重复配置 Desktop 所用供应商。

- `shared/coding-agents.ts` 增加标识和名称，通用切换、消息转用、草稿解析自动纳入新入口。
- `claude-desktop-settings.ts` 有界读取当前 profile，校验 ID、地址、Bearer 认证与模型；缺少模型列表时仅 GET 同一网关的 `/v1/models`，5 秒超时、512 KiB 上限、禁止跳转。默认使用列表首项。
- `claude-adapter.ts` 复用官方 SDK 生命周期；分别保存程序／项目偏好，Desktop 清除继承的 Code 供应商、模型、OAuth 和云端模式环境，再应用网关认证。默认计划模式、审批与准备阶段取消保持一致。
- `claudeDesktop.sessionIds` 在既有配置 kv 中记录本入口创建的 SDK 会话 ID；写入失败不启动任务。历史按来源索引及项目过滤，Code 排除 Desktop ID；两入口的本地会话引用、事件、草稿分别隔离。
- UI 保持现有按钮、主题提示和菜单，明示配置来源、Desktop 窗口无需打开、原有 Desktop 聊天不导入。

## 影响范围与授权

用户要求分开支持是本轮新增运行时及其配置读写流程的授权。现有 bridge／preload／IPC 方法和通道不变，仅其共用 `CodingAgentId` 增加合法值；主进程仍统一校验，忽略用户试图注入的任意 profile／Token 参数。既有 `claude` 标识与 Code 配置保持兼容，新版可读取既有加密草稿；旧版不识别新增的 Desktop 草稿标识，降级限制见下文。

没有新增依赖、修改外部配置、数据库 schema、加密算法或主密钥；不恢复手机端维护。只在既有配置 kv 保存非敏感偏好与会话 ID，不写入网关 Key、OAuth 或消息正文。没有提交或推送。

## 手动验收与边界

1. 用户重新打包或运行本次构建版本，保持 CC Switch 网关运行。
2. 在工具箱分别选择 Claude Code 与 Claude Desktop，确认同项目下两份草稿和模型来源各自独立。
3. Desktop 默认采用 profile 首个模型；需要其他模型时直接选择，再发送短消息验证真实供应商协议兼容性。
4. CC Switch 切换 Desktop 供应商后，下次发送读取新配置；手选模型已移除时应明确停止，点击「更多 → 同步模型」后重新选择。
5. 在 Desktop 入口创建的 SDK 会话可在重启后恢复；Code 入口不能恢复同一来源 ID，Desktop 原有聊天不应出现。

Desktop 入口复用供应商配置，执行能力仍来自 SDK，不代表完整桌面客户端接管。不支持 Desktop 官方订阅登录、Cowork、原有桌面聊天同步。profile 字段形状来自当前安装版本与 CC Switch 文档；未来格式变化、非 Bearer 认证或专有云身份需另行适配。标准路径以 Windows 为交付平台，macOS／Linux 未实机验证。

来源索引最多 10,000 项，达到上限或损坏时明确停止，不静默丢弃；应保留工具箱数据库备份，丢失索引后不能可靠重建历史来源。历史从当前项目最近 2000 项原生目录中筛选最多 200 条，不承诺枚举更早记录。既有单个顶层任务限制继续适用于两个入口。

回退可移除新入口注册并保留既有配置与草稿记录；不物理删除用户记录。旧版不识别新草稿运行时，带 Desktop 草稿的文档应保留，升级回支持版本后取回，不能为降级清空密文。
