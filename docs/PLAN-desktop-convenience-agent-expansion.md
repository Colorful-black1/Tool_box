状态：用户已授权实施；A–D 代码及合成验证已完成，已执行无模型连接探针。本轮不发送真实模型任务。

授权记录：用户同意草稿新 IPC 与用途隔离的加密接口；允许固定版本 `@anthropic-ai/claude-agent-sdk@0.3.310` 及必需依赖／Windows 原生组件；接受 DSH“提交后更新、可续接但不回放旧消息”的首版。实际接口、验证结果和待验边界见 [交付记录](desktop-convenience-agent-verification.md)。不改 schema，不恢复手机维护，不提交或推送。

## 1. 目标、范围与默认方案

按上一轮建议的实施顺序，将“第一个和第二个”理解为：

1. 常用工具收藏与最近使用。
2. 编程 Agent 未发送草稿的重启恢复。

随后接入用户常用的 Claude Code、DeepSeek Harness（默认指官方 `deepseek-ai/deepseek-harness`）。只维护 Windows 桌面端；Kimi、手机端、自动团队、多 Agent 并行写入不进入本计划。

默认先完成前两项，再逐个新增运行时。保留现有工具排序、命令面板、OpenCode / Codex 行为；不新增首页、代码编辑器或终端模拟器。各阶段可独立交付，新 Agent 的阻塞不影响前两项。

本文件记录能力划分与已确认的执行决策，不取代已批准的现有规格。授权仅覆盖上述明确事项，不作为其他高风险操作的笼统授权。

## 4. 阶段 A：常用工具收藏与最近使用

### 用户行为

* 工具目录顶部增加“收藏”“最近使用”，原工具分类与组内排序保留。
* 每个工具提供收藏按钮；点击收藏不打开工具、不改变当前输入，支持键盘与中文无障碍标签。
* 最近使用默认显示最近 8 项，仅记录成功打开的不同工具。取消未保存内容确认后，不记录目标；重复渲染和加载恢复不刷新记录。
* Ctrl+K 空输入时优先展示收藏工具和最近工具，去重；输入搜索后继续沿用现有全局搜索。此阶段不增加其他模块的使用历史。
* 从快捷入口进入工具继续经过原有草稿离开确认，不建立绕过确认的导航路径。

### 数据与实现

* 复用 `window.toolbox.config.get/set`，候选新增独立字段 `toolFavorites`、`toolRecent`，不改 `toolOrder` 含义、不新增 IPC 通道。
* 建议上限：收藏 30 项、最近记录 20 项（界面默认展示 8 项）；只保存工具 ID、必要时间元数据，不保存工具输入输出。
* 主进程逐项校验类型、ID 格式、长度、数量和重复；渲染层按注册表过滤已移除 ID。新增工具自然进入原目录。
* 串行保存，避免收藏与最近记录相互覆盖；收藏保存失败回退并提示，最近记录失败不阻止使用工具。
* 1280×820 和窄窗下复用星轨样式与图标系统；收藏／最近区域不提供跨组拖放，原组排序不受重复入口干扰。

### 验收条件

1. 收藏／取消收藏可重启恢复，不影响工具顺序和其他配置。
2. 三种入口（目录、快捷分区、Ctrl+K）成功打开工具后，最近记录一致且无重复。
3. 搜索、中文输入法确认、离开草稿取消、键盘导航、保存失败有明确行为。
4. 全新安装、旧配置、损坏配置、已移除工具均可降级；桥接未就绪仍可使用工具。

## 5. 阶段 B：Agent 草稿恢复

### 保存与恢复边界

* 首版只覆盖编程 Agent 输入框中未发送的文字，含手动输入和消息转用内容。笔记、密码、JWT、日志临时输入不纳入自动保存。
* 按运行时 ID、规范化项目绝对路径、原生会话 ID 隔离；新会话草稿使用独立标识。不得持久化重连后失效的本地 sessionRef / connectionId。
* 重启后恢复所选 Agent、项目和可用草稿；历史会话草稿在用户选择对应历史后绑定。原生会话失效时保留可取回草稿，不偷偷新建替代会话。
* 恢复只准备输入框，不自动连接、发送、执行命令或恢复运行中状态；不持久化审批、执行锁、流式消息和完整聊天正文。
* 界面显示“保存中／已保存／保存失败”。读取失败时不能用空状态覆盖旧数据；读取期间的新输入优先，禁止迟到加载覆盖已输入内容。

### 推荐存储方案与备选

推荐：主进程草稿服务 + 既有 kv 的独立 key + 现有加密服务。普通 `read_config` 不存草稿正文；不新增表、不提升 schema。

现有 `SecretBox` 仅接受密码载荷。实施前需冻结一个向后兼容的通用文本加密封装方案，复用现有 AES-256-GCM 与受系统保护的主密钥，保持旧密码密文的读写完全兼容；不得为了草稿修改算法、密钥位置或替换主密钥文件。此接口及加密链路扩展需用户明确确认后实施。

备选：用户主动“保存为笔记”。无需草稿专用加密接口与新 IPC，但无法提供同等自动恢复体验。此方案仅在推荐方案未获授权时选择，不擅自改成明文 localStorage。

### 一致性与限额

* 输入后约 500ms 防抖；主进程串行写入，使用递增修订号区分已保存版本。保存旧版本完成时不把新输入误标记为已保存。
* 切换项目／Agent、清空、发送成功后的草稿更新都进入同一队列；发送失败保留。发送期间新输入的文字不因旧请求成功被清空。
* 正常退出使用有界刷新并显示失败处理策略；不能只依赖 React 卸载 effect。异常退出仍可能丢失最后一个未保存窗口内的文字，不能承诺零丢失。
* 候选上限：每条 5 万字符、100 条、总明文 UTF-8 体积 2 MiB；主进程再次校验。达到总限额时提示管理草稿，不静默淘汰未发送内容。
* 提供用户主动清除单条／全部草稿的入口及确认。日志不打印正文、密文信封或密钥；解密失败保留原记录并提示，禁止覆盖成空白。
* 系统安全存储不可用时保留内存草稿并说明不能落盘，不降级为明文。此阶段不提供跨机器迁移承诺。

### 验收条件

1. OpenCode / Codex、两个项目、两个历史会话与新会话的草稿互不串写。
2. 重启恢复草稿但不产生原生连接／新会话／模型请求。
3. 读取迟到、连续输入、保存失败重试、发送后继续输入均不覆盖新版本。
4. 丢失原生会话、达到上限、解密失败、正常退出与异常退出边界可解释。
5. 后续新增 Claude / DSH 无需再实现各自的草稿持久化。

## 6. 阶段 C：Claude Code 可行性与执行路线

结论：有官方程序化接口，技术上可接入；完整交互体验优先采用官方 Agent SDK。官方同时提供 CLI 非交互运行和结构化输出。[Agent SDK 概览](https://code.claude.com/docs/en/agent-sdk/overview)、[CLI 程序化运行](https://code.claude.com/docs/en/headless)。

| 路线 | 优点 | 限制与选择 |
| --- | --- | --- |
| 官方 `@anthropic-ai/claude-agent-sdk` | 有类型接口、审批回调、会话读取／恢复，适合统一工作台 | 新增依赖，须确认具体版本和认证路径；推荐完整接入路线 |
| 本机 `claude -p` + 结构化事件 | 可先复用已安装 CLI，避免新运行依赖 | 基础输出不等于 GUI 单次审批；未完成公开审批接口验证前仅提供受限能力，不能默许全部权限 |

官方 SDK 的 `canUseTool` 可承接需要审批的请求与用户问答，但已被原生规则批准的工具不会进入该回调；不能把回调宣称为所有操作必经审批门。[审批与用户输入](https://code.claude.com/docs/en/agent-sdk/user-input)。

官方会话接口提供列举和读取消息的能力，可优先用于历史选择与恢复，避免通过 Token 统计解析器代替完整会话读取。[会话接口](https://code.claude.com/docs/en/agent-sdk/sessions)。

实施步骤：

1. 确认用户实际 CLI 路径、版本、Windows 原生／WSL 使用方式、认证方式；不输出认证值，不自动安装或改系统 PATH。
2. 明确 SDK 或 CLI 路线，锁定可用版本；SDK 方案列出新增依赖、打包影响与实际认证方式，确认后才修改依赖。
3. 新增 `claude-adapter.ts` 与运行时探测，注册到现有 `CodingAgentService`；保留默认权限说明与顶层单任务互斥。
4. 实现真实增量、发送、停止、单次审批；将用户问答与布尔审批区分，不用“允许”冒充用户答案。暂不支持的问答须明确结束／拒绝，不无限等待。
5. 实现原生项目历史列表、消息读取与恢复，明确加载的 settings 来源及其 hooks / MCP 行为；不改写用户原生配置。
6. 接入模型／推理选项、草稿、消息转用；仅显示已核实能力，不承诺与 Desktop 实时双向同步。

认证决策：官方说明未经批准的第三方产品不能提供 claude.ai 登录或额度。本项目应区分个人本地控制已安装 CLI 与对外分发 SDK 集成；SDK 路线采用官方支持的认证方式，不能承诺自动复用订阅额度。本轮不读取凭据，也不实现登录代理。[官方说明](https://code.claude.com/docs/en/agent-sdk/overview)。

验收：切换／连接不发送任务；指定项目真实只读回复、允许一次／拒绝、等待审批时停止、普通生成中停止、历史恢复、断连与迟到事件隔离均有证据。未验证能力不能标记为支持。

## 7. 阶段 D：DeepSeek Harness 可行性与执行路线

结论：官方存在 `dsh --profile acp` 与 SDK 路线，可实现程序化控制；当前 ACP 更适合自动化控制，不能直接等同 OpenCode 的完整交互体验。[官方 CLI](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cli-help.md)。

当前官方 ACP 契约提供创建、列举、resume、模型选项、取消、关闭与单次权限请求；不支持 `session/load` 历史回放，只发送已提交消息，没有原始 provider token 分片。恢复上下文和显示旧历史必须分别验证；不能把收到整段回复后的逐字动画称为真实流式。[ACP 契约](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/acp/acp/README.md)。

官方 TypeScript SDK 文档另有原生问答和客户端审批接口，可作为 ACP 不满足需求时的候选；它也需要独立确认事件时序与版本，不能假设换 SDK 就自动解决实时分片。[SDK 客户端](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/sdk/client/README.md)。

实施步骤：

1. 确认实际产品是官方 DSH、Desktop 或自定义发行版；记录安装路径、profile、数据目录、版本和启动器类型。固定本次支持的版本，不照搬旧教程。
2. 设计最小协议探针：确认会话、模型、审批、停止、输出粒度、历史重放与占用会话行为；遵守仓库验证门槛，不在计划阶段运行。
3. 默认优先复用本机 CLI 的 ACP，无需引入 DSH npm 依赖。只复用确实通用的 codec；现有 `AcpConnection` 的 OpenCode 错误文案与退出语义需隔离，不直接原样套用。
4. 流式决策单独交付：若安装版本有官方实时接口则采用；否则提供明确标注的“提交后更新”受限版本供用户选择。未经用户接受该差异，不标记正式对话接入完成；不改上游代码、不读取私有 WebSocket。
5. 增加 `dsh` 运行时 ID、名称、校验、偏好和适配器注册；不把 DSH 当成 DeepSeek 普通模型供应商或 OpenCode profile。
6. 将单次权限请求接入审批卡，停止与断开只作用于 Tool_box 拥有的任务；不终止用户外部 DSH 会话。
7. 有能力才展示历史正文、工具详情和子任务；否则分别提示“可续接上下文／暂不回放旧消息”等实际边界。不拼装伪造历史。

Windows 特别检查：现有“选择程序”只过滤 `.exe`，DSH 可能经 npm shim 或 Node 入口启动。若需要兼容，采用受控的运行时定位与参数数组，不拼接任意 shell 命令，不为此全局放开其他 Agent 的程序校验。

验收：固定版本的会话创建／续接、一次审批／拒绝、停止、跨项目隔离、断连不重发，以及输出粒度说明。Tool_box 与其他入口是否共用历史取决于实际 profile 和持久化根，不能预先承诺。
